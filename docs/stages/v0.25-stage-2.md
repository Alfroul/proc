## 任务清单

### 1. D1 空会话治理：`src/agent/session_log.rs` 延迟创建（~60 业务行）

**改动点**（ADR-0035 D1 实装规格逐条）：

- `RecorderInner` 结构改造：
  - 加 `path: PathBuf`（延迟创建目标；文件名时间戳 = 构造时刻，ADR Consequences 既定）
  - `writer: BufWriter<File>` → `writer: Option<BufWriter<File>>`（None = 未创建或已降级放弃）
  - 加 `pending_start: Option<LogEvent::SessionStart>`（provider / wall_start 暂存）
- `start_in_dir`：保留 `fs::create_dir_all` 检查（`is_enabled()` 语义不变——构造成功即 enabled，目录可写性验证留在构造时）；**不再立即 `File::create` + 写 SessionStart**——只暂存 pending_start
- `write_entry`（唯一落盘汇聚点，TextDelta 聚合段 / QueryStarted / Error / … 全部经此）：`writer` 为 None 时尝试物化——`File::create(path)` 成功 → 补写 SessionStart（ts_rel_ms = 0，seq 0）+ 写当前事件；失败 → 清 pending_start 静默放弃（后续调用 no-op，写失败静默降级契约不变）
- 移除被孤立的私有 `write()` 方法（原 SessionStart 立即写入口）
- 更新 `start_in_dir` doc 注释（目录创建失败构造时降级 / 文件创建延迟语义）

**验收**：进面板不发问 → sessions 目录 0 新文件；发问 → 文件首两行 `session_start` + `query_started`；Error-only 会话 → 2 行文件（ADR「诊断价值」）；既有 A/C 组测试全绿（它们的断言在「发过事件」语义下不受影响）。

### 2. TD-24 状态机：`src/workers/restart.rs` + `src/workers/manager.rs`（~25 业务行）

**改动点**：

- `restart.rs`：`RestartState` 加 `pub fn on_respawn_failed(&mut self, now: SystemTime)`——`retry_count = saturating_add(1)` + `last_crash = Some(now)`（backoff 从失败尝试点重新起算——`now` 参数的语义落点；`restart_tick` 的 pending 过滤器依赖 `last_crash.is_some()` 维持重试队列成员资格）
- `manager.rs` `try_respawn`（L207-213）：`spawn_one` 返 false 时对 state 调 `on_respawn_failed(now)`（spawn 成功路径 `on_respawned` 不变）
- 更新 `restart.rs` 模块头「状态机调用顺序」注释（补 spawn 失败分支）

**验收**：mock 口径见任务 4——TD 原文「spawn_one 恒 false → MAX_RETRIES 次后 permanent_failure 止损」；既有 `test_worker_restart.rs` 全绿（spawn 成功路径行为不变——`restart()` 同 tick 因 backoff 未到不触发 spawn，`last_crash` 断言不受影响）。

### 3. TD-40 regex hardening：`src/security/trusted_signers.rs`（~5 业务行）

**改动点**：L74 裸 `regex::Regex::new(&raw.vendor_pattern)` → `regex::RegexBuilder::new(&raw.vendor_pattern).size_limit(64 * 1024).build()`（regex crate 自带 API，Cargo deps +0）。

**验收**：极端 regex（嵌套量词展开超 64KB 编译预算）→ rule 被 filter_map 拒绝；普通 regex 不受影响；编译失败 warn 日志路径复用既有分支。

### 4. 测试（~150 测试行）

**4a. 三路径语料回归**（新文件 `tests/test_agent_v0_25_stage_2.rs`，ADR-0035 D1「stage 2 回归测试口径」逐条 + stage-1 Spike「对 stage 2 的启示」）：

- **TUI 路径（AgentPanel 语义）· recorder 层**：`start_in_dir(tmpdir)` → `is_enabled() == true` → 不 log 任何事件 → 断言 tmpdir 0 个 `.jsonl`（治理主断言）
- **TUI 路径 · recorder 层 Error 触发**：只 log 一个 `Error` 事件 → 恰 1 文件且 2 条（`session_start` + `error`）——「Error 也触发落盘」口径
- **TUI 路径 · session 层不发问**：`AgentSession::spawn` + recorder（tmpdir）→ 不 send_query → drop handle → 0 文件（AgentPanel 进出面板语义）
- **TUI 路径 · query 进行中退出边界**（brainstorm 风险 3）：HangingProvider（`stream()` 返 `futures_util::stream::pending()`）→ `send_query` → drain 到 `QueryStarted` → **drop handle（中途退出）** → 文件存在且含 `session_start` + `query_started`（已落盘文件保留口径；detached session 线程阻塞在 block_on 属测试可接受——进程退出收割）
- **发问首两行锚**：既有 `test_session_records_full_log_sequence`（v0_22_stage_3 C 组）已断言 `session_start` → `query_started` 开头序——不重复造，本文件注释指向
- **ask / eval 路径锚（现状显式化，防口径漂移）**：`USERPROFILE` 重定向 tmpdir（`TempEnvGuard` 串行模式，`test_path_rules.rs` 先例）→ `build_runner(Some("mock"), None, 6)`（与 `run_agent_ask` 同一构造链；eval 共享 build_runner，AgentRunner 无 recorder 字段）→ `run_with_progress("当前系统 CPU 和内存使用率是多少", &|_| {})`（fixture 回放 query，`test_agent_v0_20_stage_2.rs` 既有 fixture 命中先例）→ 断言重定向后 `sessions` 目录无 `.jsonl`（不存在或空）

**4b. TD-24 测试**：

- `src/workers/restart.rs` tests mod 单元测试 × 2：`on_respawn_failed` 增计数 + `last_crash` 重定位 + 新 backoff 阶梯生效（backoff(1)=30s 从失败点起算）；连续失败 saturating 至 MAX_RETRIES 不越界 + `is_permanent_failure()`
- `tests/test_worker_restart.rs` 集成测试 × 1（TD 原文验证口径）：**mock spawn_one 恒 false** = 非 canonical thread_name（`"mock-failing-worker"`）直插 `restart_history`（pub 字段，既有测试同款手法）→ `spawn_one` 走 `_ => false` 分支确定性失败，不依赖环境（disk-io-etw 需管理员的不确定性规避）→ `restart_tick` 在 t0+5s / +30s / +300s 三次尝试后 `retry_count == 3` + `is_permanent_failure()` + `RestartStatus::from_state` 显示 `PermanentFailure` + 此后 tick 不再尝试（止损断言）

**4c. TD-40 测试**：`trusted_signers.rs` tests mod——toml 双 rule（极端 regex `(a{300}){300}` 展开超 64KB + 普通 `^Adobe`）→ load 后仅存普通 rule（极端被拒）。
