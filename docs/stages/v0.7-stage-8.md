**目标**：用 `aya-rs` 加载 eBPF 程序，监听 3 类内核事件，把 DNS 查询日志 + per-process 网络流量 + execve + connect + TLS SNI 端到端关联为 `ProcessFlow`，回答"哪个二进制和哪个域名说了多少字节"。命中可疑外联时通过 SecurityRule R15 扣分。

**前置依赖**：阶段 1-7 已完成。

- `cargo test --release -q`（全量基线）
- `cargo build --release --features ebpf`（Linux only，**首次跑确认 feature flag 不破**）

**技术决策（详见 ADR-0016）**：

- **用 aya-rs**（不用 libbpf-rs 或 BCC）：纯 Rust 实现，CO-RE 内嵌，不需要 kernel headers；Helix / bpftrace 都在用
- **feature flag `ebpf`**：默认编译不带 eBPF（包体不膨胀），Linux 用户 `cargo build --release --features ebpf` 显式启用
- **Windows / macOS 不支持**：cfg-gate 让 feature flag 仅在 Linux target 生效；其他平台编译为 stub
- **3 类内核事件**：
  1. `tracepoint sys_enter_connect`：socket connect 调用入口
  2. `kprobe tcp_connect` / `kprobe __tcp_connect`（不同内核版本不同函数名）：完整 TCP 流建立
  3. `tracepoint sched:sched_process_exit`：进程退出（exit-accounting）
- **不监听 TLS SNI**（第一版）：SNI 需要在 SSL_write 函数上挂 uprobe，OpenSSL/BoringSSL 多个版本分支处理复杂。第一版只把 DNS 查询日志（v0.5.0 已有）+ connect 关联，SNI 留 v0.8.0+
- **数据通路**：aya ring_buf → userspace reader 线程 → 聚合到 `HashMap<(pid, saddr, daddr), ProcessFlow>` → 主线程 1s tick drain → App::flows
- **PID 复用防串**：ProcessFlow key 含 `(pid, start_time)`，与 v0.6 ProcessInfo 缓存键一致

详见 `docs/adr/0016-ebpf-flow-graph.md`。
