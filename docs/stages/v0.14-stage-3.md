### 1. `src/filter/mod.rs` 加 FrameField + FrameEvalCtx

新增字段归属枚举（与 `Field` 作用 ProcessInfo、`NetworkField` 作用 ProcessFlow 平级分离）：

```rust
/// v0.14 stage 3：录屏帧字段。作用对象 [`crate::record::UiFrame`]，与 [`Field`]
/// （[`ProcessInfo`]）/ [`NetworkField`]（[`ProcessFlow`]）平级分离。
///
/// UiFrame 含两类数据：(1) 帧级标量（timestamp / cpu_usage / memory_used）；
/// (2) 帧内集合（processes / anomalies）。本枚举对应 5 个搜索维度。
///
/// 设计取舍（与 stage 2 FilterExpr 设计原则一致）：分一套 ctx + 一个 apply 方法
/// 让类型系统保证字段不会跨 ctx 误用——`cpu > 5` 在 Flow 视图（无 frame 上下文
/// 即纯网络）不会拿到 frame 数据。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FrameField {
    /// 帧绝对时间戳（unix epoch 秒）。数值字段。
    Timestamp,
    /// 帧整体 CPU 占用百分比（0-100）。数值字段。
    Cpu,
    /// 帧整体内存（字节）。数值字段。
    Mem,
    /// 帧内任一进程名匹配（`FrameAnomaly.processes[].name`）。文本字段（regex / 子串）。
    Name,
    /// 帧内任一 anomaly 的 severity（典型值 `info / warning / critical`）。文本字段。
    AnomalySeverity,
}

impl FrameField {
    #[must_use]
    pub fn is_text(self) -> bool {
        matches!(self, Self::Name | Self::AnomalySeverity)
    }

    /// 从 UiFrame 取值。`Name` / `AnomalySeverity` 在帧内集合里**任一**匹配即命中
    /// （`FieldValue::Text(s)` 返第一个匹配项，apply 路径 regex/= 会逐项重试）。
    #[must_use]
    pub fn extract_first(self, frame: &crate::record::UiFrame) -> FieldValue {
        match self {
            Self::Timestamp => FieldValue::Num(frame.timestamp as f64),
            Self::Cpu => FieldValue::Num(f64::from(frame.cpu_usage)),
            Self::Mem => FieldValue::Num(frame.memory_used as f64),
            Self::Name => FieldValue::Text(
                frame.processes.first().map(|p| p.name.clone()).unwrap_or_default()
            ),
            Self::AnomalySeverity => FieldValue::Text(
                frame.anomalies.first().map(|a| a.severity.clone()).unwrap_or_default()
            ),
        }
    }

    /// 在帧内集合中**任一**项匹配（文本字段用）。数值字段直接走 single。
    #[must_use]
    pub fn any_match(self, frame: &crate::record::UiFrame, pred: &dyn Fn(&str) -> bool) -> bool {
        match self {
            Self::Name => frame.processes.iter().any(|p| pred(&p.name)),
            Self::AnomalySeverity => frame.anomalies.iter().any(|a| pred(&a.severity)),
            // 数值字段不该走 any_match（apply 路径直接 extract_first）
            _ => false,
        }
    }
}
```

### 2. `src/filter/parser.rs` 加 FrameField dispatch

`parse_field` 扩 5 个新标识符 → `ParsedField::Frame(FrameField)`：

```rust
"timestamp" | "ts" => ParsedField::Frame(FrameField::Timestamp),
"cpu" => ... // 已有 Process(Field::Cpu)；冲突需解决
```

**冲突解决**：`cpu` / `mem` 在 List / Tree 视图是 Process 字段，在 timeline 搜索是 Frame 字段，**同名歧义**。

设计决策：**在 FilterExpr parser 层不区分**（保留 v0.7/v0.11 契约不变），由调用方决定走哪条 apply 路径。具体做法：

- parser 仍把 `cpu` 解析成 `ParsedField::Process(Field::Cpu)`（向后兼容 List/Tree 视图）
- 但**额外暴露** `parse_frame_expr(input)` 入口（专供 timeline 搜索）：
  - 该入口把 `cpu` / `mem` 解析成 `FrameField::Cpu` / `FrameField::Mem`
  - 同一 parser 主体 + 不同字段映射表 → 通过 `parse_frame_expr` 切换语义
- 实现：`parse_field_with(mode: ParseMode)` 接收枚举 `Process`（默认）/ `Frame`，按 mode dispatch；既有 `parse()` 默认走 Process 模式，新增 `parse_frame(input)` 走 Frame 模式

```rust
#[derive(Clone, Copy)]
enum ParseMode {
    Process,  // 默认：cpu/mem → Process 字段
    Frame,    // timeline 搜索：cpu/mem → Frame 字段，额外支持 timestamp / name / anomaly.severity
}

fn parse_field_with(i: &str, mode: ParseMode) -> NomRes<'_, ParsedField> {
    // ... take_while1 ...
    match (ident, mode) {
        // 共有：所有模式都识别 network 字段（保险，不强制）
        ("sni", _) => ParsedField::Network(NetworkField::Sni),
        // ... 其他 network 字段同款 ...
        // process 模式专属
        ("cpu", ParseMode::Process) => ParsedField::Process(Field::Cpu),
        ("mem" | "memory", ParseMode::Process) => ParsedField::Process(Field::Mem),
        // ... 其他 process 字段 ...
        // frame 模式专属
        ("cpu" | "mem" | "memory", ParseMode::Frame) => {
            let f = if ident == "cpu" { FrameField::Cpu } else { FrameField::Mem };
            ParsedField::Frame(f)
        }
        ("timestamp" | "ts", ParseMode::Frame) => ParsedField::Frame(FrameField::Timestamp),
        ("name", ParseMode::Frame) => ParsedField::Frame(FrameField::Name),
        ("anomaly.severity" | "severity", ParseMode::Frame) => ParsedField::Frame(FrameField::AnomalySeverity),
        _ => return Err(...unknown...),
    }
}
```

`leaf` 函数加 `ParsedField::Frame` 分支 → 构造 `FrameFieldCmp` / `FrameRegex` / `FrameIn` / `FrameTextEq`。

`parse_frame(input)` 入口：与 `parse(input)` 同款但传 `ParseMode::Frame`。

### 3. `src/replay/search.rs`（新）：搜索状态机

```rust
//! v0.14 stage 3：录屏时间轴搜索。FilterExpr 扩 FrameField 维度，命中帧在
//! timeline 高亮 + n/N 跳转。

use crate::filter::{FilterExpr, ParseError, parse_frame};
use crate::record::UiFrame;

/// 搜索状态。None=未激活 / Some=激活中。
#[derive(Debug, Clone)]
pub struct ReplaySearch {
    /// 用户输入的原始文本（含 `:` 前缀模式与既有视图 UX 一致）。
    pub input: String,
    /// parse 后的 AST。parse 失败时保留上一次成功 AST（与既有 FilterExpr UX 一致）。
    pub expr: Option<FilterExpr>,
    /// parse 错误（输入中时显示在 timeline 上）。
    pub error: Option<ParseError>,
    /// 上次搜索计算出的命中帧索引列表（按升序）。
    pub matches: Vec<usize>,
    /// 当前 cursor 在 matches 中的索引（n/N 移动）。
    pub cursor: usize,
}

impl ReplaySearch {
    pub fn new() -> Self {
        Self {
            input: String::new(),
            expr: None,
            error: None,
            matches: Vec::new(),
            cursor: 0,
        }
    }

    pub fn is_active(&self) -> bool { !self.input.is_empty() || self.expr.is_some() }

    /// 用户按键 → push 字符到 input；按 `:` 启动表达式模式（与 List/Tree 同款）。
    pub fn push_char(&mut self, c: char) { self.input.push(c); self.reparse(); }

    pub fn pop_char(&mut self) { self.input.pop(); self.reparse(); }

    /// 重新 parse input。失败保留上一次 expr（让 UI 继续过滤），error 显示给用户。
    fn reparse(&mut self) {
        if self.input.is_empty() {
            self.expr = None;
            self.error = None;
            return;
        }
        // FilterExpr 模式必须以 `:` 起头；否则视为 substring（在帧进程名 / anomaly
        // title / status_message 三处子串匹配）。
        match if self.input.starts_with(':') {
            parse_frame(&self.input[1..])
        } else {
            // substring 走特殊 expr，用 marker variant 或包装成一个表达式：
            // 简化：把 substring 转成 `name =~ /<input>/i`，让 apply_frame 跑同一套
            crate::filter::build_frame_substring_expr(&self.input)
        } {
            Ok(expr) => { self.expr = Some(expr); self.error = None; }
            Err(e) => { self.error = Some(e); /* 保留 self.expr */ }
        }
    }

    pub fn reset(&mut self) {
        self.input.clear();
        self.expr = None;
        self.error = None;
        self.matches.clear();
        self.cursor = 0;
    }

    /// 重新计算命中帧列表。调用方传 player（按需 frame_at） + 范围。
    /// 长录屏遍历可能慢，仅在 input 变化时调一次。
    pub fn recompute_matches<F>(&mut self, total: usize, mut frame_at: F)
    where
        F: FnMut(usize) -> Option<UiFrame>,
    {
        self.matches.clear();
        let Some(expr) = self.expr.as_ref() else { return; };
        for idx in 0..total {
            if let Some(frame) = frame_at(idx) {
                let ctx = crate::filter::FrameEvalCtx { frame: &frame };
                if expr.apply_frame(&ctx) {
                    self.matches.push(idx);
                }
            }
        }
        self.cursor = 0;
    }

    /// n 键：跳转到下一命中（cursor + 1）。返回目标帧 idx（None=无下一命中）。
    pub fn next_match(&mut self) -> Option<usize> {
        if self.matches.is_empty() { return None; }
        self.cursor = (self.cursor + 1).min(self.matches.len() - 1);
        Some(self.matches[self.cursor])
    }

    /// N 键：跳转到上一命中。
    pub fn prev_match(&mut self) -> Option<usize> {
        if self.matches.is_empty() { return None; }
        self.cursor = self.cursor.saturating_sub(1);
        Some(self.matches[self.cursor])
    }
}
```

`build_frame_substring_expr(input)` 在 `src/filter/mod.rs` 加一个 pub helper（构造 `FrameRegex { field: Name, re: <input as regex>, case_insensitive: true }`）—— regex 转义由 `regex::escape` 处理。

### 4. `ReplayController` 集成 search

字段新增（与 bookmark_panel 平级）：

```rust
pub search: Option<ReplaySearch>,

```

`handle_key` 加分支（与 stage 2 `bookmark_panel` 同款前置拦截）：
- `search_active == true`：
  - Esc → 关闭搜索（保留 expr + matches，让用户继续 n/N 跳转）
  - Enter → 关闭输入态（同上保留）
  - Backspace → pop input + reparse + recompute
  - 字符 → push + reparse + recompute
- 否则（输入态未激活）：
  - `/` → 进入输入态（input 清空，重新开始）
  - `n` → `search.next_match()` → 设 ts.current_frame + ReplayAction::ApplyFrame
  - `N` (Shift+N) → `search.prev_match()` → 同上
  - 既有键位（q / space / Left / Right / + / - / Home / End / B）保留

**搜索计算 lazy 化**：`recompute_matches` 仅在 input 变化时调；n/N 跳转只读 `matches` 列表。长录屏遍历成本 = N × 165 µs（@ 1000 进程），30 min × 30 FPS = 54000 frames × 165 µs ≈ 9 秒——**用户可感延迟**，需在 status_message 提示。

**优化（必做）**：第一次 recompute 后把 matches 缓存到 `ReplaySearch.matches`，后续 n/N 不再遍历，只移动 cursor。

新增 `ReplayAction::SearchMatchesUpdated(usize)` 让 App 设 status（含命中数）。或简化方案：复用 `BookmarkPanelToggled`，由 App 直接读 `self.replay.search.as_ref().map(|s| s.matches.len())` 设 status。

## 已知风险与回退

**风险 1：`cpu` / `mem` 字段名歧义（Process vs Frame）**
- 缓解：parser 暴露两套入口 `parse()`（Process 模式默认）/ `parse_frame()`（Frame 模式），调用方按场景选；既有 `proc ls --filter` / List 视图走 Process 模式不变；timeline 搜索走 Frame 模式
- 单元测试 `parse_frame_cpu_threshold` + `parse_process_cpu_threshold`（既有）并存验证

**风险 2：长录屏遍历慢（> 1 秒）**
- 缓解：recompute_matches 仅在 input 变化时调一次，n/N 跳转只读缓存列表；status_message 提示「正在搜索 N 帧…」
- 未来优化（v0.15+）：footer 加索引段（max_cpu_frame_idx 等）让阈值搜索 O(1)

**风险 3：substring 模式 regex 元字符注入**
- 缓解：`build_frame_substring_expr` 内部 `regex::escape(input)`，让 `.` `*` `+` 等当字面量

**风险 4：搜索 modal 与书签 modal 冲突**
- 缓解：handle_key 优先级 — bookmark_panel 激活时拦截所有键（包括 `/`）；search 输入态激活时也拦截所有键（包括 `B`）。两者互斥不会同时激活

**回退策略**：stage 3 失败 → `git checkout` 还原 `src/filter/{mod,parser}.rs` / `src/replay/{controller,search}.rs` / `src/tui/replay_panel.rs` → stage 3 重做。stage 3 不依赖 stage 4 任何代码，独立可回退。
