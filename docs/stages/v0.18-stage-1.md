### 决策 2：项 3 rmcp 0.11 调研结论（context7 docs 验证，2026-07-10）

stage 1 Spike 用 context7 查 rmcp 0.11 `ServerHandler::subscribe_resource` / `ResourceSubscriber` API（brainstorm 决策 3 mitigate 调研子任务）：

| 维度 | rmcp 0.11 原生 API | 结论 |
|---|---|---|
| server capability 声明 | `ServerCapabilitiesBuilder::enable_resources_subscribe()` 让 server 声明支持 resources_subscribe | 复用，server 启动时调一次 |
| client 端发起订阅 | `ServerSink::subscribe(SubscribeRequestParams)` — client 角色方法 | 不暴露给 server handler |
| server 端 subscribe hook | **`ServerHandler` trait 不暴露 `subscribe_resource` 方法**——client `resources/subscribe` 请求 SDK 内部自动 ACK，不传到 user handler | 自建 worker lifecycle 必要 |
| server 主动 push | `Peer::notify_resource_updated(ResourceUpdatedNotificationParam)` — server 通过 Peer 句柄给 client 发 notification | 复用，worker 1s tick 调此 API |
| client 接收 push | `ClientHandler::on_resource_updated(ResourceUpdatedNotificationParam, ...)` — client 角色的 handler | 自动接收，server 无需关心 |

**关键结论**：rmcp 0.11 没有「server 持注册表 + 1s tick push」的原生 helper，proc 需自建 worker lifecycle（brainstorm 决策 3 拍板）。stage 2 实装时通过 `RequestContext::extensions` 或类似机制拿到 `Peer` 句柄（具体 API stage 2 调研），持 `Arc<Mutex<HashMap<SubscriberId, Peer<RoleServer)>>>` 注册表，1s tick 遍历调 `peer.notify_resource_updated` push 增量。

### 决策 3：项 3 subscribe_worker.rs 注册表 value 用占位类型（stage 1 Spike stub）

stage 1 Spike 暂用 `Arc<Mutex<HashMap<SubscriberId, ()>>>` 让结构编译过（占位 value 类型）。stage 2 替换为 `Arc<Mutex<HashMap<SubscriberId, Peer<RoleServer)>>>`。

**理由**：
- stage 1 不引入 rmcp 0.11 `Peer` 类型依赖（避免在 stub 阶段就 commit 到具体类型）
- stage 2 调研 rmcp 0.11 Peer 拿取路径（`RequestContext::extensions` / 自定义 hook）后确定具体类型
- 占位 `()` 让 stage 1 测试简单（subscribe / unsubscribe / spawn_push_task 都返 Err，subscriber_count 永远 0）

### 决策 4：项 4 `run_record_headless` 第二参数命名 `_duration`（stage 1 Spike 不实装）

stage 1 Spike `run_record_headless(output, _duration: Option<u64>)` 签名带下划线前缀让 clippy 不报 unused parameter。stage 2 实装时去掉下划线前缀 + 在函数体顶部插入：

```rust
if let Some(secs) = _duration {
    std::thread::spawn(move || {
        std::thread::sleep(std::time::Duration::from_secs(secs));
        crate::shutdown::request();
    });
}
```

与 ADR-0029 §关键设计点 6 + brainstorm 决策 4 拍板对齐（子进程 timer 随 child 退出自动终止，无 zombie timer / MCP handler 不持 timer 状态 / 复用 v0.6 落地的 `shutdown::requested()` 干净退出路径）。

### 决策 5：ADR 扩段不新 ADR（与 brainstorm 决策 5 拍板对齐）

stage 1 Spike 不新 ADR，仅扩段 ADR-0027（项 3）+ ADR-0029（项 4）：
