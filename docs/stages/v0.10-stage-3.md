### 阶段 3：FlowAggregator 关联 + ProcessFlow.source 字段 + UI 集成

> ✅ **已发布**（v0.10.0，2026-06-28）
>
> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.10-stage-3.md，完成所有任务后确认完成`

**目标**：把 Schannel SNI 集成到 FlowAggregator，与 v0.9 eBPF 路径统一在 ProcessFlow 数据结构里。Windows 用户看到与 Linux 用户同款 Flow 子视图体验（SNI / bytes 显示，JA4 仍空，留 TD）。

**前置依赖**：v0.10 阶段 2 已完成（Schannel SNI 已能采集）。

**任务清单**（预测）：

1. **ProcessFlow 加 source 字段**
   ```rust
   // src/ebpf/flow.rs
   #[derive(Debug, Clone, Copy, PartialEq)]
   pub enum FlowSource {
       Ebpf,       // Linux + ebpf feature
       Schannel,   // Windows
   }
   
   pub struct ProcessFlow {
       // ... v0.9 字段
       pub source: FlowSource,
   }
   ```
   - 兼容旧录屏：`#[serde(default = "default_source")]`

2. **FlowAggregator 接受 Schannel 事件**
   - Linux 路径不变
   - Windows 路径：`App::flow_aggregator` 同样接 SniRecord（来自 Schannel worker）
   - FlowAggregator 用 source 字段区分数据来源

3. **UI 统一显示**
   - `src/tui/port_table.rs` Flow 子视图：
     - source = Ebpf → 显示完整字段（SNI / JA4 / bytes）
     - source = Schannel → 显示 SNI（JA4 空 / bytes 用 sysinfo per-process 网络速率）
   - 表格列不变（用户看到的是数据，来源透明）

4. **`proc flows` CLI 跨平台**
   - Linux + ebpf feature：走原 v0.7 路径
   - Windows admin：走 Schannel 路径
   - 输出格式统一（source 字段加在 JSON）

5. **R15 跨平台**
   - 安全评分 R15 在 Windows 也激活（Schannel 提供的 SNI 喂给 dns_name 白名单检查）
   - JA4 黑名单在 Windows 不触发（无 JA4 数据）

6. **测试**（`tests/test_flow_source.rs`）
   - mock 两个 source 的 SniRecord，验证 FlowAggregator 正确聚合
   - Windows 集成测试：curl https://example.com → R15 评分变化（如 example.com 不在白名单）

**验收标准**：
- Windows admin 跑 proc，curl https://example.com 后端口面板 Flow 子视图显示 SNI = "example.com"
- `proc flows` 在 Windows admin 输出活跃 flow（不显示降级提示）
- ProcessFlow.source 字段在录屏序列化中正确 round-trip
- TD-18 标 Fixed

**容量预估**：~500 行（FlowSource enum + aggregator 200 + UI 200 + 测试 100），工具调用 30-50 次。
