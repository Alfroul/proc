## 目的

MockProvider fixture 回放让 CI 跑 agent loop **零 LLM 调用**：录制真实 LLM
（Gemma 4 E2B + Anthropic Sonnet 各一组）的响应到 JSONL 文件，测试时按 query
匹配确定性回放。收益：确定性强（同输入同输出）/ 零 API 成本 / 无需 GPU /
CI 不依赖 llama-server。

## fixture 格式（决策 5 拍板 JSONL）

```jsonl
// tests/fixtures/agent/<scenario>-<level>.jsonl，每行一个 JSON 对象
{"query_hash":"a1b2c3...","request":{"messages":[...],"tools":[...]},"response_deltas":[{"Text":"查看"},{"Text":"系统"},{"ToolCall":{"name":"proc_metrics_system","args":{}}},{"ToolResult":{...}},{"Text":"当前 CPU 23%..."},{"EndTurn":{"stop_reason":"end_turn"}}]}
```

字段：

| 字段 | 含义 |
|---|---|
| `query_hash` | query 文本 + provider 名的 SHA-256 前 16 hex（回放匹配键）|
| `request` | 录制时的完整请求快照（messages + tools），diff / debug 用 |
| `response_deltas` | `Delta` 枚举序列（Text / ToolCall / ToolResult / EndTurn），回放时逐条 yield |

## 录制策略

| Provider | 录制内容 | 单 query 耗时 | 总耗时（70 query）|
|---|---|---|---|
| Gemma 4 E2B（`--no-thinks`）| 全部 70 query | ~10s | ~12 分钟 |
| Anthropic Sonnet 4.6 | 全部 70 query（对照）| ~3s | ~3.5 分钟 |

- **录制时机**：stage 2 末段（MockProvider / record_fixture / ToolRegistry /
  AgentRunner 骨架全部落地后）。LLM 响应依赖 system prompt + tool schema 的
  最终形态，提前录制会作废。
- **失败重试**：单 query 最多重试 2 次；重试后仍失败 → 该 query 标记
  `record_failed`，不阻塞其余 query。
- **L1 验收口径**（brainstorm 风险 1 mitigate 4）：L0 23 query 必须全部有可用
  fixture；L1 27 query ≥ 22 个有可用 fixture（80%）；L2 20 query 录制留档
  不验收（v0.21 启用）。

## 录制工具接口（stage 2 落地实装）

```rust
// src/agent/record_fixture.rs
pub struct FixtureRecorder {
    provider: Box<dyn LlmProvider>,
    output_dir: PathBuf,
}

impl FixtureRecorder {
    /// 批量录制：跑 query 清单，每条结果 append 到对应 <scenario>-<level>.jsonl。
    pub async fn record_all(&mut self, queries: &[FixtureQuery]) -> Result<RecordReport>;
}

pub struct FixtureQuery {
    pub scenario: &'static str,   // "performance-diagnose"
    pub level: u8,                // 0 / 1 / 2
    pub query: String,
}

pub struct RecordReport {
    pub recorded: usize,
    pub failed: Vec<String>,
}
```

## MockProvider 回放路径（stage 2 实装）

1. 构造时读 `fixtures_dir` 下全部 `*.jsonl`，建 `query_hash → response_deltas`
   内存索引。
2. `complete()`：取最后一条 user message 计算 query hash，命中 → 按 deltas
   重放拼 `CompleteResponse`；未命中 → `LlmError::Config` 报「fixture 缺失」。
3. `stream()`：同一索引，deltas 逐条 yield。
4. 回归测试：`test_agent_mock_provider_replay_50_queries`（brainstorm 测试矩阵）
   —— L0 23 + L1 27 共 50 query 全部确定性回放。
