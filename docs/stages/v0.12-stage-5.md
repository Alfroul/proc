**任务清单**：

1. **TD-23：DNS ETW diag JSON 输出加 dns_collector 字段**（`src/cli/diag.rs`）
   - 现状：human-readable 模式有 `dns_collector: <kind>` 行，JSON 模式无
   - 修复：JSON 输出 object 加 `"dns_collector": "etw" | "powershell" | "none"` 字段
   - 同步检查 `src/mcp/handler.rs` 中 proc_diag MCP tool schema 是否需要更新
   - 测试：扩 `tests/test_dns_etw.rs` 或 `tests/test_diag.rs`（如有）验证 JSON 字段存在

2. **TD-29：NetworkIn HashSet 优化**（`src/filter/mod.rs`）
   - 现状：NetworkIn 分支用 `values.iter().any(...)`，O(N) 每 flow
   - 修复：FilterExpr::NetworkIn 构造时把 Vec 转 HashSet（apply 时 O(1) 查找）
   - 但 FilterExpr 是不可变 AST，HashSet 构造需在 parse 阶段做（parser.rs parse_in_list 返回 HashSet-backed NetworkIn）
   - 或：NetworkIn 字段从 Vec 改为 HashSet，apply 直接 contains
   - 测试：扩 test_filter_expr_v2.rs 加 100 values × 1000 flows 性能测试（如能 benchmark）

3. **TD-32：R17 ScriptInterpreter 系统启动白名单**（`src/security/lineage.rs`）
   - 现状：当前进程是 wscript/cscript/mshta 即扣 15 分，不看祖先
   - 修复：detect_suspicious_chain 在判定 ScriptInterpreter 前，检查 chain[0]（直接父）是否为 services.exe / wininit.exe / svchost.exe（系统启动入口）；如是则不扣分（系统登录脚本白名单）
   - 测试：扩 test_lineage.rs 加 case：chain [services.exe → wscript.exe] → 不命中 ScriptInterpreter

4. **TD-33：R18 + path_check Downloads 去重**（`src/security/score.rs`）
   - 现状：Downloads 路径同时命中 path_check.downloads_dir (15) + R18.UserProfileDownloads (15) = 30 分
   - 修复：score 第 18 步前查 path_check risk_factors 是否已含 downloads_dir；含则跳过 R18 UserProfileDownloads 检查（去重）
   - 或：R18 内部 UserProfileDownloads weight 从 15 降到 5（更简单但破坏 stage-6 doc 原方案）
   - 选 surgical：在 score.rs 第 18 步加去重逻辑
   - 测试：扩 test_path_rules.rs 加 case：Downloads 签名进程扣分从 30 降到 15

5. **TD-35：property_at_index lifetime 修正**（`src/dns_log/etw.rs` + `src/schannel_etw/provider.rs`）
   - 现状：返回 `&'static EVENT_PROPERTY_INFO` 但实际生命周期绑到 info_ptr 指向的 buffer
   - 修复：加 lifetime parameter `<'a>`，返回 `Option<&'a EVENT_PROPERTY_INFO>`
   - 与 TD-22（已归档为代码质量候选）同款问题，本阶段一并修
   - 测试：clippy 仍 0 warnings（lifetime 修正后无新增警告）

6. **TD-36：MCP DNS tool state 化**（`src/mcp/handler.rs`）
   - 现状：MCP `proc_dns` 每次调用 spawn 临时 EtwDnsCollector，启动前 DNS 查询抓不到
   - 修复：MCP handler 持久 EtwDnsCollector（与 App::workers.dns_log_worker 同生命周期）
   - 改动：MCP handler 加 state（rmcp SDK state 传递机制），启动时 spawn collector，调用 proc_dns 时 drain
   - 测试：扩 mcp handler 测试（如有）验证多次 proc_dns 调用共享同一 collector
