### 阶段 3：FilterExpr v2 网络字段接入

> ✅ **已完成**（v0.11.0 阶段 3 会话产出，2026-06-29；commit 引用见 CONTEXT.md「术语演进历史」段）

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.11-stage-3.md，完成所有任务后确认完成`

**目标**：把 v0.10 落地的 `ProcessFlow.sni` / `dns_name` / `remote_addr` 字段接入 FilterExpr AST。用户能直接搜「哪些进程连到了 google.com」「谁在跟 1.2.3.4 通信」，**配合 v0.10 Schannel SNI 数据立即出价值**。

**前置依赖**：阶段 1 已完成（ProcessInfo 字段骨架就位，但本阶段不依赖阶段 1 字段——FilterExpr v2 接入的是 ProcessFlow / FlowSource 字段，已在 v0.10 落地）。可与阶段 2 并行执行。

**依赖测试**（开工时跑这些测试的详情）：
- `cargo test --release --test test_filter_expr -- --nocapture`（v0.7/v0.8 落地的 FilterExpr 契约，v2 必须保持兼容）
- `cargo test --release --test test_flow_source -- --nocapture`（ProcessFlow.source 字段契约）

**任务清单**：

1. **FilterExpr AST 扩 NetworkField**（`src/filter/mod.rs`）
   - 现有 `FilterExpr::FieldCmp(field, op, value)` 中 field 是 `ProcessField` enum（Cpu / Mem / Pid / Name / SecurityScore / DiskRead / DiskWrite / NetSent / NetRecv）
   - 加 `NetworkField` enum：`Sni` / `DnsName` / `RemoteAddr` / `RemotePort` / `BytesOut` / `BytesIn` / `Source`
   - FilterExpr 加新变体：`NetworkFieldCmp(NetworkField, Op, Value)` / `NetworkRegex(NetworkField, Pattern)` / `NetworkIn(NetworkField, Vec<Value>)`
   - 设计取舍：为什么不合并到 `FieldCmp`？因为 ProcessField 作用于 `&ProcessInfo`（List view），NetworkField 作用于 `&ProcessFlow`（Flow view + 进程关联 flow）。**作用对象不同**，分两个变体清晰。

2. **Parser 扩网络字段语法**（`src/filter/parser.rs`）
   - 现有字段名 token：`cpu` / `mem` / `pid` / `name` / ... → 加 `sni` / `dns_name` / `remote_addr` / `remote_port` / `bytes_out` / `bytes_in` / `source`
   - 操作符复用现有：`>` / `<` / `=` / `!=` / `>=` / `<=` / `=~`（正则）
   - 加 `in` 操作符：`sni in ("a.com", "b.com", "c.com")`（HashSet 查询）
   - 错误信息中文化：扩 `error_kind_to_chinese` 处理新字段名（如未知字段 `xxx` → 「未知字段名：xxx（支持 cpu/mem/pid/name/sni/dns_name/...）」）

3. **EvalCtx 扩 NetworkEvalCtx**（`src/filter/mod.rs`）
   - 现有 `EvalCtx<'a>` 持 `&ProcessInfo` + `Option<u32> security_score`
   - 加 `NetworkEvalCtx<'a>` 持 `&ProcessFlow`
   - `FilterExpr::apply(&EvalCtx)` 不变；加 `FilterExpr::apply_network(&NetworkEvalCtx)` 方法
   - ProcessPanel 的 List / Tree / AppGroup view 不受影响（继续用 `apply`）；Flow 子视图用 `apply_network`

4. **Flow 子视图接入 FilterExpr**（`src/view_models/process_panel.rs` + `src/tui/port_table.rs`）
   - Flow 子视图加 `/` 搜索 + `:` FilterExpr 模式（与 List view 同款）
   - `flow_filtered_indices(flows: &[ProcessFlow])` 方法：按 mode 分支（Substring / FilterExpr）
   - 标题栏显示当前表达式 + parse 错误（与 List view 同款 UI）

5. **CLI `proc flows --filter '<expr>'`**（`src/cli/flows.rs`）
   - 现有 `proc flows` 不支持过滤；加 `--filter` 参数（与 `proc ls --filter` 同款 parser）
   - 表达式作用于 `ProcessFlow` 字段（sni / dns_name / remote_addr）

6. **测试**（`tests/test_filter_expr_v2.rs` 新）
   - 单元：Parser 解析 `sni =~ /google\.com$/` → NetworkRegex(Sni, "google\\.com$")
   - 单元：Parser 解析 `remote_addr in ("1.2.3.4", "5.6.7.8")` → NetworkIn(RemoteAddr, [...])
   - 单元：Parser 解析 `dns_name == "example.com"` → NetworkFieldCmp(DnsName, Eq, "example.com")
   - 单元：错误中文化 — `unknown_field =~ /x/` → 错误信息含「未知字段名」
   - 单元：旧表达式兼容 — `cpu > 5 AND name =~ /chrome/` 仍能正确解析（不破坏 v0.7/v0.8 契约）
   - 集成：mock flows → `sni =~ /evil\.com/` 过滤返回命中的 flow
   - 集成：Flow 子视图按 `:` 进 FilterExpr 模式 + 表达式正确过滤

7. **ADR-0011 增量段**（`docs/adr/0011-filter-expression.md`）
   - 加「v0.11.0 阶段 3 增量：FilterExpr v2 网络字段」段
   - 说明 NetworkField 与 ProcessField 分两个 AST 变体的设计取舍（作用对象不同）

8. **CONTEXT.md 更新**
