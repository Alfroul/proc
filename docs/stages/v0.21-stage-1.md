### 2. `src/agent/session.rs` 骨架（~130 行，声明式）

```rust
//! v0.21 TUI AgentPanel 会话层（ADR-0031 D1）
//!
//! 专用线程 + 自有 tokio Runtime + std mpsc 事件通道桥接同步 TUI 主循环
//! （WorkerManager 同款模式）。实装在 stage 2。

use serde_json::Value;
use tokio::sync::oneshot;

use super::runner::{RunnerOutcome, StopCause};

/// history 滑动窗口：system prompt + 最近 N 轮（决策 D4，常量不预加配置）
pub const MAX_HISTORY_TURNS: usize = 12;

/// 写操作确认决策（面板 y → Approved / n → Denied）
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ConfirmDecision {
    /// 用户确认执行——dispatch 以 confirm: true 真执行（ADR-0008/0029 契约）
    Approved,
    /// 用户拒绝——返 blocked JSON，模型转向解释 + 等价命令行
    Denied,
}

/// 写操作确认请求（dispatch 遇 WRITE_TOOL_NAMES tool 时经 SessionEvent 发出）
pub struct ConfirmRequest {
    pub tool_name: String,
    pub arguments: Value,
    /// 影响摘要（kill → 目标进程列表 / docker_rm → 容器名 / usb_release → 盘符）
    pub summary: String,
    /// 一次性回复通道（TUI y/n 后 send）
    pub reply: oneshot::Sender<ConfirmDecision>,
}

/// TUI 渲染的唯一数据源（tick 内 try_recv drain）
#[derive(Debug)]
pub enum SessionEvent {
    /// 用户 query 开始处理
    QueryStarted(String),
    /// assistant 流式文本增量（D6：TUI 按 tick 批量 append）
    TextDelta(String),
    /// 开始执行一个 tool call
    ToolStart { name: String, arguments: Value },
    /// 一个 tool call 执行完成
    ToolFinished { name: String, is_error: bool, result_chars: usize },
    /// 写操作请求确认（面板进入 AwaitingConfirm 态）
    ConfirmRequested(ConfirmRequest),
    /// 一轮 LLM 调用结束（多轮 ReAct 的轮边界）
    TurnFinished,
    /// 整个 query 处理完成
    SessionFinished { final_text: String, stop: StopCause },
    /// 会话错误（网络 / ctx 溢出 / provider 错误）
    Error(String),
}

/// AgentSession：跨 query 的会话容器（多轮 history + provider + 事件通道）
///
/// stage 2 实装：专用 std::thread + 自有 tokio Runtime + spawn/send_query/interrupt。
pub struct AgentSession {
    // 字段 stage 2 实装时补全（provider / registry / history / events_tx / cancel）
    _private: (),
}

/// TUI 侧持有的会话句柄（drain 事件 + 中断 + Drop 收尾）
///
/// stage 2 实装：interrupt()（cancel flag）+ drain_event()（try_recv）。
pub struct SessionHandle {
    // 字段 stage 2 实装时补全（events_rx / cancel flag / join handle）
    _private: (),
}
```

**注意**：
- `SessionEvent` 不 derive Clone（`ConfirmRequested` 含 oneshot::Sender 不可 Clone）——`#[derive(Debug)]` 可（oneshot::Sender 实现 Debug）
- `AgentSession` / `SessionHandle` 的方法签名（`spawn` / `send_query` / `interrupt` / `drain_event`）本 stage 只写 doc comment 说明，**不写方法**（空 struct 无字段，写方法无意义；stage 2 实装时一并落）——与 v0.20 stage 1「trivial 纯函数直接实装、复杂路径 todo!()」原则一致：本 stage 无 trivial 方法

## 已知风险（stage 1 实施时关注）

### 风险 1：AppMode 加变体的 match 穷尽连锁

加 `Agent` 变体后所有 match AppMode 处编译报错——这是编译器引导的预期行为，逐处补分支即可。**注意别用 `_ =>` 通配符兜底**（会让未来第 12 个变体静默漏分支）；如既有代码已用通配符则保持既有风格（surgical 原则）。

### 风险 2：`A` 键与既有大小写分层冲突

小写 `a` 已被占用（process list select_all / docker watch / monitor add / port_panel）；大写 `A` 需 stage 1 落地时全仓 grep `KeyCode::Char('A')` 确认无冲突。如冲突，fallback = palette 唯一入口 + brainstorm 决策 8 注记更新（小修范畴）。

### 风险 3：`todo!()` 被测试路径意外触达

`AgentPanelController::handle_key` 若 todo!()，App 集成层 stage 1 **不能调它**（退出键内联在 App 层处理），stage 3 再接线。测试只打非 todo 路径。

### 风险 4：SessionEvent 的 Debug derive（oneshot::Sender）

`ConfirmRequested(ConfirmRequest)` 含 `oneshot::Sender`——它实现 Debug 可 derive；但如编译报错则手写 Debug 或去掉该变体的 derive（小修范畴，stage 2 实装时最终定）。
