## Spike 调查发现（本会话产出记录）

### A. 空会话机制归因（含 brainstorm 修正）

**产生链**（源码级）：TUI 进 Agent 面板 → `App::enter_agent_session`（`src/app.rs:1077`）→ `build_session`（`src/agent/builder.rs:66`）→ `SessionRecorder::start`（`src/agent/session_log.rs:96`）**构造即落盘**——`start_in_dir` 立即 `File::create` + 写 `SessionStart` 单行（L109-125）。`QueryStarted` 只在 session_loop 真正收到 query 时记录（`session.rs:271`）。**用户进面板不发问退出 → 永久留下单行空文件**。

**关键修正**：ask / eval 路径走 `build_runner`（`agent_cmd.rs:137/250`）——**不建 recorder，不产生任何 session 文件**。brainstorm 环境事实表「新增 39 文件与 v0.24 stage 3 eval run 时间吻合」是**相关非因果**：eval 不建 recorder；真相是用户在跑 eval 的同一开发时段反复开 TUI 进/出 Agent 面板（v0.22 引入 session log 默认 true 后每次进入都落盘）。

**实测盘点**（2026-08-27）：**102 文件 / 100 空**（98%，比拍板会话 96/94 又增 6——本机持续使用中）；全部 `-llama-cpp` 后缀；文件**成对出现、间隔 15-30s**（如 `125642/125735`、`014307/014321`）——「进面板→退出→再进」节奏；按日分布 08-21（4）→ 08-22（12）→ 08-23（18）→ 08-24（26）→ 08-25（18）→ 08-26（10）→ 08-27（10+），与 v0.22+ 各 cycle 开发强度吻合。非空 2 文件（08-21 的两个，多行含 query/tool 活动）不在治理范围。

**对 stage 2 的启示**：治理点只在 TUI 路径的 SessionRecorder；ask/eval 天然不产生空文件，stage 2 的「三路径回归测试」重点验证 ask/eval 语义不回归（它们不落盘是现状，不是治理引入）。

### B. 治理方案终判：延迟创建（详见 ADR-0035 D1）

首个**非 session_start** 事件到达才 `File::create`（SessionStart 暂存内存，届时补写首行）。弃退出清理的理由：Drop 语义不可靠（Arc\<Mutex\> poison / 构造方 drop 顺序）+ 延迟创建天然覆盖 TUI 中途退出。口径核对：无 `QueryStarted` 的文件在 corpus.rs 成功段状态机（`QueryStarted` 开段，corpus.rs:61）下永远不产出语料 → 治理不影响 `RagIndex` 正确性；Error 事件也触发落盘（诊断价值 + 无成功段不入语料）。

### C. MCP 持久化现状（重大范围修正）

- **TD-54 已落地**（v0.17 stage 3，feature `mcp-persistent-state` **默认启用**）：`ProcMcpHandler.snapshot: Arc<Mutex<Option<SystemSnapshot>>>` + `run_snapshot_worker` 1s tick（refresh + refresh_heavy_incremental，`mod.rs:293`）
- **TD-52 已落地**（v0.17 stage 4）：`system_history: VecDeque<MetricsSample>` 30s cap + `proc_metrics_history` tool（single worker 兼任 push）
- `record_handle`（v0.17 stage 6）+ `subscribe_push_worker`（v0.18 stage 2）同 feature gate 后已落地
- **tech-debt.md 状态回填滞后**——stage 3 做回填（非实装）。stage 3 MCP 组实装余量：TD-50（~30 行）+ TD-53（改道方案，见下）
- **TD-53 终判：做，但改道 sysinfo delta**（详见 ADR-0035 D2）：原方案（handler 持久 disk_io_etw worker）否决——NT Kernel Logger 全局单实例（与 TUI proc 同机互斥）+ 非管理员恒失败（MCP server 常态非提权运行）+ dns_collector 先例不可复制（DNS 用非独占 provider）。新方案：`run_snapshot_worker` 内加 delta 计算（TUI `update_disk_speeds`（`app.rs:1781`）同款：`disk_usage` 差分 / elapsed 填 `ProcessInfo.disk_read_speed/write_speed`）→ `metrics_disk_io` 从 `process_cache()` 读 top-N per-process 段。规模 ~200-300 → **~60-100 行**；数据源精度与 TUI 非管理员档一致（process IO counters，含非磁盘 IO 口径差，响应段内声明）。
