### 阶段 2：DNS ETW 替代 PowerShell probe

> ✅ **已完成**（v0.11.0 阶段 2 会话产出，2026-06-29；commit 引用见 CONTEXT.md「术语演进历史」段）

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.11-stage-2.md，完成所有任务后确认完成`

**目标**：用 `Microsoft-Windows-DNS-Client` ETW provider（event 3008/3010，含查询名 + 结果 IP 列表）替代当前 `src/dns_log/windows_dns.rs` 的 PowerShell `Get-WinEvent` 轮询。性能 + 完整性双提升（PowerShell 500ms-1s 延迟 → ETW < 50ms；PowerShell 漏抓高频查询 → ETW 抓 100%）。PowerShell 路径保留作 fallback。

**前置依赖**：阶段 1 已完成（WorkerManager::restart 可用——本阶段 ETW worker 也可享受 restart 能力）。

**依赖测试**（开工时跑这些测试的详情）：
- `cargo test --release --test test_dns_log -- --nocapture`（PowerShell 路径契约，fallback 必须保持兼容）
- `cargo test --release --test test_schannel_etw -- --nocapture`（ETW 模式参考，复用同款 StartTraceW + EnableTraceEx2 + OpenTraceW + ProcessTrace 骨架）

**任务清单**：

1. **写 ADR-0020**（`docs/adr/0020-dns-etw-provider.md`）
   - Status: Accepted
   - Context: PowerShell probe CPU 持续占 3-5% + 漏抓高频查询；用户报 bug 时附 DNS 日志缺数据
   - Decision: 手写 windows-rs ETW（`Win32::System::Diagnostics::Etw` + `Win32::System::Diagnostics::Tdh`），开 `Microsoft-Windows-DNS-Client` session（provider GUID `{1C95126E-7EEA-49A9-A3FE-A9FB58F46014}`），event 3008（QueryResponse）/ 3010（QueryCompleted）含查询名 + 结果 IP 列表
   - Alternatives: (a) ferrisetw（自动 TDH，但与项目偏好「手写更可控」冲突，同 ADR-0015/0018）；(b) PowerShell + WMI CIM 模式（仍 spawn 子进程，性能没本质改善）；(c) 直接读 `%SystemRoot%\System32\dnsrslvr.log`（仅缓存解析器日志，不含应用层查询）
   - Consequences: 仅 Windows + 管理员权限；非 admin / Win10 早期版本降级到 PowerShell fallback；ETW schema 用 TDH 动态解析（与 ADR-0018 schannel_etw 同款）

2. **event 3008/3010 schema 调研**（先于实装）
   - 管理员 PowerShell：`logman create trace proc-dns-probe -p {1C95126E-7EEA-49A9-A3FE-A9FB58F46014} 0xFFFFFFFFFFFFFFFF 255 -ets`
   - 触发：`Resolve-DnsName example.com` + `curl https://example.com`
   - 停止 + 解析：`logman stop proc-dns-probe -ets && tracerpt -y proc-dns-probe.etl -of XML -o dns.xml`
   - 字段（社区文档 + 实测）：QueryName（UTF-16 LE）/ QueryType（A/AAAA/CNAME...）/ QueryStatus（0 = SUCCESS）/ QueryResults（分号分隔的 IP 列表）
   - 跨 Win 版本兼容：用 TDH 按 property name 找，不硬编码偏移（同 ADR-0018 路线）

3. **DNS ETW provider 实装**（`src/dns_log/etw.rs` 新）
   - 复用 schannel_etw / disk_io_etw 模式：StartTraceW + EnableTraceEx2 + OpenTraceW + ProcessTrace + EventRecordCallback
   - callback fast-filter `event_id == 3008 || event_id == 3010` → TDH 解析 → 构造 `DnsQuery` 结构（与 `dns_log/mod.rs::DnsQuery` 同款）
   - worker 复用 `SnapshotWorker<Vec<DnsQuery>>`，500ms tick → 主线程 drain（与原 PowerShell probe 节奏一致）
   - PID 来源：`EVENT_HEADER.ProcessId`（用户态 provider，不需 thread_map）
   - 降级路径：StartTraceW 失败（非 admin / session 占用）/ EnableTraceEx2 失败（provider GUID 错）/ x86 进程 → 返回 None

4. **collector 切换逻辑**（`src/dns_log/mod.rs`）
   - `detect_collector()` 改为：先尝试 ETW → 失败则 fallback PowerShell probe
   - 保持 `DnsQuery` / `DnsResult` 数据结构不变（collector 透明）
   - `DnsLogWorker` 类型不变（仍是 `SnapshotWorker<Vec<DnsQuery>>`）

5. **PowerShell probe 保留作 fallback**（`src/dns_log/windows_dns.rs`）
   - 不删代码，加注释「v0.11 阶段 2 后退为 fallback；ETW 路径在 src/dns_log/etw.rs」
   - 仅在 ETW 启动失败时启用

6. **proc diag 集成**
   - `DnsLogWorker::metrics_snapshot` 加 `collector: "etw" | "powershell" | "none"` 字段，让用户报 bug 时附上 collector 类型
   - 或在 `proc diag` 输出加单独一行 `dns_collector: etw`

7. **测试**（`tests/test_dns_etw.rs` 新）
   - 单元：mock event 3008 bytes → parser 返回正确 DnsQuery（query_name + result IPs）
   - 跨平台 stub：非 Windows 上 `try_spawn_etw` 返 None
   - 集成（admin only）：spawn worker → `Resolve-DnsName example.com` → 1s 内 SniRecord 出现 + query_name = "example.com"
   - 集成（非 admin）：try_spawn_etw 返 None → detect_collector fallback 到 PowerShell 路径

8. **CONTEXT.md 更新**
   - 加术语：DnsEtwWorker / DNS_ETW_PROVIDER_GUID / event 3008/3010 schema
   - 术语演进历史加 v0.11.0 阶段 2 行

9. **README FAQ 加一条**
   - 「Windows DNS 日志怎么工作？」答：默认走 ETW（< 50ms 延迟），失败降级到 PowerShell probe；用 `proc diag` 看 `dns_collector` 字段确认当前 collector
