## 目标

落地 ADR-0033 D5 的 record agent 侧语义：**TUI AgentPanel 会话中** `proc_record_start` / `proc_record_stop` 经 confirm（y）后**真实执行**（spawn headless 录屏子进程跨 tool 调用保活 / kill + flush 落盘），会话 teardown 自动 stop 防孤儿录制进程，CLI ask / eval 路径继续拦截但文案改「仅 TUI AgentPanel 会话支持」——**47 tool 全部真实可用，仅剩的两个「不支持」清零**（brainstorm 决策 6）。

**核心设计**（D5「句柄持有」行：复用 ADR-0029 record_handle pattern，不重写）：

- 新类型 `RecordState`（session.rs）：`child: Arc<Mutex<Option<Child>>>`（MCP 同款槽）+ `file_path: Arc<Mutex<Option<String>>>`（start 时记忆落盘路径——agent catalog 的 `proc_record_stop` 是 no_params，stop/teardown 靠记忆值定位文件）；三方法 `start` / `stop` / `teardown_stop` 全部薄包 MCP 既有 `make_record_start_json` / `make_record_stop_json`
- 持有层：`AgentSession::spawn` 内部创建（**签名不变，builder.rs 零改动**）——session 线程持 clone（喂 runner + 循环退出兜底 teardown），`SessionHandle` 持 clone（App teardown 用）
- 执行链：`AgentPanel y → Approved → runner 注入 confirm:true → execute_confirmed_tool(call, &record) → RecordState::start/stop`
- 防孤儿双保险：App `teardown_agent_session` 在 interrupt/shutdown 前调 `SessionHandle::stop_orphan_recording()`（Notice 双落点：面板 ChatEntry + App status_message——App::shutdown 也走此函数，Ctrl+C 路径自动覆盖）；session_loop 退出后兜底 `record.teardown_stop()`（Handle 被直接 drop 未走 App teardown 的场景，静默落盘——幂等）

**⚠ D5「录制范围」措辞与实装的差异（stage 1 风险 4 兑现点，实装前知会）**：D5 原文「录制**整个终端屏幕**（与手动 R 键同款）……用户可见后续对话被录进回放」与复用路径的实际语义不符——`proc record --no-tui` 子进程用 ratatui **TestBackend 合成渲染 120x40 系统仪表盘**（`src/cli/record.rs:89` `run_record_headless`，不 attach 真实终端），录的是**后台系统监控画面（进程列表 / DNS / 指标面板），不含 AgentPanel 对话、不含真实终端内容**。MCP `proc mcp` 路径（ADR-0029）即此语义。按 stage 1 风险 4 预授权协议（「不一致以 stage 2 实装为准更新附录」），本阶段任务 6 修订 D5 措辞；若用户期望「录真实终端含对话」需走 App 侧录屏状态联动（跨线程协议改造 ~200+ 行，违背「复用不重写」拍板），**本阶段不做**。

### 1. RecordState 类型 + AgentSession 接线（`src/agent/session.rs`，~80 行）

新增（session.rs，置于 `ConfirmRequest` 定义附近）：

```rust
/// v0.23 stage 2（ADR-0033 D5）：agent 侧录制状态——ADR-0029 record_handle
/// pattern 的 AgentSession 层实例。child 跨 tool 调用保活（session 线程与
/// SessionHandle 共享 clone）；file_path 记 start 时的落盘路径（agent catalog
/// 的 proc_record_stop 是 no_params，stop / teardown 靠记忆值定位文件）。
#[derive(Clone, Default)]
pub struct RecordState {
    child: Arc<std::sync::Mutex<Option<std::process::Child>>>,
    file_path: Arc<std::sync::Mutex<Option<String>>>,
}
```

三方法（全部薄包 MCP helper，不重写子进程管理）：

- `pub fn start(&self, confirm: bool, output: &str, duration_secs: Option<u64>) -> Value`——调 `crate::mcp::handler::record::make_record_start_json(confirm, output, duration_secs, &self.child)`；返回值 `ok == true` 时把 `file_path` 槽置 `Some(output.to_string())`
- `pub fn stop(&self) -> Value`——`file_path` 槽空 → 返 `{"ok": false, "error": "无录屏进行中；先调 proc_record_start"}`；非空 → 调 `make_record_stop_json(&path, &self.child)`，`ok == true` 时清 `file_path` 槽
- `pub fn teardown_stop(&self) -> Option<String>`——child 槽空返 `None`（无录制）；非空调 `self.stop()`，返回 Notice 文案 `录屏已自动保存至 <path>`（path 取结果 JSON 的 `file_path` 字段，缺失容错「未知路径」）；幂等（二次调用 child 已空 → None）

接线（`AgentSession::spawn` / `session_loop` / `SessionHandle`）：

- `spawn` 内 `let record = RecordState::default();`——一个 clone 随 provider/registry 进线程闭包，一个存进 `SessionHandle` 新字段 `record`。**spawn 签名不变**（状态内建，`builder.rs::build_session` 零改动）

## 已知风险（stage 2 实施时关注）

### 风险 1：测试内 spawn 的 child 是 test binary 自身

**问题**：`make_record_start_json` 走 `std::env::current_exe()`——测试进程下 spawn 的「录屏子进程」是 test binary 带 `record --no-tui` 参数（libtest 当作未知 filter 快速退出），非真实 proc.exe 录屏。
**mitigate**：A 组断言只锚 `ok:true` / `pid` / `file_path` / stop 的 `action:"stop"`，不锚 child 存活时长或真实 `.prec` 帧；真实链路由用户手动验证（验收标准 12 下方可选项）。

### 风险 2：teardown_stop 阻塞窗口与 App 3s 等待的交互

**问题**：`make_record_stop_json` kill 后 wait 上限 10s；App `teardown_agent_session` 的线程退出等待上限 3s。
**mitigate**：App 侧 `stop_orphan_recording()` 置于 `interrupt()/shutdown()` **之前**（kill + flush 完成后才发提示与收尾）；正常路径 kill 触发子进程 shutdown handler 干净退出通常 <1s；10s 上限仅子进程卡死时触达，与 App::shutdown 手动录屏同款上限（D5「复用防孤儿模式」同源语义），可接受。

### 风险 3：record_stop 参数语义与 MCP 版差异

**问题**：MCP 版 `proc_record_stop` 要求 `file_path` 与 start 匹配；agent catalog 是 no_params——记忆值与模型传参可能不一致。
**mitigate**：agent 分支统一忽略 stop 参数、以记忆值为准（catalog schema 已声明无参）；无录制时返「无录屏进行中」业务错误；此差异随任务 6 写进 D5 落地注记。

### 风险 4：录制范围语义与 D5 原文差异（已在目标段显式知会）

**问题**：D5 原文「录整个终端屏幕 / 对话被录进回放」与 headless 合成仪表盘实装不符。
**mitigate**：任务 6 以实装为准修订 D5（stage 1 风险 4 预授权协议）；「录真实终端含对话」为协议层改造（~200+ 行），超出「复用不重写」拍板——若用户在 doc 确认时提出异议，按规则 15 停下重新拍板。
