**目标**：把 v0.6 App 中直接持有的 5 个 panel 字段（`process_panel` / `port_panel` / `usb_panel` / `monitor_panel` / `docker_panel`）拆出对应 controller（`ProcessPanelController` / `PortPanelController` / `UsbPanelController` / `MonitorPanelController` / `DockerPanelController`），App 只持 controller 引用 + 全局状态。**对应 TD-6**。

**前置依赖**：阶段 1-4 已完成。**特别注意**：本阶段是**纯重构**，**不引入任何新功能**，所有 v0.6 + v0.7 阶段 1-4 行为必须 100% 保留。

**技术决策（详见 ADR-0012）**：

- **复用 v0.6 阶段 5 的 InspectorController / ReplayController / WorkerManager 拆分模式**（已成功验证）：
  - 每个 controller 持自己的状态
  - `handle_key` 返回 `PanelAction` 枚举让 App 派发副作用（不直接 mutate App）
  - `PanelAction` 包含 `StatusMessage(String)` / `Kill(KillRequest)` / `RecordOp(...)` / `Clipboard(String)` / `Monitor(...)` 等已有副作用类型
- **不引入 trait object**：5 个 controller 都是具体类型（App 持 `process: ProcessPanelController` 等），不用 `Box<dyn PanelController>`。理由：性能 + 编译期类型安全；trait object 的运行时 dispatch 在 ratatui 50ms tick 下不必要
- **不并行做**：5 个 controller 一个一个拆（ProcessPanel 最复杂先做，作为模板；后 4 个照葫芦画瓢），每个 controller 拆完跑全量回归
- **保留 v0.6 公开 API**：`App::process_panel` / `App::port_panel` 等 public 字段不能直接删，会破坏 tests/test_inspector.rs。改成 `App::process_panel()` 方法返回 `&ProcessPanelController`，编译失败处补 `.panel()` 调用

   - 新建 `src/view_models/process_panel/controller.rs`（或在现有 `process_panel.rs` 内追加 module）：
     ```rust
     pub struct ProcessPanelController {
         pub panel: ProcessPanel,  // 原 struct 重命名后塞进来
     }

     impl ProcessPanelController {
         pub fn new(...) -> Self { ... }
         pub fn handle_key(&mut self, key: KeyEvent, ctx: &PanelContext) -> PanelAction { ... }
         pub fn tick(&mut self, snapshot: &SystemSnapshot) { ... }
         pub fn panel(&self) -> &ProcessPanel { &self.panel }
         pub fn panel_mut(&mut self) -> &mut ProcessPanel { &mut self.panel }
     }
     ```
   - **关键**：`ProcessPanel` 本身保留，只是从「App 直接持有」改为「Controller 持有」
