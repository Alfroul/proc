**任务清单**：

1. **TD-26：HRESULT 映射扩 + SignatureStatus 加变体**（`src/security/signature.rs`）
   - 加 SignatureStatus 新变体：`Expired`（CERT_E_EXPIRED）/ `UntrustedRoot`（CERT_E_UNTRUSTEDROOT）/ `ChainError`（CERT_E_CHAINING）
   - Display 实现：Expired → 「证书过期」/ UntrustedRoot → 「不受信根」/ ChainError → 「证书链断裂」
   - badge：Expired / UntrustedRoot → ⚠️（与 Unsigned/Revoked 同档，表示有签名但有问题）；ChainError → ❓（验证失败）
   - `from_wintrust_result` 扩映射：
     - `CERT_E_EXPIRED` (0x800B0101) → Expired
     - `CERT_E_UNTRUSTEDROOT` (0x800B0109) → UntrustedRoot
     - `CERT_E_CHAINING` (0x800B010A) → ChainError
     - `CERT_E_WRONG_NAME` (0x800B0113) → ChainError（名称不匹配归类为链问题）
     - `TRUST_E_CERT_SIGNATURE` (0x80096010) → ChainError（签名无效）
   - `signature_risk_factor` 扩权重：
     - Expired: weight 15（证书过期比 Unsigned 轻微，曾经受信）
     - UntrustedRoot: weight 15（不受信根，可能是自签名或缺失中间证书）
     - ChainError: weight 10（链断裂，验证不完整）
   - 修复 `_ => None` 为显式 Trusted => None（如 stage 8 v0.11 已修则跳过）

2. **TD-27：TRUSTED_SIGNERS 扩 + trusted_signers.toml 用户配置**
   - 扩 `TRUSTED_SIGNERS` 内置列表（src/security/signature.rs）：
     - 加 Adobe / Cisco / Oracle / VMWare / Docker / Red Hat / Apache Software Foundation / Python Software Foundation / GitHub / Electron.js 等
   - 新建 `src/security/trusted_signers.rs`：
     - ` TrustedSignersRule` struct: `{ name: String, vendor_pattern: String, reason: Option<String> }`
     - `load_trusted_signers()` 函数：读 `~/.config/proc/trusted_signers.toml`，TOML 格式 `[[signer]] name / vendor_pattern / reason`，默认不存在 → 空 Vec
     - 解析失败 / regex 编译失败 → 静默降级为空（tracing::warn）
     - 与内置 TRUSTED_SIGNERS 列表合并（用户配置追加，不替换）
   - `SecurityScorer` 加 `trusted_signers_rules: Vec<TrustedSignersRule>` 字段，构造时一次性加载
   - `verify_signature_with_policy` 在升级 Signed → Trusted 时，除查内置 TRUSTED_SIGNERS 外，也查用户配置 rules（regex 匹配 CompanyName）
