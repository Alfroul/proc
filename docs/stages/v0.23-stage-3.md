### 风险 2：E2B 非确定性方差误判（单列改善可能是噪声）

**问题**：基线 run 自身观察过同 query 两次 attempt 行为不同；单列 +3 升幅可能落在方差带内。
**mitigate**：列 ② 终验即方差测量列（同 binary 同配置复跑，两列 v2 自身 delta 给出方差带）；拍板标准要求「主指标向好 + 靶点行为迁移」双证据；幅度 ±2 内且靶点无迁移 → 从保守（不动默认）。

### 风险 3：跨列环境漂移破坏单变量隔离

**问题**：基线 run（2026-08-22）时 Docker daemon 未运行（docker 场景 10 条全失败入画像）；若 v2 列挂机时 Docker 在运行，环境变量混入。
**mitigate**：任务 3 挂机前核对 Docker 状态与基线一致；不一致则关闭后挂机或归档时对 docker 场景单独标注排除（L0 3 / L1 3 / L2 4 条）。

### 风险 4：挂机中断（llama-server / 断电 / 误触）

**mitigate**：已内建——结果 JSON 每 query 全量重写实时落盘 + 单 query LlmError 不中断 + 惰性重 spawn 自愈（v0.22 FULL 实测零中断）；中断后已跑 query 数据完整可分析（不足 70 条则按实际数据对比并标注）。

### 风险 5：`--dirty` 污染 run meta

**问题**：`git_describe()` 运行时取 cwd `git describe --dirty`——挂机时工作树不干净会让 meta 带 `-dirty` 后缀，削弱 D2 的 v1/v2 区分证据。
**mitigate**：任务 2 顺序铁律（commit → rebuild → 挂机）+ 任务 3 第 4 项核对（挂机期间勿改仓库文件——含 IDE 自动生成的 untracked 之外的 tracked 改动）。
