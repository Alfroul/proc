**目标**：用 `ferrisetw` crate 开 ETW KernelTrace session，监听 `EVENT_TRACE_FLAG_DISK_IO` + DiskIo TypeGroup1 事件，按 PID 聚合，得到 per-process 磁盘 R/W BPS（v0.6 只有 per-volume）。进程列表加 `DISK R` / `DISK W` 两列；CLI `proc ls --sort disk_read` 也覆盖到新数据源。

**前置依赖**：阶段 6 已完成（监控面板 + alert 体系已扩好，本阶段补第三个平台专项）。

- `cargo test --release --test test_psi -- --nocapture`（阶段 6 基线）
- `cargo test --release -q`（全量基线）

**技术决策（详见 ADR-0015）**：

- **用 ferrisetw**：Rust 安全封装 KrabsETW，已是事实标准。自写 FFI 会重复造轮子
- **KernelTrace 不 UserTrace**：磁盘 IO 是内核 provider，必须用 `KernelTrace` + `EVENT_TRACE_FLAG_DISK_IO`
- **DiskIo TypeGroup1**：内核 provider GUID `{3d6fa8d4-fe05-11d0-9dda-00c04fd7ba7c}`，事件 ID 15（DiskIo_TypeGroup1）含 `DiskNumber / TransferSize / IssuingThreadId / FileObject / ...`
- **PID 映射**：事件本身不含 PID（只有 IssuingThreadId），需要：
  1. 维护 `thread_id → pid` map（来自 sysinfo）
  2. 或监听 `Thread_Start/Stop` type 事件维护 map
  3. 推荐（更稳）：直接用 sysinfo 的 `Process::threads()` 一次拉所有 thread → pid
- **降级**：非 Windows 平台 stub 返回空；Windows 上 ferrisetw 启动失败（如非管理员）也降级，进程列表的 DISK R/W 列显示 `-`
- **数据源对比**：v0.6 已有 per-process disk_read/disk_write（来自 sysinfo `Process::disk_usage()`），但 sysinfo 在 Windows 实现走的是 `IO_*.ProcessId` 性能计数器，**精度比 ETW 低且粒度只到 bytes/采样周期**。本阶段用 ETW 替换 sysinfo 数据源（同样的列，数据更准）。

详见 `docs/adr/0015-etw-per-process-disk-io.md`。

**任务清单**：

1. **依赖添加 + cfg-gate（10 min）**
   - `Cargo.toml` 加：
     ```toml
     [target.'cfg(windows)'.dependencies]
     ferrisetw = "1"
     ```
   - `default` features 不变（ferrisetw 只在 Windows target 依赖）
   - 验证：Windows 编译通过；Linux/macos 不拉 ferrisetw

2. **新建 `src/disk_io_etw/mod.rs`（1 h）**
   - cfg-gate：`#[cfg(windows)]` 实装
   ```rust
   #[derive(Debug, Clone, Default, serde::Serialize)]
   pub struct DiskIoStats {
       pub read_bps: u64,
       pub write_bps: u64,
   }

   pub type DiskIoMap = std::collections::HashMap<u32, DiskIoStats>; // pid -> stats

   pub struct DiskIoEtwWorker {
       thread: Option<std::thread::JoinHandle<()>>,
       stop_flag: std::sync::Arc<std::sync::atomic::AtomicBool>,
       stats_rx: std::sync::mpsc::Receiver<DiskIoMap>,
   }

   impl DiskIoEtwWorker {
       pub fn spawn() -> Self { /* 见任务 3 */ }
       pub fn latest(&self) -> Option<DiskIoMap> { self.stats_rx.try_recv().ok() }
       pub fn shutdown(self) { /* join thread */ }
   }
   ```
   - 验证：编译通过（API 与 v0.6 的 NetFlowWorker 同款）

3. **ETW provider + callback（2 h）**
   - 新建 `src/disk_io_etw/provider.rs`（Windows only）：
   ```rust
   use ferrisetw::provider::Provider;
   use ferrisetw::trace::KernelTrace;
   use ferrisetw::schema_locator::SchemaLocator;
   use ferrisetw::parser::Parser;

   pub fn start_disk_io_session(
       stop_flag: Arc<AtomicBool>,
       stats_tx: mpsc::Sender<DiskIoMap>,
   ) -> anyhow::Result<()> {
       // 维护 thread_id -> pid map（每 5s 刷新一次 sysinfo）
       let thread_to_pid = Arc::new(Mutex::new(HashMap::<u32, u32>::new()));

       // 启动 ETW session
       let mut trace = KernelTrace::new()
           .named("ProcDiskIoTrace")
           .enable(Provider::kernel(&KernelEventProvider::DiskIo))
           .start()?;  // 注意：KernelTrace 不是 UserTrace

       // 在 callback 内：
       // - 解析 DiskIo_TypeGroup1 schema
       // - 拿 TransferSize / IssuingThreadId / FileObject
       // - 查 thread_to_pid map 拿 pid
       // - 累加到 per-pid 字节计数
       // - 每 1s flush 到 stats_tx
       Ok(())
   }
   ```
   - **难点**：ferrisetw 的 KernelEventProvider 可能不是直接名字，需要查源码确认 enum 路径
   - **难点**：Thread → PID map 的更新策略，sysinfo 的 `System::threads()` 返回 Vec<Thread>，每 thread 含 `tid () -> Pid`（Pid 是 u32）和 owner `pid () -> Pid`
   - 验证：Windows 编译通过；启动 session 不报错

4. **callback 内累加 + 1s flush（1 h）**
   - 用 `Arc<Mutex<HashMap<u32 /*pid*/, (u64 /*r*/, u64 /*w*/)>>>` 作为累加 buffer
   - callback 把每个 DiskIo 事件加到 buffer（read 还是 write 看 `Flags` 字段）
   - 单独的 flush 线程每 1s 拿锁，drain buffer，把 delta 转成 bps（除以采样间隔），推到 stats_tx
   - 验证：buffer 不泄漏（callback 不阻塞）

10. **ADR-0015（30 min）**
    - `docs/adr/0015-etw-per-process-disk-io.md`
    - Status: Accepted
    - Context: v0.6 per-process 磁盘 IO 走 sysinfo（性能计数器，精度低），Resource Monitor 走 ETW 更准
    - Decision: ferrisetw KernelTrace + DiskIo TypeGroup1 + thread→pid map，**覆盖** sysinfo 数据源（不新增列，替换数据源）
    - Alternatives: 沿用 sysinfo / 用 ETW + 用户态 provider / 用 Event Traces for Windows API 自写
    - Consequences: Windows 管理员权限下数据更准；非管理员降级到 sysinfo；增加依赖 ferrisetw（仅 Windows target）
    - 验证：ADR 存在
