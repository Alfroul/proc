### 阶段 1：ADR-0017 + OpenSSL symbol offset 调研 + uprobe hello world

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.9-stage-1.md，完成所有任务后确认完成`
>
> **预测性 doc**：本阶段实际启动时再细化任务清单。

**目标**：产出 v0.9.0 cycle 的设计文档（ADR-0017）+ 调研 OpenSSL 各版本 `SSL_write` symbol offset + 跑通 aya uprobe hello world（最简 uprobe attach 到 `libc.dlopen` 验证框架）。

**前置依赖**：v0.8.0 已 tag（ebpf Linux 真实验证通过）。

**任务清单**（预测）：

1. **写 ADR-0017**（`docs/adr/0017-ebpf-sni-ja4.md`）
   - Status: Accepted
   - Context: v0.7/v0.8 的 ebpf flow graph 只关联 DNS + connect，HTTPS 域名抓不到（DNS cache hit / 系统 hosts 直接走缓存）。需要 uprobe 在 `SSL_write` 入口抓 ClientHello 明文 SNI
   - Decision: OpenSSL 优先 + JA4 按 RFC 9503 + BoringSSL/LibreSSL 后续兼容
   - Alternatives: kprobe on `tcp_connect` + IP 反查（反向 DNS，慢且不准）；NSS 抓 Firefox（独立栈）
   - Consequences: 多版本 OpenSSL offset 表（OpenSSL 1.0/1.1/3.x + BoringSSL + LibreSSL）

2. **OpenSSL symbol offset 调研**
   - `readelf -s /usr/lib/x86_64-linux-gnu/libssl.so.3` 找 `SSL_write` symbol
   - 用 `aya-tool` (cargo install aya-tool) 生成 BTF binding：`aya-tool generate -i ssl -t SSL_write`
   - 验证 offset：`gdb -batch -ex 'disassemble SSL_write' /usr/lib/x86_64-linux-gnu/libssl.so.3`
   - 文档化：每个 OpenSSL 版本（1.0/1.1/3.x）的 `SSL_write` 入参 offset（参数 1 = SSL* / 参数 2 = buf / 参数 3 = len）

3. **uprobe hello world**（最简验证）
   - 在 `src/ebpf/ebpf-ebpf/src/main.rs` 加一个 uprobe 程序 attach 到 `libc:malloc`
   - 进程 malloc 时 ring_buf 推一个 event
   - userspace 端读 ring_buf 打印
   - 验证 aya uprobe 框架在 Linux 真实跑通

**验收标准**：
- ADR-0017 文件存在，Status: Accepted
- OpenSSL 1.1/3.x 的 SSL_write symbol offset 已记录
- uprobe hello world 在 Linux 跑通（malloc 触发 event 推送）
- `cargo build --release --features ebpf` 通过

**容量预估**：~400 行（ADR 200 + uprobe demo 100 + 调研笔记 100），工具调用 30-50 次。
