### 阶段 5：进程父子链 + R17 可疑链检测

> ✅ **已完成**（v0.11.0 阶段 5 会话产出，2026-06-29；commit 引用见 CONTEXT.md「术语演进历史」段）

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.11-stage-5.md，完成所有任务后确认完成`

**目标**：实装 `ProcessInfo.parent_chain: Vec<(u32, String)>`（阶段 1 仅声明骨架，本阶段填实）—— 从当前进程追溯到根（System / Init）；新安全规则 R17 检测「Word/Excel → cmd/powershell/wscript」典型 macro attack 链，扣 35 分。

**前置依赖**：阶段 1 已完成（`ProcessInfo.parent_chain: Vec<(u32, String)>` 字段骨架已就位）。

**依赖测试**（开工时跑这些测试的详情）：
- `cargo test --release --test test_security -- --nocapture`（v0.6/v0.7/v0.11 阶段 4 安全评分框架契约）
- `cargo test --release --test test_collect -- --nocapture`（ProcessInfo 字段 + sysinfo 集成契约）

**任务清单**：

1. **parent_chain 字段实装**（`src/collect.rs`）
   - 阶段 1 已声明 `pub parent_chain: Vec<(u32, String)>`（默认空 Vec）
   - 本阶段在 `refresh_heavy_incremental` 时填充：
     - 用 sysinfo `parent()` 拿当前进程的 parent_pid
     - 从 `cached_processes` 查 parent_pid 对应的 ProcessInfo，递归追溯到根（parent_pid == 0 或找不到时停）
     - 防循环：visited HashSet 防止 PID 复用导致的环（A → B → A）
     - 最大深度：32（防止恶意构造超长链，也避免 sysinfo 异常时的死循环）
   - 字段类型不变（保持 `Vec<(u32, String)>`），只是从空 Vec 变成填充后 Vec

2. **父子链构建逻辑**（`src/security/lineage.rs` 新）
   - `pub fn build_parent_chain(pid: u32, snapshot: &SysinfoRegistry) -> Vec<(u32, String)>`
   - `pub fn detect_suspicious_chain(chain: &[(u32, String)]) -> Option<SuspiciousPattern>`
   - `SuspiciousPattern` enum：`OfficeToShell`（Word/Excel/PowerPoint → cmd/powershell/wscript/cscript/mshta）/ `BrowserToShell`（Chrome/Edge/Firefox → cmd/powershell）/ `ScriptInterpreter`（wscript/cscript/mshta 直接运行）/ `Custom`（用户配置的规则）
   - 加载用户配置：`~/.config/proc/lineage_rules.toml`（可选，默认空 → 只用内置 4 种 pattern）

3. **R17 规则实装**（`src/security/score.rs`）
   - 加 `check_lineage_risk(procs: &[ProcessInfo]) -> Vec<RiskFactor>`
   - 对每个进程：调 `detect_suspicious_chain(&proc.parent_chain)`
   - 命中 `OfficeToShell` → 扣 35 分（比 R16 未签名更严重——这是典型 macro attack 行为）
   - 命中 `BrowserToShell` → 扣 25 分（可能合法，如浏览器扩展调 shell，但有恶意可能）
   - 命中 `ScriptInterpreter` → 扣 15 分（wscript/cscript 直接运行可能合法，如系统脚本）
   - `Custom` 规则按用户配置 weight
   - R17 加到 `SecurityScorer::score` 第 17 步（v0.11 阶段 4 R16 + 阶段 5 R17 = 17 项）

4. **UI 显示**（`src/tui/process_table.rs` + `src/tui/detail_view.rs`）
   - 进程列表不显示 parent_chain（太占空间）
   - Inspector Summary Tab 加「父进程: {parent_name} ({parent_pid})」+「祖父进程链: A → B → C」一行显示
   - 命中 R17 时 Inspector 顶部显示红色警告「⚠ 可疑父子链：Word → powershell」

5. **配置文件支持**（`~/.config/proc/lineage_rules.toml` 可选）
   - 默认不存在 → 只用内置 4 种 pattern
   - 用户显式创建 → 解析 TOML 加自定义规则
   - 格式示例：
     ```toml
     [[rule]]
     name = "my_apps_to_shell"
     parent_pattern = "(?i)(my_editor)"
     child_pattern = "(?i)(cmd|powershell)"
     weight = 30
     ```

6. **测试**（`tests/test_lineage.rs` 新）
   - 单元：`build_parent_chain` 防循环（构造 mock A → B → A 链，验证 visited HashSet 终止）
   - 单元：`build_parent_chain` 最大深度 32（构造 33 层链，验证截断）
   - 单元：`detect_suspicious_chain` 命中 OfficeToShell（mock chain [Word, cmd]）
   - 单元：`detect_suspicious_chain` 命中 BrowserToShell
   - 单元：`detect_suspicious_chain` 命中 ScriptInterpreter
   - 单元：R17 规则扣分（35 / 25 / 15 三档）
   - 集成：mock ProcessInfo parent_chain → BackgroundScorer 评分变化

7. **CONTEXT.md 更新**
   - 加术语：parent_chain / SuspiciousPattern / lineage_rules.toml / R17
   - 术语演进历史加 v0.11.0 阶段 5 行

8. **README FAQ 加一条**
   - 「proc 显示 R17 命中，但我的 Word 启动 cmd 是合法脚本？」答：(1) 检查命令行参数（`proc inspect` 看 cmd args）；(2) 在 `~/.config/proc/lineage_rules.toml` 加白名单条目跳过该 pattern
