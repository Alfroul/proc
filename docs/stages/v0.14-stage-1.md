## ROI 来源（PERF-BASELINE-v0.13 §4 实测）

| fixture | serialize mean | deserialize mean |
|---|---|---|
| 100 进程 | 2.3 µs | 10.2 µs |
| 500 进程 | 9.0 µs | 61.0 µs |
| 1000 进程 | 14.1 µs | **165.4 µs** |

**长 session 累计成本（30 min × 30 FPS × 1000 进程 = 54000 frames）**：
- 全量 deserialize 启动加载：54000 × 165 µs = **9 秒**
- 单帧体积 ~200 KB × 54000 = **~10 GB RAM**（必 OOM）
- 文件体积 ~10 GB（bincode 不压缩）

**stage 1 按需加载预期效果**：
- 启动加载：只读 footer + frame_offsets → **< 100 ms**（无论 session 多长）
- 内存占用：仅当前帧（按需 deserialize）→ **~1 MB**（与 session 长度无关）
- seek：单帧 165 µs（用户无感）

## 任务清单

### 1. `src/record/frame.rs` 加 footer 类型

新增类型（保留现有 `RecordingHeader` / `UiFrame` / `LegacySystemFrame` 不变）：

```rust
/// 文件 footer：v3 文件末尾追加，含 frame_offsets + 元数据。
/// reader open 时只读 footer 即可拿到全部定位信息（无需 deserialize 全部帧）。
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RecordingFooter {
    /// footer 自身格式版本（独立于 header.version，便于 footer schema 演进）
    pub version: u16,
    /// 镜像一份 header.version 用于 sanity check（v3 = 3）
    pub header_version: u16,
    /// 第一帧 timestamp（与 header.start_time 可能差几秒，footer 以实际首帧为准）
    pub start_time: u64,
    /// 末帧 timestamp
    pub end_time: u64,
    /// 帧总数
    pub frame_count: u64,
    /// 全部帧 anomalies 总和（用户面向元数据）
    pub anomaly_count: u64,
    /// 全部帧 docker_events + ops 总和（用户面向元数据）
    pub event_count: u64,
    /// 全 session 最高的 cpu_usage（百分比 0-100）
    pub max_cpu: f32,
    /// 全 session 最高的 memory_used（字节）
    pub max_mem: u64,
    /// 每帧在文件中的字节偏移（指向 8B len prefix 起点）
    pub frame_offsets: Vec<u64>,
}

/// 8-byte trailer 魔数，写在文件最末尾，让 reader 用 file_size - 16 快速识别 v3。
pub const FOOTER_MAGIC: [u8; 8] = *b"PREC3FT\x01";
/// footer 占用的 trailer 大小：footer_bytes + 8B footer_len + 8B FOOTER_MAGIC
pub const FOOTER_TRAILER_LEN: usize = 16;
```

**单元测试**：`RecordingFooter` serde round-trip + 默认构造。

### 3. `src/record/reader.rs` Player 重写为按需加载

新 `Player` 结构：

```rust
pub struct Player {
    path: PathBuf,
    header: RecordingHeader,
    footer: RecordingFooter,            // v3 有；v1/v2 老文件由 sidecar 兜底（也填这个字段）
    file: std::fs::File,                // 持久打开，frame_at 时 seek + read
    /// 单帧 LRU 缓存（last_idx + last_frame），命中率 99%（连续访问同一 idx）
    cache_idx: std::cell::Cell<Option<usize>>,
    cache_frame: std::cell::RefCell<Option<UiFrame>>,
}
```

**`Player::open` 流程**：
1. 打开文件
2. 读 8B header_len + header
3. 检查 header.magic
4. 读 file_size
5. 如果 file_size > 16 + header_len_total：seek 到 file_size - 16 读 trailer
   - trailer 匹配 FOOTER_MAGIC → v3 文件：seek 到 (file_size - 16 - footer_len) 读 footer
   - trailer 不匹配 → v1/v2 老文件：调用 `open_legacy_with_sidecar` 路径
6. 返回 Player

**`Player::frame_at` 签名变更**：
```rust
// 旧：
pub fn frame_at(&self, index: usize) -> Option<&UiFrame>
// 新：
pub fn frame_at(&self, index: usize) -> Option<UiFrame>
```

返回 owned（因为可能不在内存）。开销：1 次 IO seek + 8B len read + N B frame read + 165 µs bincode deserialize @ 1000 进程。完全可接受（参考 PERF-BASELINE）。

实现：
- 检查 cache_idx == Some(idx) → 返回 cache_frame.clone()
- 否则 seek 到 frame_offsets[idx] + 8 → read frame_len + frame_bytes → bincode::deserialize
- 写 cache
- 返回 owned

**`Player::frame_near_timestamp`**：基于 footer.start_time / end_time 二分查找 frame_offsets（无需 deserialize 全部帧）。

**`Player::total_frames` / `time_range` / `header` / `meta`**：
- `total_frames(&self) -> usize` → footer.frame_count as usize
- `time_range(&self) -> (u64, u64)` → (footer.start_time, footer.end_time)
- `header(&self) -> &RecordingHeader` → &self.header
- `meta(&self) -> &RecordingFooter` → &self.footer

**影响面**（需调整调用点）：
- `src/replay/controller.rs:91` `self.replay_player.as_ref()?.frame_at(idx).cloned()` → 去掉 `.cloned()`（frame_at 已 owned）
- `src/replay/controller.rs:104` `if let Some(frame) = player.frame_at(frame_index)` → 不变（if let 自动 owned）
- `src/tui/replay_panel.rs:86` `player.frame_at(current).map(|f| f.timestamp)` → 不变（owned 也支持 .map）

### 4. v1/v2 老文件兼容 + .prec.idx sidecar 缓存

**`src/record/sidecar.rs`（新）**：

```rust
const SIDECAR_MAGIC: [u8; 8] = *b"PRECIDX\x01";

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct IdxSidecar {
    pub magic: [u8; 8],
    pub version: u16,
    pub source_path: String,
    pub source_size: u64,
    pub source_mtime: u64,
    pub header: RecordingHeader,
    pub footer: RecordingFooter,
}

impl IdxSidecar {
    pub fn sidecar_path(prec_path: &Path) -> PathBuf {
        // recording.prec → recording.prec.idx
        let mut s = prec_path.as_os_str().to_os_string();
        s.push(".idx");
        PathBuf::from(s)
    }

    pub fn try_load(prec_path: &Path) -> Option<Self> {
        let sidecar_path = Self::sidecar_path(prec_path);
        let bytes = std::fs::read(&sidecar_path).ok()?;
        let sidecar: IdxSidecar = bincode::deserialize(&bytes).ok()?;
        // 新鲜性检查：source_size + source_mtime 必须匹配当前 prec 文件
        let meta = std::fs::metadata(prec_path).ok()?;
        let size = meta.len();
        let mtime = meta.modified().ok()?
            .duration_since(std::time::UNIX_EPOCH).ok()?
            .as_secs();
        if sidecar.source_size != size || sidecar.source_mtime != mtime {
            return None;  // 文件已变化，sidecar 过期
        }
        if sidecar.magic != SIDECAR_MAGIC { return None; }
        Some(sidecar)
    }

    pub fn write(&self, prec_path: &Path) -> std::io::Result<()> {
        let sidecar_path = Self::sidecar_path(prec_path);
        let bytes = bincode::serialize(self).unwrap();
        std::fs::write(sidecar_path, bytes)
    }
}
```

**`Player::open_legacy_with_sidecar`** 流程：
1. 尝试 `IdxSidecar::try_load(prec_path)` —— 如有 + 新鲜，直接用 sidecar 的 header / footer 构造 Player
2. 否则 fallback 全量加载（保留当前 v1/v2 read 路径）+ 计算 footer 字段（max_cpu / max_mem / anomaly_count / event_count / frame_offsets）+ 写新 sidecar
3. 写 sidecar 失败静默（用户目录只读不致命）

**关键不变量**：v1/v2 老文件**永不重写**（只读，sidecar 单独管理）。

**单元测试**：
- 老文件首次 open → 慢路径（全量加载）+ sidecar 文件生成
- 老文件二次 open → 快路径（sidecar 命中）
- 老文件被改 → sidecar 过期 → 重生成
- sidecar 损坏（随机字节）→ 静默降级到全量加载

```rust
fn run_replay_info(file: &Path) -> anyhow::Result<()> {
    use crate::record::Player;
    let player = Player::open(file.to_path_buf())?;
    let header = player.header();
    let meta = player.meta();
    println!("{}", format("录制文件: {}", file.display()).cyan());
    println!("格式版本:     v{}", header.version);
    println!("主机名:       {}", header.hostname);
    println!("开始时间:     {}", format_iso(header.start_time));
    println!("结束时间:     {}", format_iso(meta.end_time));
    println!("时长:         {}", format_duration(meta.end_time.saturating_sub(meta.start_time)));
    println!("帧数:         {}", meta.frame_count);
    println!("异常事件:     {}", meta.anomaly_count);
    println!("docker/操作:  {}", meta.event_count);
    println!("最高 CPU:     {:.1}%", meta.max_cpu);
    println!("最高内存:     {}", format_bytes(meta.max_mem));
    Ok(())
}
```

## 已知风险与回退

**风险 1：frame_at 签名变更（&UiFrame → UiFrame）影响调用点**
- 影响文件：`src/replay/controller.rs` / `src/tui/replay_panel.rs`

- 如遗漏 → cargo check 立即报错，机械修复

**风险 2：v1 → v3 / v2 → v3 兼容性 bug**
- 缓解：单元测试覆盖 v1 / v2 / v3 三档文件
- 老 .prec 文件继续可用（fallback 路径保留）

**风险 3：sidecar 格式不兼容未来 footer 演进**
- 缓解：sidecar 含 version 字段；未来 footer 升级 sidecar 自动失效重生成

**回退策略**：stage 1 失败 → `git checkout` 还原 reader.rs / writer.rs / frame.rs → stage 1 重做。stage 1 不影响 stage 2-4 独立性（书签 / 搜索 / 倒放都可基于 v2 全量加载路径开发，stage 1 延后到 stage 5 前补做）。
