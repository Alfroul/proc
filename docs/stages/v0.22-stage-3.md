### 2. `src/agent/session_log.rs`（新，~330 行业务）

**JSONL schema（serde 锁定，roundtrip 测试锚）**：

```rust
pub struct SessionLogEntry {
    pub seq: u64,          // 0 起，头条目是 SessionStart
    pub ts_rel_ms: u64,    // Instant 相对毫秒（单调）
    #[serde(flatten)]
    pub event: LogEvent,
}

#[serde(tag = "kind", rename_all = "snake_case")]
pub enum LogEvent {
    SessionStart { provider: String, wall_start: String },  // 墙钟锚（ISO UTC）
    QueryStarted { text: String },                          // query 原文（≤ 200 chars 截断）
    TextDelta { chars: usize },                             // 聚合段（ts = 首 delta 时间）
    ToolStart { name: String },
    ToolFinished { name: String, is_error: bool, result_chars: usize },
    ConfirmRequested { tool_name: String },
    ConfirmDecision { approved: bool },
    TurnFinished,
    SessionFinished { stop: String, final_chars: usize, final_head: String },  // stop 用 StopCause::label；head ≤ 200
    Error { message: String },                              // ≤ 200 chars 截断
}
```

**SessionRecorder**：

- `SessionRecorder::start(provider) -> SessionRecorder`——`dirs_config_dir()/sessions/<utc_timestamp_compact()>-<provider>.jsonl`；目录创建 / 打开失败 → 静默降级（内部 None，后续 log 全 no-op，不影响会话）；测试注入用 `start_in_dir(dir, provider)`
- `SessionRecorder::disabled()`——`[session].log = false` 或降级态
- `Clone`（Arc<Mutex<Inner>> 内部——sink / confirm closure 与 session_loop 共享）
- `log(&self, ev: &SessionEvent)`——唯一记录入口：TextDelta 进聚合缓冲（首 delta 记 ts，累计 ≥ 64 chars 写一条；非 delta 事件先 flush 缓冲再写）；每条写完 flush（per-line flush——会话崩溃时已写行完整，Drop 无需特殊收尾）
- `log_confirm_decision(&self, approved: bool)`——confirm 转发线程专用

**analyze_session_log(path) -> Result<SessionMetrics, String>**：逐行解析（空行跳过 / 坏行报行号）→ 状态机走一遍：

- `SessionMetrics { provider, wall_start, total_ms, queries: Vec<QueryMetrics>, totals: MetricsTotals }`
- `QueryMetrics { index, query_head, ttft_ms: Option, duration_ms: Option, delta_events, delta_chars, tool_calls, tool_errors, turns, confirms, confirm_decision_max_ms: Option, stop: Option<String>, error: Option<String> }`
- `MetricsTotals { queries, answered, ttft_avg_ms/max_ms, generation_avg_ms, delta_events/chars, tool_calls/tool_errors, turns, confirms, confirm_approved/denied, confirm_decision_avg_ms, errors }`
- query 外事件（如空 query 的 Error）只进 totals 不造 query

**format_session_metrics(&SessionMetrics) -> String**：纯函数格式化（provider / 墙钟起点 + 时长 / 总指标块 TTFT·生成时长·delta·tool·confirm / per-query 表）。

## 已知风险（stage 3 实施时关注）

### 风险 1：confirm 转发线程的生命周期

**问题**：决策记录靠换出 oneshot + std::thread 转发；面板 drop 未决策 / teardown 发 Denied / 正常 y/n 三条路径都必须不泄漏不挂死。

**mitigate**：oneshot Sender drop → `blocking_recv` 返 Err → 线程退出（不转发，runner 侧 RecvError → Denied 语义不变）；先记录后转发保证日志序。C 组测试覆盖 Denied 路径；teardown 发 Denied 是 v0.21 既有语义（走换出通道透明）。

### 风险 2：session log 写入的时序与体量

**问题**：sink 在 session 线程的 runtime block_on 内同步写文件；高频 delta 若逐条落盘体积失控。

**mitigate**：BufWriter + per-line flush（单行小、事件率低）；TextDelta ≥64 chars 聚合 + 测试断言行数上限；单会话几百 KB 预期（brainstorm 风险 2 实测验证项）。

### 风险 3：spawn 签名变更的测试波及

**问题**：`AgentSession::spawn` 3 → 4 参动 2 个既有测试文件。

**mitigate**：各补 `SessionRecorder::disabled()` 一行（小修范畴，brainstorm 步 11）；两个文件全量跑确认零破坏——它们正是「SessionEvent 形状零改动」的验证锚。

### 风险 4：E2B FULL 挂机稳定性（brainstorm 风险 1）

**mitigate**：已内建——单 query LlmError 不中断 + JSON 每 query 实时落盘 + 惰性重 spawn 自愈。挂机前先跑 `--quick`（26 query）冒烟确认链路。

### 风险 5：`docs/eval/` 目录首次入 git

新目录（本 stage 创建）；md 归档入 commit，json 留本地。注意 `.gitignore` 不需要动（json 在仓库根 / 工作目录产出，不在 docs/eval/ 下留存 json）。
