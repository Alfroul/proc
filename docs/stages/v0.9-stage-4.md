### 阶段 4：切片 C — `tcp_sendmsg` / `tcp_recvmsg` kprobe 累计 bytes

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.9-stage-4.md，完成所有任务后确认完成`

**目标**：用 kprobe hook `tcp_sendmsg` / `tcp_recvmsg`，按 `(pid, saddr, daddr)` 聚合累计 `bytes_out` / `bytes_in`。让 ProcessFlow 能回答「这个进程发了多少字节到 example.com」。

**前置依赖**：v0.9 阶段 2 已完成（SNI 关联已能匹配 pid + remote_ip + ssl_ptr）。

**任务清单**（预测）：

1. **内核态 kprobe 程序**（`src/ebpf/ebpf-ebpf/src/main.rs`）
   - 加 `#[kprobe]` 函数 attach 到 `tcp_sendmsg`（入参：`struct sock *sk` + `struct msghdr *msg` + `size_t size`）
   - 加 `#[kprobe]` 函数 attach 到 `tcp_recvmsg`
   - 从 `struct sock *sk` 提取 saddr / daddr / sport / dport
   - 用 `bpf_get_current_pid_tgid()` 取 pid
   - 用 `BPF_MAP_TYPE_HASH` 维护 `(pid, saddr, daddr, dport) -> u64 bytes_total` map

2. **FlowBytesMap 读取**
   - userspace 端 1s tick 遍历 map → drain 到 `Vec<BytesRecord>`
   - 每个 BytesRecord 关联到对应 ProcessFlow（pid + remote_addr + remote_port 匹配）
   - 累计到 `ProcessFlow.bytes_out` / `bytes_in`

3. **map 大小控制**
   - hash map 大小固定 4096（足够 500 进程 × 平均 8 连接）
   - LRU 淘汰：30s 未更新的 entry 自动清（用 last_seen ts）

4. **ProcessFlow 扩字段**
   ```rust
   // src/ebpf/flow.rs
   pub struct ProcessFlow {
       // ... v0.7 字段
       pub bytes_out: u64,  // 已有但 v0.7 留 0
       pub bytes_in: u64,   // 已有但 v0.7 留 0
       pub sni: Option<String>,        // v0.9 阶段 2 加
       pub ja4: Option<String>,        // v0.9 阶段 3 加
   }
   ```
   - 更新 TD-17 标注：bytes_out / bytes_in 已实现

5. **测试**（`tests/test_ebpf_bytes.rs`）
   - 集成测试（ignored）：启动 proc flows → 触发 `curl https://example.com -o /tmp/test`（下载 ~1MB）→ 等 5s → proc flows 显示该 flow bytes_in > 1_000_000
   - 单元测试：mock BytesRecord 聚合逻辑

**验收标准**：
- `tcp_sendmsg` / `tcp_recvmsg` kprobe attach 成功
- bytes_out / bytes_in 在 ProcessFlow 真实有值（不为 0）
- curl 下载 1MB 后 flow bytes_in > 1MB
- TD-17 bytes 部分标实现

**容量预估**：~500 行（内核态 200 + userspace 200 + 测试 100），工具调用 30-50 次。**关键风险**：`struct sock` offset 在不同内核版本可能不同（Linux 4.x / 5.x / 6.x），开工时需 BTF 验证。
