### 阶段 4：进程签名验证 + R16「未签名进程」

> ✅ **已完成**（v0.11.0 阶段 4 会话产出，2026-06-29；commit 引用见 CONTEXT.md「术语演进历史」段）

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.11-stage-4.md，完成所有任务后确认完成`

**目标**：用 `WinVerifyTrust` API 验证每个进程的 `.exe` 是否微软 / 已知 CA 签名；`ProcessInfo.signature_status` 字段实装（阶段 1 仅声明骨架，本阶段填实）；BackgroundScorer 异步验证（避免主线程 50ms tick 阻塞）；新安全规则 R16 命中未签名进程扣分。

**前置依赖**：阶段 1 已完成（`ProcessInfo.signature_status: SignatureStatus` 字段骨架已就位，默认 `Pending`）。

**依赖测试**（开工时跑这些测试的详情）：
- `cargo test --release --test test_security -- --nocapture`（v0.6/v0.7 安全评分框架契约）
- `cargo test --release --test test_background_scorer -- --nocapture`（异步评分框架契约）

**任务清单**：

1. **写 ADR-0021**（`docs/adr/0021-process-signature-verification.md`）
   - Status: Accepted
   - Context: malware 常见特征 = 未签名 .exe 从 %TEMP% 启动；当前 proc 15 项安全评分无签名维度
   - Decision: `WinVerifyTrust` API（windows-rs `Win32::Security::WinTrust` feature）+ `SignatureStatus` 4 状态机 + BackgroundScorer 异步集成 + LRU 缓存（避免每 heavy refresh 重复验证同一 .exe）
   - Alternatives: (a) `sigcheck.exe`（Sysinternals，外部依赖）；(b) `Get-AuthenticodeSignature` PowerShell（spawn 子进程，慢）；(c) `wintrust` crate（不维护，最后 release 2019）；(d) `rust-pkcs11`（库方向错误，PKCS#11 是智能卡 / HSM）
   - Consequences: WinVerifyTrust 调用 ~10-50ms / .exe（必须异步）；cat 文件（.cat）签名也覆盖（驱动 + 系统组件）；内核态签名（驱动签名）走不同 policy，本周期不区分

2. **SignatureStatus 4 状态机**（`src/security/mod.rs`，阶段 1 已声明 enum，本阶段实装转换逻辑）
   - `Pending`：默认值，BackgroundScorer 还没验证（启动后头 1-2 个 heavy refresh 内会填实）
   - `Trusted`：签名链能追溯到微软根 CA（含微软签名 + 已知第三方 CA 如 DigiCert / Sectigo）
   - `Untrusted`：未签名 / 自签名 / 签名链断裂 / 签名过期
   - `Unknown`：验证失败（文件不存在 / 无法读取 / API 调用错误）
   - 加 `SignatureStatus::from_wintrust_result(result: u32) -> Self` 转换函数

3. **签名验证实装**（`src/security/signature.rs` 新）
   - `pub fn verify_signature(exe_path: &Path) -> SignatureStatus`
   - 用 `WinVerifyTrust` + `WINTRUST_ACTION_GENERIC_VERIFY_V2` policy + `WTD_REVOKE_NONE` flag
   - **跨平台 stub**：非 Windows 直接返回 `Unknown`（cfg-gate）
   - **测试可注入**：暴露 `verify_signature_with_policy(path, policy_override)` 内部函数，单元测试用 mock policy 验证状态转换

4. **LRU 缓存**（`src/security/signature.rs`）
   - `SignatureCache` 持 `HashMap<PathBuf, (SignatureStatus, SystemTime)>`（路径 → 状态 + 验证时间）
   - TTL：1 小时（避免长跑后状态过期，但避免每 heavy refresh 重复验证）
   - 容量上限：1000 条（避免内存膨胀）；超限时按 LRU 淘汰
   - 缓存键：`.exe` 完整路径（不含 PID——同 .exe 不同 PID 签名相同）

5. **BackgroundScorer 集成**（`src/security/score.rs` + `src/security/background.rs`）
   - `BackgroundScorer::request` 加 `signature_cache: Arc<Mutex<SignatureCache>>` 参数
   - 评分时对每个 ProcessInfo：
     - cache 命中 → 直接用 cached status
     - cache 未命中 + status == Pending → 调 `verify_signature` 填实 + 写 cache
   - **不阻塞主线程**：所有验证在 BackgroundScorer 工作线程跑
   - 主线程 heavy refresh 时 poll BackgroundScorer 结果，更新 `cached_processes` 中 `signature_status` 字段

6. **R16 规则实装**（`src/security/score.rs`）
   - 加 `check_signature_risk(procs: &[ProcessInfo]) -> Vec<RiskFactor>`
   - 对每个进程：`signature_status == Untrusted` → 扣 25 分（与 v0.6 R5 已知 C2 端口 30 分同档，略低——未签名不必然恶意）
   - `signature_status == Pending / Unknown` → 不扣分（避免误报：启动后头 1-2 个 heavy refresh 内全部 Pending，扣分会刷屏）
   - R16 加到 `SecurityScorer::score` 第 16 步（v0.6 14 项 + v0.7 R15 + v0.11 R16 = 16 项）

7. **UI 显示**（`src/tui/process_table.rs`）
   - 进程列表加 `🔒` / `⚠` / `❓` / `⏳` 标记（Trusted / Untrusted / Unknown / Pending）
   - Inspector Summary Tab 加「签名状态: Trusted (微软)」/「签名状态: Untrusted」行

8. **测试**（`tests/test_signature.rs` 新）
   - 单元：mock `verify_signature_with_policy` 返回不同 result code → 转换为对应 SignatureStatus
   - 单元：SignatureCache LRU 淘汰逻辑（1001 条插入后最旧的被淘汰）
   - 单元：SignatureCache TTL 过期（1h 后重验）
   - 集成：BackgroundScorer 异步填 signature_status（mock verify 后 poll 拿到结果）
   - 集成：R16 规则 — `signature_status == Untrusted` 命中扣 25 分；`Pending` / `Unknown` 不扣分
   - 跨平台 stub：非 Windows 上 verify_signature 直接返 Unknown

9. **CONTEXT.md 更新**
   - 加术语：SignatureStatus / SignatureCache / verify_signature / R16
   - 术语演进历史加 v0.11.0 阶段 4 行

10. **README FAQ 加一条**
    - 「proc 显示我的应用是 Untrusted，但我有签名？」答：检查签名链是否完整（中间证书是否缺失）+ 签名是否过期 + 是否 cat 文件签名（驱动 / 系统组件走 .cat，proc 当前不区分，留 TD）
