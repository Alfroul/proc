## stage 2 执行顺序建议（按依赖关系）

### Wave 1：删整模块 / 整文件（破坏性最大但最干净）

1. `rm -rf src/ebpf/ebpf-ebpf/`（内核态 sub-project）
2. 删 `src/ebpf/{stub.rs, elf_loader.rs, worker.rs}` 三个文件
3. 拆 `src/ebpf/flow.rs`：保留 ProcessFlow / FlowSource(Schannel only) / Schannel 相关 free function
4. 删 `src/psi.rs` + `tests/test_{psi,ebpf_flow,linux_stubs}.rs`
5. `cargo check` —— 预计大量错误（imports / use 引用）

### Wave 2：清理 lib.rs / mod.rs 引用

6. `src/lib.rs`：删 `pub mod ebpf;` + `pub mod psi;` + 删 not-windows cfg 分支
7. `src/workers/manager.rs`：删 `ebpf_worker: Option<EbisuBpfWorker>` 字段 + spawn / metrics 集成
8. `src/app.rs`：删 `App::flows` 字段相关 ebpf 方法 / `tick_flows_ebpf`
9. `cargo check` —— 错误数应大幅下降

### Wave 3：单文件 cfg gate 清理（按 3.1 → 3.2 顺序）

10. 3.1 简单文件（单 cfg gate）：批量删 not-windows 分支，每改 3-5 文件跑 `cargo check`
11. 3.2 重点文件：`src/collect.rs` / `src/process_control.rs` / `src/inspect/*.rs`，逐处确认
12. `cargo check` + `cargo test` —— 应恢复绿色

### Wave 4：清空 Cargo.toml feature stub

13. `Cargo.toml`：删 stage 1 保留的 `nvtop = []` / `nethogs = []` / `ebpf = []` 3 个空 feature flag
14. `cargo check` —— 应 0 warnings（rustc 1.80+ unexpected_cfgs 检查）

### Wave 5：清理 imports / dead code

15. `cargo clippy --release --all-targets -- -D warnings` —— 修复残留 dead code / unused imports
16. `cargo fmt --all -- --check` —— 格式校验
17. `cargo test --release -q` —— 全量测试，应 ≥ 1146 passed / 0 failed（与 stage 1 基线一致或略低，因为删了 Linux stub tests）

## stage 2 容量预估

- **代码删除量**：~1500-2000 行（src/ebpf/ ~400 + src/psi.rs ~150 + tests/* ~480 + cfg gate 删除 ~500-800）
- **新增 / 修改量**：~250-400 行（imports 清理 + 类型简化 + dead code 修复）
- **工具调用次数**：60-100 次（含 30+ 次 cargo check / test 验证）
- **Checkpoint 概率**：中等偏高（`src/collect.rs` 6 处 + `src/process_control.rs` 9 处可能需要中段 checkpoint）。建议**分两个 sub-stage**：
  - **sub-stage 2a**：Wave 1 + Wave 2（删整模块 + 清理 lib.rs 引用），单会话可完成
  - **sub-stage 2b**：Wave 3 + Wave 4 + Wave 5（cfg gate 逐文件清理），单会话可完成
- **风险评估**：低。所有 Linux 路径代码从未在用户的 Linux 真机环境跑过（TD-19 长期推迟），删除不影响 Windows 主路径。
