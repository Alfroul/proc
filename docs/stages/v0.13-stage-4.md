## 注意事项

### A. 方案 c 的 release 简化
- v0.13 是「性能验证 cycle」，**无业务代码改动**
- 与 v0.12.0（6 stage + 大量业务代码改动）相比，本 stage 4 收尾简化：
  - 无新增「已知限制」（cycle 不引入新限制）
  - 无新功能用户面向说明（benchmark suite 是开发者面向，不是用户面向）
  - CHANGELOG v0.13.0 段比 v0.12.0 短得多
- 但仍需 surgical 完成所有文档同步

### B. 版本号一致性
- `Cargo.toml` version
- `Cargo.lock` 自动同步（cargo build 触发）
- `CHANGELOG.md` `[0.13.0]` header
- `git tag v0.13.0`
- README banner（如有版本号引用）

四处必须一致。

### C. tag 不 push
- `git tag -a v0.13.0` 仅本地打
- 用户确认后再 `git push origin v0.13.0`
- 这与 v0.12.0 / v0.12.1 / v0.12.2 模式一致

### D. stage docs ✅ 标记
- 每个 stage doc 头部加 `> ✅ **已完成**` 是项目惯例（v0.11/v0.12 都有）
- 让未来 cycle 的会话能快速判断哪些 stage 已交付
- 本 stage 完工时**所有 4 个 stage docs 都应有 ✅ 标记**

### E. CONTEXT.md 不入 commit
- CONTEXT.md 是 `.gitignore` 私有文件
- 但本地需要更新（保持术语一致性）
- commit 不含此文件改动
