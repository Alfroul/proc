**目标**：把 v0.7 阶段 4 只接入 List view 的 FilterExpr 扩展到 Tree view 和 AppGroup view。用户在这两个视图按 `:` 也能切到 FilterExpr 模式，输入 `cpu > 5 AND name =~ /chrome/` 能正确过滤。

**前置依赖**：v0.8.0 阶段 2 已完成（FilterExpr 错误信息已中文化，体验更好）。

**核心挑战**（详见 `docs/tech-debt.md` TD-15 段）：

1. **Tree view**：`tree::TreeNode` 是 `ProcessInfo` 派生的精简结构，filter 通过 `get_filtered_tree_visible()` 走 substring。需要：在 `get_filtered_tree_visible` 加 mode 分支，FilterExpr 走 TreeNode 含的 ProcessInfo 字段。

2. **AppGroup view**：`AppGroupProcess` 只有 `pid/name/cpu_usage/memory/role_hint` 4 字段，**不持 `&ProcessInfo`**。FilterExpr::apply 接 `EvalCtx{process: &ProcessInfo, ...}` 直接调不到。要接需改 `app_group_filtered_visual_items` 签名传 cached_processes 进来，或改 AppGroup 结构持 `Arc<ProcessInfo>`。

**依赖测试**（开工时跑）：

- `cargo test --release --test test_filter_expr -- --nocapture`（v0.7 阶段 4 + v0.8 阶段 2 基线）
- `cargo test --release --test test_app_group -- --nocapture`（AppGroup 现状）
- `cargo test --release --test test_tree -- --nocapture`（Tree 现状）

**任务清单**：

#### 切片 A：Tree view 接入（半天）

1. **改 `tree::TreeNode` 持 FilterExpr 模式**（`src/tree.rs`）

   - 如果是精简：要么扩字段（持 Arc<ProcessInfo>），要么改 `get_filtered_tree_visible` 签名传 cached_processes
   - 推荐方案：传 cached_processes（不动 TreeNode 结构），保持 v0.7 阶段 5 拆分边界

2. **`get_filtered_tree_visible` 加 mode 分支**（`src/view_models/process_panel.rs`）
   ```rust
   pub fn get_filtered_tree_visible(&self, cached_processes: &[ProcessInfo]) -> Vec<TreeNode> {
       match &self.search.mode {
           QueryMode::Substring => /* 原 v0.7 逻辑 */,
           QueryMode::FilterExpr(expr) => {
               /* 用 expr.apply 过滤 ProcessInfo，再 map 到 TreeNode */
           }
       }
   }
   ```

3. **`handle_tree_key` 加 `:` 激活**（`src/view_models/process_panel.rs`）
   - 在 `'/'` 激活 substring 旁边加 `':'` 激活 FilterExpr
   - 复用 SearchState::handle_input（v0.7 已实现 `:` 切换）

#### 切片 B：AppGroup view 接入（半天）

4. **改 AppGroup 结构或 API 签名**（`src/view_models/process_panel.rs` + `src/app_group.rs`）
   - 选项 A（推荐）：改 `app_group_filtered_visual_items(&self, cached_processes: &[ProcessInfo])` 签名，按 pid 查原始 ProcessInfo
   - 选项 B：改 `AppGroupProcess` 持 `Arc<ProcessInfo>`（需改构造点 + 序列化）
   - **选 A**：影响面小，不动数据结构，符合 surgical 原则

5. **AppGroup 内 FilterExpr 实现**
   ```rust
   pub fn app_group_filtered_visual_items(
       &self,
       cached_processes: &[ProcessInfo],
   ) -> Vec<AppGroupProcess> {
       match &self.search.mode {
           QueryMode::Substring => /* 原 v0.7 逻辑 */,
           QueryMode::FilterExpr(expr) => {
               /* 用 pid 查 cached_processes 拿 ProcessInfo，再 expr.apply */
               /* AppGroup 的 cpu/memory 是聚合值，FilterExpr 用聚合值判断（不是单进程） */
           }
       }
   }
   ```
   - 注意：AppGroup 是按 .exe 聚合的，cpu_usage = sum(同 exe 的所有进程 cpu)。FilterExpr 在 AppGroup view 应判断**聚合值**（`cpu > 50` 表示「该 .exe 总 cpu > 50」），不是单进程

6. **`handle_app_group_key` 加 `:` 激活**（`src/view_models/process_panel.rs`）
   - 同 Tree，复用 SearchState::handle_input
