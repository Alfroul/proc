**核心设计**（ADR-0034 D1/D3/D4 定值规格）：

- **索引单元**：`Entry { query, tools: Vec<String>, conclusion_head, source }`——`source` 用 `EntrySource::{Session, Eval}` 二值 enum 区分主语料与 bootstrap（D3 口径标记）
- **session 成功段状态机**（D3）：`QueryStarted{text}` 开段 → 段内 `ToolStart{name}` 计数 ≥ 1 → `SessionFinished{stop: "end_turn", final_head}` 收尾且段内无 `Error` 事件 → 产出 Entry；error 段 / 零 tool 段 / 非 `end_turn` 收尾（max_steps / empty_after_retry / interrupted）一律不产出
- **bootstrap 解析**（D3）：`EvalRunFile` 反序列化直读（serde Deserialize 已派生，零新解析代码）→ `results` filter `passed == true` → `Entry { query, tools: actual_tools, conclusion_head: final_text_head, source: Eval }`
- **去重**：聚合层按归一化 query（lowercase + 去空白）全局去重，先 session 后 eval、同 normalized query 保留首见（附录 B「3 run 去重后 40 独立 query」口径）
- **分词**（D1）：ASCII 字母数字连续段 → lowercase 单 token；连续 CJK 段（U+4E00~U+9FFF，其余字符含中文标点作分隔）→ 长度 1 产单字 token、长度 ≥ 2 滑窗 2-gram；中英文混合 query 自然切分
- **评分**（D1）：`score(entry) = Σ_{t ∈ tokens(query)} idf(t) × min(tf(t, entry.query), 3)`，`idf = ln(1 + N/df)`（N = 条目总数，df = query tokens 含 t 的条目数），不做长度归一化；`min_score = 1.0` 逐条门槛（低于不入选）；top-k = 3；排序 score 降序、并列按 `tools.len()` 降序、再并列稳定保序
- **污染排除**（D4，检索前过滤）：exact match（归一化后全等）一律排除；词元覆盖率 `|set(tokens(query)) ∩ set(tokens(entry.query))| / min(两集合大小)` ≥ 0.6 排除（双向 min 分母）；排除数进返回值（stage 3 命中次数报告的数据源）
- **注入模板渲染**（D2，纯函数）：`[历史经验参考]` 头 + 逐条 `- "<query>" → tool1 → tool2（结论：<conclusion_head 截 80 chars>）` + `[当前问题] <原 query>`；预算硬上限 **1200 chars**（≈800 token，中文 ~1.5 chars/token 粗估），超限按相关性降序**整条截断**（不截半条）；无命中（min_score 门槛下零条目）→ 原文透传零注入痕迹；`est_tokens = round(chars / 1.5)` 随返回值携带（D4 报告口径）
- **索引构建**（D3）：`RagIndex::build` 全量重建（百级文件毫秒级，不做增量）；目录缺失 / 文件损坏 → 跳过该源 + 一次 stderr 警告 + 继续其余源（`SessionRecorder::disabled()` 同款静默降级契约，最终可能空索引但绝不 panic）

## 已知风险（stage 2 实施时关注）

### 风险 1：CJK 分词边界的实现自由度

**问题**：D1 只定「连续 CJK 2-gram」——单字 CJK 段、中文标点、CJK 扩展区（U+9FFF 以上）归属未逐字定值，实装随意发挥会埋下检索口径漂移。
**mitigate**：目标段定死口径（CJK 判定 U+4E00~U+9FFF；其余字符含中文标点一律作分隔；单字 CJK 段产单字 token）；内联单元三例锚定（含中文标点分隔例）；ADR 落地注记回写实装口径。

### 风险 2：覆盖率口径歧义（multiset vs 集合）

**问题**：D4 公式 `|tokens ∩ tokens|` 未明示集合还是多重集——分母 min 同样有歧义，实装选错会导致排除判定与 0.6 阈值标定（附录 B 依据的 <0.4 / >0.7 分离带）错位。
**mitigate**：统一**去重集合**口径（`token_set`）；内联单元锚定边界例（恰 0.6 排除 / 双向 min——长 query 含短 entry 场景）；集成 C 组三类样例是最终判定锚。

### 风险 3：历史 eval JSON 与当前 struct 的反序列化兼容

**问题**：bootstrap 直读 `EvalRunFile` 依赖 v0.22/v0.23 归档的三份 JSON 与当前 struct 字段一致——若后续 eval schema 演进（加字段无 default），旧 JSON 解析会失败。
**mitigate**：三份基线 JSON 均由当前 harness 产出（v0.22 起 `EvalRunFile` 字段未变）；解析失败走 Err → 警告跳过该源不 panic（静默降级兜底）；测试用真实 struct 构造序列化闭环验证。schema 未来演进是 stage 3+ 事务，本阶段不预设。

### 风险 4：session JSONL 的 query text 已截断 200 chars

**问题**：`SessionLogEntry` 落盘时 query text 经 `truncate_chars(…, 200)`——Entry.query 是截断版，超长 query 的检索与排除判定基于截断文本。
**mitigate**：与排除判定（exact / coverage）同底（当前 query 在 runner 侧同口径截断后判定即一致）；eval bootstrap 的 query 无截断（`QueryResult.query` 全文）不受影响；ADR D3 落地注记显式声明此口径，stage 3 接线时 runner 侧沿用同款截断。
