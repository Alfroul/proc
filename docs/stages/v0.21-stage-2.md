### 2. 项 2：`AgentRunner::run_streaming`（~200 行）

签名：

```rust
pub async fn run_streaming(
    &self,
    query: &str,
    history: &[Message],
    sink: &(dyn Fn(StreamEvent) + Send + Sync),
    confirm: Option<&(dyn Fn(ConfirmRequest) + Send + Sync)>,  // ConfirmHook
    cancel: &std::sync::atomic::AtomicBool,
) -> Result<RunnerOutcome, LlmError>
```

> **实施注记**：hook 签名从规划的 `Fn(ConfirmRequest) -> Receiver` 简化为
> `Fn(ConfirmRequest)`——runner 自建 oneshot（reply 放进 request 发出），rx
> 由 runner 持有 await，hook 只负责发事件，session 层闭包无需包装 rx。

- **消息组装**：`[system] + history(克隆) + [user query]`——history 由 session 层维护（runner 无状态）
- **tools / options**：与 complete 路径同款（entry 4 + proc_finish 起步、`tool_choice=Required`、`max_tokens=1024`）
- **流式消费循环**（每 turn）：`provider.stream()` 逐 delta——`Delta::Text` → 累积 + `sink(TextDelta)`；`Delta::ToolCall` → 收集；`Delta::ToolResult` → 忽略（MockProvider fixture 回放含此 delta，runner 自己执行 tool）；`Delta::EndTurn` → 记 stop_reason。流结束 → `sink(TurnFinished)`
- **assistant message 组装**：content = 累积文本（空则 None）+ tool_calls；后续逻辑与 complete 路径逐分支对齐：proc_finish 提取 answer → EndTurn return；real_calls 执行（`expand_tools_for_help_calls` 决策 J + `spawn_blocking`）；无 calls 有 text → EndTurn return；空响应（text 空 + 无 calls）→ nudge 重试一次（同 turn 内二连 stream）
- **cancel 检查点**（3 处）：每 turn 开头 / 流消费循环每个 delta 后 / confirm await 期间——命中即返 `Ok(RunnerOutcome{ final_text: "已中断", stop: Interrupted })`，已完成 steps 保留在 trace
- **既有 `run` / `run_with_progress` / `execute_tool_calls` 零改动**（CLI ask 回归锚）

## 已知风险（stage 2 实施时关注）

### 风险 1：TUI 同步主循环 × async agent（brainstorm 风险 1，本阶段逻辑侧 mitigate）

session 线程 + std mpsc + `try_recv` drain 是既定架构；本阶段测试覆盖「线程 send / 测试主线程 drain」端到端即等价验证 TUI 消费模式。注意 session 线程内 `rt.block_on` 是线程私有 runtime，不与任何外部 runtime 纠缠。

### 风险 2：confirm 挂起生命周期（brainstorm 风险 2）

- run_streaming 的 confirm await 必须 cancel-aware（`select!` + 短轮询），否则 Drop 后线程永久悬挂（非 daemon 线程会阻止进程退出）
- reply Sender drop（面板崩溃 / 事件丢弃）→ rx Err → 视为 Denied，不挂死
- D 组测试必须带超时断言（`exited` 轮询 < 5s）

### 风险 3：E2B 流式行为未实测（brainstorm 风险 3）

ScriptedStreamProvider 先全覆盖 runner 聚合逻辑（分片 ToolCall 已由 provider 层 ToolCallAccum 聚合为完整 Delta::ToolCall——runner 收到的已是聚合后形态）；E2B 冒烟放最末，如不可靠 stage 3 降级「tool 步骤流式 + 最终文本一次性」（事件面不变）。

### 风险 4：多轮 ctx 溢出（brainstorm 风险 4）

滑动窗口 12 轮 + `truncate_history` 单元测试；溢出本身依赖真实模型 ctx——降级路径（LlmError → Error 事件）已有，stage 3 面板展示提示。

### 风险 5：写操作放行安全边界（brainstorm 风险 5）

- Approved 测试只用不存在的 PID / 不存在的容器名（业务错误路径，验证放行语义而非真杀）
- `confirm: true` 注入点在 runner（Approved 分支内），dispatch 的 complete 路径永无注入通道
- CLI ask 拦截语义不变（E 组回归锚）

### 风险 6：容量 ~1350 行接近铁律 19 上限（brainstorm 风险 6）

排序已定（项 1 → 项 2 → 项 3 → 测试 → 冒烟）；如上下文告急（< 30%）在 confirm 协议段前触发 Checkpoint（`docs/handoff-stage-2-checkpoint.md`），前两项独立成立。测试与实现交织进行（每项完成即写对应组测试），不留大块尾部测试。
