## 实施决策（stage 4 内拍板，按 brainstorm 步 15 规则记录）

### 决策 A：SSE 分帧器抽共享模块 `src/agent/sse.rs`（不 feature-gate）

`SseFrameBuffer` 现居 `llama_cpp_provider.rs`（feature `llama-cpp` gate 内），
anthropic-only build（`--no-default-features --features anthropic`）拿不到。
抽到新模块 `src/agent/sse.rs`（无 cfg gate——纯字节处理零依赖），llama_cpp_provider
`pub use super::sse::SseFrameBuffer;` re-export 保持既有测试 import 路径
（`proc::agent::llama_cpp_provider::SseFrameBuffer`）不变。SSE 协议本身
provider 无关（`data:` 帧提取 + 跨 chunk 半行安全），Anthropic SSE 的
`event:` 行由 `extract_data_payload` 天然忽略、事件类型从 data JSON 的
`type` 字段判别——分帧器零改动复用。

### 决策 B：消息转换规则（proc Message 超集 → Anthropic Messages API）

| proc 侧 | Anthropic 侧 | 说明 |
|---|---|---|
| `Message{role: System}` | 顶层 `"system": "<拼接>"` 字段 | Anthropic 不允许 messages 里出现 system role；多条 system 以 `\n\n` 拼接 |
| `Message{role: User}` | `{"role":"user","content":"..."}` | |
| `Message{role: Assistant, content}` | content blocks：`[{"type":"text","text":...}]` | text 空则不产 block |
| `Message{role: Assistant, tool_calls}` | 同一消息 content blocks 追加 `{"type":"tool_use","id","name","input":<Value>}` | `input` 直接用 `arguments` Value（Null 降级 `{}`） |
| `Message{role: Tool, tool_results}` | `{"role":"user","content":[{"type":"tool_result","tool_use_id","content"}...]}` | Anthropic 要求 tool_result 在 **user** 消息里；一个 proc Tool 消息的多条 result 打包成一个 user 消息的多个 block |
| 空 assistant 消息（content 空 + 无 tool_calls，runner 空响应重试路径 push 的占位） | **整条跳过** | Anthropic 要求每条消息 content 非空，空 assistant 会 400 |

首消息必须是 user role：system 提取后 messages 首条即 user query，天然满足。

### 决策 C：采样参数最多取一 + grammar 忽略

Anthropic API 约束 `temperature` / `top_p` / `top_k` **至多设一个**（同设 400）。
AgentOptions 的 temperature/top_p/top_k 来自 agent.toml `[llama-cpp]` 段透传
（runner 无差别下发），provider 侧按优先级 **temperature > top_p > top_k 只取
第一个 Some**，其余忽略 + `tracing::warn`。`grammar`（GBNF）是 llama.cpp 专属
扩展字段，AnthropicProvider 静默忽略（不进请求体）。`stop_sequences` 原生同义
直传。

### 决策 D：tool_choice 映射 + max_tokens 回退链

- `ToolChoice::Auto` → `"tool_choice": {"type":"auto"}`；`Required` →
  `{"type":"any"}`（Anthropic 语义：强制本轮必调 tool，与 OpenAI `required`
  等价）。**proc_finish 控制 tool 由 runner 注入 tools 数组，provider 只透传
  schema**——Sonnet 在 `any` 约束下调 `proc_finish(answer)` 结束循环，与
  stage 3b 决策 I 的循环语义完全兼容，无需 provider 特判。
- `max_tokens` 是 Anthropic API **必填**字段：`options.max_tokens
  .unwrap_or(self.max_tokens)`（runner 恒传 Some(1024)——stage 3b 决策 I 的
  防超长生成结论，Sonnet 同样适用；FixtureRecorder 直调 complete 时落到
  provider 默认值）。

### 决策 E：anthropic 对照 fixture 不默认录制（可选项 deferred）

brainstorm 项 8 原文「录制 anthropic 对照 fixture（可选）」。落地**不做**：
(1) MockProvider 的 query_hash 只含 query 文本（stage 2 决策 D——provider 名
不计入），同目录混放两 provider 的 fixture 会互相覆盖索引；(2) CI 回放价值
为零——fixture 格式是 provider 无关的 Delta 序列，E2B 真实 fixture 已覆盖
回放路径。留 REVIEW-v0.20 记录 deferred（如 v0.21 需要，落独立目录
`tests/fixtures/agent-anthropic/` 即可，FixtureRecorder 现成可用）。

### 决策 F：Sonnet 验收口径 = 合计 ≥ 48/50（不按 L0/L1 分别硬性）

brainstorm 风险 1 mitigate 5 + 附录 A 验收表：Anthropic 对照「同 50 query
全跑通，≥ 48/50」。测试统计 L0/L1 分项打印但 **assert 合计 ≥ 48**（Sonnet
对 L0/L1 无能力差异，分档硬性是 E2B 小模型专属口径）。QUICK 模式
（`PROC_AGENT_QUICK=1`，每 (scenario, level) 抽 1 ≈ 18 query）仅供迭代，
正式验收跑 FULL。

### 决策 G：model ID 以 API 实测为准

agent.toml `[anthropic].model` 默认值 `claude-sonnet-4-6`（brainstorm 决策 9
写入）。真实验收时如 API 返 404 model-not-found（Anthropic 常要求 dated ID
如 `claude-sonnet-4-6-YYYYMMDD`），按 API 错误信息调整代码默认值 + agent.toml
样例，并在阶段报告记录实测结论。

### 决策 H：Sonnet 真实验收 deferred（用户拍板 2026-08-17：无 API key）

用户确认本机无 `ANTHROPIC_API_KEY`，**跳过 50 query 真实对照验收**——
REVIEW-v0.20 验收段记录 deferred（验收标准 #6 降档），不做假设性数字。
降级验证已做：(1) 24 个 CI 纯逻辑测试覆盖消息转换 / tool_choice 映射 /
响应解析 / stream 聚合全链路（零网络）；(2) CLI 冒烟——无 key 走
`from_env` friendly error；**无效 key 真实请求到达 api.anthropic.com 返
403 并正确映射 `LlmError::Api{status, body}`**（HTTP 路径 + headers + 错误
处理全链路验证；model ID 有效性在 auth 之后才校验，决策 G 风险留存——
有 key 后首个真实请求即验证）。`#[ignore]` 验收测试已就位
（`test_agent_stage4_anthropic_acceptance`），用户后续拿到 key 可直接跑：
`ANTHROPIC_API_KEY=... cargo test --release --features anthropic -- --ignored
test_agent_stage4_anthropic_acceptance`。

- struct 扩 `api_key: String`（from_env 读 `ANTHROPIC_API_KEY` 存入——
  from_env 签名 `(model, max_tokens)` 不变保 stage 1 测试兼容）+ 内部

- **请求构造（纯函数）**：
  - `messages_to_anthropic(messages) -> (Option<String> system, Vec<Value>)`
    （决策 B 转换表）
  - `tools_to_anthropic(&[ToolSchema]) -> Vec<Value>`：`{"name","description",
    "input_schema":<parameters>}`（注意是 `input_schema` 不是 `parameters`）
  - `build_request_body(messages, tools, options) -> Value`：model / max_tokens
    （决策 D 回退链）/ system / messages / tools / tool_choice（决策 D 映射）/
    采样参数最多一（决策 C）/ stop_sequences；**不带 stream 字段**（stream
    由 query param 或请求体 `"stream":true` 控制，两路径共用本函数 + 外层
    补 stream 位）
- **响应解析（纯函数）**：
  - `parse_messages_response(json) -> Result<CompleteResponse, LlmError>`：
    content blocks 数组 → text 块拼接 content + tool_use 块转 `ToolCall`
    （`input` 已是 object，缺省 `{}`）；`stop_reason` 映射 `end_turn→EndTurn`
    / `tool_use→ToolUse` / `max_tokens→MaxTokens` / `stop_sequence→StopSequence`；
    `usage.input_tokens/output_tokens` → `Usage`；顶层 `error` 字段（API 错误
    响应形状）→ `LlmError::Api`
- **stream SSE 聚合**：
  - `AnthropicStreamAccum`：`content_block_start`（tool_use 块记 id/name）+
    `content_block_delta`（`text_delta` → 逐帧 yield `Delta::Text`；
    `input_json_delta.partial_json` 按 index 累积）+ `content_block_stop`
    （tool_use 块 arguments JSON 字符串 → Value，失败降级 Null）→ yield
    `Delta::ToolCall`；`message_delta.delta.stop_reason` → `Delta::EndTurn`
    恰好一次（`message_stop` 兜底补发）；`ping` / `message_start` 忽略
  - `stream()` 走 `stream::once(async setup) + try_flatten`（与 stage 3a
    决策 C 同款——trait 非 async 签名下的请求发起方案；Anthropic 无子进程
    spawn，setup 只发 HTTP 请求）
- `complete()` / `stream()` 公共路径：POST + headers（`x-api-key` /
  `anthropic-version` / `content-type`）→ 非 2xx → `LlmError::Api{status, body}`

## 已知风险（stage 4 实施时关注）

### 风险 1：ANTHROPIC_API_KEY 未设置（本机确认无）

真实验收 / CLI 冒烟都需要。mitigate：任务 5 开跑前向用户要 key（仅会话内
export，不落盘）；CI 测试零网络依赖不受影响。

### 风险 2：model ID 不匹配（决策 G）

`claude-sonnet-4-6` 若非 API 接受的 model ID（Anthropic 常要 dated ID），
首个真实请求 404。mitigate：读 API error body 按提示调整默认值，阶段报告
记录。

### 风险 3：Anthropic 消息校验 400（空 content / 首消息非 user / tool_use
与 tool_result 不配对）

决策 B 转换表已规避（空 assistant 跳过 / system 顶层提取 / tool_result 按ID
配对回填）。mitigate：真实验收首 query 冒烟即暴露；转换层单测覆盖各形态。

### 风险 4：验收期间 API 限流 / 网络

50 query × 多轮 tool call（Sonnet 单 query 约 2-4 轮）≈ 150-200 次请求。
mitigate：reqwest 默认连接复用；失败 query 打印 LlmError 诊断；QUICK 模式
先验证链路再跑 FULL。

### 风险 5：Sonnet 对「写操作拦截」query 的行为差异

L1 的 4.5 / 8.3~8.5 期望主 tool 是监控类（monitor_add 等被
WRITE_TOOL_NAMES 拦截的是 kill/usb_release/docker_rm/record——monitor 不在
拦截清单），Sonnet 拿到 `ok:false` 拦截 JSON 后会解释并给命令行（few-shot
教学意图）。与 E2B 同口径验收（tool_hit + final_text 非空），无额外风险。
