### 阶段 1：Worker Restart（TD-4）+ ProcessInfo 字段骨架

> ✅ **已完成**（v0.11.0 阶段 1 会话产出，2026-06-29；commit 引用见 CONTEXT.md「术语演进历史」段）

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.11-stage-1.md，完成所有任务后确认完成`

**目标**：
1. 实装 `WorkerManager::restart(name)` + 指数退避策略（TD-4 长期挂账，v0.6.0 至今）
2. 为阶段 4（签名验证）/ 阶段 5（父子链）锁定 ProcessInfo 字段骨架——`signature_status: SignatureStatus` + `parent_chain: Vec<(u32, String)>`，**只声明字段 + Default 实现**，业务逻辑留给后续阶段（Spike 风格）
3. crash banner 升级：显示 restart 状态（restarting / restarted / permanent failure）

**前置依赖**：v0.10.0 已 tag（commit `b7a13f7` / 959 passed 基线）。

**依赖测试**（开工时跑这些测试的详情）：
- `cargo test --release --test test_metrics -- --nocapture`（worker metrics 框架，restart 需要兼容）
- `cargo test --release --test test_panic_hook_chain -- --nocapture`（panic hook + crash report，restart 与之协作）

**任务清单**：

1. **写 ADR-0019**（`docs/adr/0019-worker-restart-policy.md`）
   - Status: Accepted
   - Context: TD-4 长期挂账；v0.6.0 阶段 3 catch_unwind 截获 panic 后 worker 永久死亡，用户必须重启 proc
   - Decision: 指数退避（5s / 30s / 5min）+ 最大重试次数 3 + reset 计数（运行 1h 无 panic 后归零）；与 crash banner 集成显示 restart 状态
   - Alternatives: (a) 立即重启（无退避，可能 panic loop）；(b) 永久死亡（v0.10 行为）；(c) 用户手动重启按钮（侵入）
   - Consequences: 重启期间 worker 缺数据（如 port_worker 死亡 → 端口面板不刷新）；3 次失败后永久死亡 + banner 持续红色

2. **ProcessInfo 字段骨架**（`src/collect.rs`）
   - 加 `pub signature_status: SignatureStatus` 字段（`#[serde(default)]`）—— **默认 `Pending`**，阶段 4 由 BackgroundScorer 异步填实
   - 加 `pub parent_chain: Vec<(u32, String)>` 字段（`#[serde(default)]`）—— **默认空 Vec**，阶段 5 由 collect 时填实
   - 加 `SignatureStatus` enum 定义到 `src/security/mod.rs`（跨模块共享）：`Pending` / `Trusted` / `Untrusted` / `Unknown`，`#[derive(Debug, Clone, Copy, PartialEq, Eq, Default, Serialize, Deserialize)]`，`#[default] Pending`
   - 3 处字面量构造点（`collect.rs` heavy refresh / `collect.rs` tests / `cli/ls.rs` mk_process helper）同步加 `signature_status: SignatureStatus::Pending` + `parent_chain: Vec::new()`
   - **不写** WinVerifyTrust 调用（留阶段 4）
   - **不写** parent_chain 填充逻辑（留阶段 5）

3. **WorkerManager::restart 实装**（`src/workers/manager.rs`）
   - 加 `restart_history: HashMap<&'static str, RestartState>` 字段到 WorkerManager
   - `RestartState { retry_count: u32, last_restart: Option<SystemTime>, last_reset: SystemTime }`
   - `pub fn restart(&mut self, name: &str) -> bool` —— 检查退避窗口 + 重试次数；满足条件则重新 spawn 对应 worker；返回 true 表示已触发重启
   - 重启 worker 时复用各 worker 的 `try_spawn` 入口（port_worker / usb_worker / net_flow_worker / dns_log_worker / disk_io_etw_worker / schannel_etw_worker）
   - 不实装 `ebpf_worker` restart（Linux-only，本 cycle 不动 ebpf 路径）

4. **App::tick 集成 restart 检查**（`src/app.rs`）
   - `tick_poll_crashes` 升级：drain `crash_rx` 时不再仅 push 到 `active_crashes`，同时调 `workers.restart(&crash.worker)`
   - 加 `App::restart_tick` 方法（每 1s 调一次）：检查 `restart_history` 中处于退避等待的 worker，时间到了就尝试 respawn

5. **Crash banner 升级**（`src/tui/crash_banner.rs` 或同款位置）
   - banner 渲染时查 `restart_history` 状态：
     - retry_count = 0 + 正在等待 → 「worker {name} restarting in {N}s...」
     - retry_count > 0 + 重启成功 → 「worker {name} restarted (retry #{N})」3 秒后淡出
     - retry_count >= 3 → 「worker {name} permanent failure」持续红色

6. **测试**（`tests/test_worker_restart.rs` 新）
   - 单元：mock worker panic → restart() 调用 → 验证 worker 重新 spawn（mock try_spawn 计数）
   - 退避窗口：连续 panic 验证 5s / 30s / 5min 间隔
   - 最大重试：4 次 panic 后 retry_count = 3，restart() 返回 false
   - reset 计数：1h 无 panic 后 retry_count 归零
   - 集成（admin only）：spawn proc → kill 一个 worker 线程 → 验证 banner 显示 restarting → 5s 后 worker 恢复

7. **CONTEXT.md 更新**
   - 加术语：WorkerRestartPolicy / RestartState / SignatureStatus / parent_chain（4 个新术语）
   - 术语演进历史加 v0.11.0 阶段 1 行

8. **tech-debt.md 更新**
