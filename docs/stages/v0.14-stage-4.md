## ROI 来源（brainstorm §子方向 3：倒放）

**现状**：`ReplayController` 只有正向播放（`ReplaySpeed::Half / Normal / Double / Quad`），倒放只能手动 Left Left Left 单帧后退。事后分析「刚才发生了什么」时，用户希望按播放键自动回退——典型场景：监控到 anomaly 触发，用户停在 anomaly 帧想看「之前 5 秒发生了什么」，目前只能手动按 Left 150 次。

**stage 4 落地效果**：
- 回放时按 `r` 切方向：Forward ↔ Reverse（小写 r；不与录制键 `R` 冲突——后者是 Shift+R 在 App 主路径触发 `toggle_recording`，ReplayController 仅在回放路径激活，路由不到）
- 倒放速度档位同正向：Half=0.5x（每两 tick 退 1 帧）/ Normal=1x / Double=2x / Quad=4x
- timeline icon 反映方向：正向播放 ▶ / 倒放 ◀ / 暂停 ⏸（暂停时不区分方向，UX 与「播放中」对齐）
- 倒放到首帧（idx=0）自动暂停（对称：正向到末帧暂停既有逻辑保留）

**与 stage 1-3 的衔接**：stage 1 v3 按需加载让单帧 seek = 165 µs（@ 1000 进程），倒放每 tick 反向 seek 一帧无感延迟；stage 2 书签 `B` 键、stage 3 搜索 `/` + n/N 跳转都不受 direction 影响（书签 / 搜索是「跳转」语义，与 playback direction 独立）。

### 1. `src/replay/controller.rs` 加 `ReplayDirection` 枚举 + 字段

新枚举与 `ReplaySpeed` 平级：

```rust
/// v0.14 stage 4：录屏回放方向。`Forward` = 帧索引递增（默认），
/// `Reverse` = 帧索引递减（倒放）。
///
/// 设计取舍：作为独立枚举（而非扩 ReplaySpeed 8 档）—— speed 与 direction
/// 正交（任意 speed × 任意 direction 组合），独立字段更清晰，UI 渲染 / 配置
/// 序列化也直观（未来 `proc replay --speed 2x --reverse` CLI flag 时不动
/// ReplaySpeed 序列化契约）。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum ReplayDirection {
    /// 默认方向：帧索引递增。
    #[default]
    Forward,
    /// 倒放：帧索引递减。
    Reverse,
}

impl ReplayDirection {
    #[must_use]
    pub fn is_reverse(self) -> bool {
        matches!(self, Self::Reverse)
    }

    /// v0.14 stage 4：UI icon（与 timeline 渲染共用同一字符表）。
    /// 暂停态由调用方决策（playing == false 时显示 ⏸，与本方法无关）。
    #[must_use]
    pub fn icon(self) -> &'static str {
        match self {
            Self::Forward => "\u{25B6}",  // ▶
            Self::Reverse => "\u{25C0}",  // ◀
        }
    }

    /// 切方向（Forward ↔ Reverse）。
    #[must_use]
    pub fn toggle(self) -> Self {
        match self {
            Self::Forward => Self::Reverse,
            Self::Reverse => Self::Forward,
        }
    }
}
```

### 3. tick 双向分支（ReplayController::tick）

`tick` 方法的 step 计算不变（Half / Normal / Double / Quad 四档），但在 `current_frame` 应用时按 direction 分支：

```rust
pub fn tick(&mut self) -> ReplayAction {
    if self.bookmark_panel.is_some() {
        return ReplayAction::Noop;
    }
    let Some(ts) = self.timeline_state.as_mut() else {
        return ReplayAction::Noop;
    };
    if !ts.playing || ts.total_frames == 0 {
        return ReplayAction::Noop;
    }
    // Half speed steps every other tick; the rest advance by N frames per tick.
    let step = match ts.speed {
        ReplaySpeed::Half => {
            ts.half_tick = (ts.half_tick + 1) % 2;
            usize::from(ts.half_tick == 0)
        }
        ReplaySpeed::Normal => 1,
        ReplaySpeed::Double => 2,
        ReplaySpeed::Quad => 4,
    };
    if step == 0 {
        return ReplayAction::Noop;
    }
    // v0.14 stage 4：方向分支。正向 saturating_add + clamp 到末帧；
    // 倒放 saturating_sub + clamp 到首帧。到边界自动暂停。
    match ts.direction {
        ReplayDirection::Forward => {
            let last = ts.total_frames.saturating_sub(1);
            ts.current_frame = (ts.current_frame + step).min(last);
            if ts.current_frame >= last {
                ts.playing = false;
            }
        }
        ReplayDirection::Reverse => {
            ts.current_frame = ts.current_frame.saturating_sub(step);
            if ts.current_frame == 0 {
                ts.playing = false;
            }
        }
    }
    ReplayAction::ApplyFrame
}
```

**边界对称性**：
- 正向：到末帧（`current_frame >= last`）暂停（既有逻辑保留）
- 倒放：到首帧（`current_frame == 0`）暂停（新逻辑）

**Half 速度的 half_tick**：切方向不重置 half_tick——节奏连续性优于「切方向后第一个 tick 必动」（与 speed 切换不重置 half_tick 同款原则）。

### 6. VT100 回放路径（`src/tui/mod.rs::run_vt_replay`）

VT100 replay 是独立循环（`run_vt_replay`），与 UiFrame replay 不同路径。stage 4 决策：**不为 VT100 路径加倒放**——VT100 文件是字节流（无结构化帧索引），倒放需要把整个字节流倒序解析（每个 VT100 序列需反向应用：clear / cursor move / SGR 等），实现成本远超 stage 4 的 ~250 行预算（实际 ~1000+ 行 + VT100 反向解释器）。

** surgical 取舍**：
- VT100 replay 路径保留既有正向行为
- `r` 键在 VT100 replay 路径下 no-op（不报错，但也不切方向）
- CONTEXT 术语段标注「VT100 replay 无倒放」（与 stage-3 「VT100 replay 无时间轴搜索」同款注释）

**实现**：`run_vt_replay` 的键位 handler 加 `KeyCode::Char('r') => {}` 显式吞掉（避免未来 VT100 路径加了其他功能时 `r` 误触发），或保留既有 fallthrough 不动（`r` 在 VT100 replay 路径下本来就是 no-op）。stage 4 走后者（最小改动）。

## 已知风险与回退

**风险 1：`r` 键误触发**
- 现状：`r` 在回放路径无绑定（fallthrough no-op）；本 stage 新增切方向绑定
- 用户预期：回放时按 `r` 切方向是 stage 4 新功能，用户首次按 `r` 会有「咦这是干啥」的瞬间——status_message 提示「倒放中（再按 r 切回正向）」弥补
- 缓解：status_message 在每次 toggle 后必显示，让用户立即理解发生了什么

**风险 2：倒放时 half_tick 节奏**
- Half 速度倒放：`(half_tick + 1) % 2`，half_tick=0 时 step=1（后退），half_tick=1 时 step=0（间歇）
- 切方向不重置 half_tick：连续切方向可能让用户感知「节奏不规律」——但 speed 切换也不重置 half_tick（既有行为），保持一致
- 缓解：unit test `toggle_direction_does_not_reset_half_tick` 验证节奏连续

**风险 3：倒放时搜索 n/N 跳转 UX**
- 现状：n=下一命中（帧索引增大），N=上一命中（帧索引减小），与 direction 解耦
- 倒放时用户可能预期 n=「时间倒退的下一命中」（帧索引减小）——vim 习惯是按 search 方向走
- 缓解：stage 4 doc 明确「n/N 与 direction 解耦」+ status_message 不变（n/N 跳转后保持既有「命中 N/M 帧」提示）
- 未来优化（v0.15+）：如用户反馈强烈，加 direction 感知的 n/N（倒放时反转 cursor 移动方向）

**风险 4：tick 倒放与 ApplyFrame 副作用**
- App::apply_replay_frame 是基于 current_frame 的克隆应用到 panels，与方向无关——倒放每次 tick 把前一帧覆盖到 panels，正确
- 缓解：既有 apply_replay_frame 测试覆盖 frame_at(idx) → 应用流程，倒放复用同一路径，无需新增

**风险 5：VT100 路径行为不一致**
- 现状：UiFrame replay 路径有倒放，VT100 replay 路径无倒放
- 用户预期：用户可能不知道当前是哪种 replay（VT100 vs UiFrame）——但 VT100 replay 是独立 CLI 子命令（`proc replay-vt`），与 UiFrame replay（`proc replay`）入口不同，用户使用时已知类型
- 缓解：CONTEXT 术语段标注「VT100 replay 无倒放」；VT100 replay 路径 `r` no-op 不报错（保留既有 fallthrough）

**回退策略**：stage 4 失败 → `git checkout` 还原 `src/replay/{controller,mod}.rs` / `src/app.rs` / `src/tui/replay_panel.rs` → stage 4 重做。stage 4 不依赖 stage 5 任何代码，独立可回退。倒放是独立 tick 分支，回退不影响 stage 1-3 已落地的格式 v3 / 书签 / 搜索功能。
