### 阶段 6：FlowAggregator 关联 + UI 显示 SNI/JA4/bytes

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.9-stage-6.md，完成所有任务后确认完成`

**目标**：把前 5 个阶段产出的 SNI / JA4 / bytes 数据集成到 FlowAggregator + 端口面板 Flow 子视图 + 安全评分 R15。用户能看到「哪个进程连了 example.com，发了多少字节，TLS 指纹是 X」。

**前置依赖**：v0.9 阶段 2-5 全部完成。

**任务清单**（预测）：

1. **FlowAggregator 集成 SNI / JA4 / bytes**
   - `src/ebpf/flow.rs::FlowAggregator::ingest_sni_event(SniEvent)`
     - 用 ssl_ptr 或 (pid, ts) 关联到现有 ProcessFlow
     - 写入 sni / ja4 字段
   - `FlowAggregator::ingest_bytes_record(BytesRecord)`
     - 累加 bytes_out / bytes_in

2. **ProcessFlow Display 扩展**
   - `impl Display for ProcessFlow` 加 SNI / JA4 / bytes 字段
   - 格式：`[pid 1234 chrome] 142.250.x.x:443 sni=google.com ja4=t13d1715h2_... out=12KB in=1.2MB`

3. **端口面板 Flow 子视图扩列**（`src/tui/port_table.rs`）
   - 现有列：PID / 进程名 / 远端 / 端口 / 域名 / 首次见到
   - 新增列：JA4 / bytes_out / bytes_in
   - 表格列宽自适应（参考 help_panel Workers 区段 v0.7 阶段 1 TD-8 修复模式）

4. **`proc flows` CLI 输出扩**（`src/cli/flows.rs`）
   - human-readable 表格加 JA4 / bytes 列
   - JSON 输出加 ja4 / bytes_out / bytes_in 字段

5. **R15 安全评分增强**（`src/security/flow.rs`）
   - 现有 v0.7 R15 命中条件：(1) dns_name 不在白名单 (2) 10s 内 ≥ 50 个不同 IP
   - v0.9 新增命中条件：(3) JA4 指纹在「已知挖矿 / C2 客户端」黑名单
   - 黑名单来源：开源威胁情报（如 [ja4-rs](https://github.com/FoxIO-LLC/ja4) 数据库）+ 用户配置 `~/.config/proc/ja4_blocklist.txt`

6. **测试**（`tests/test_flow_aggregator_v09.rs`）
   - ingest SNI / bytes 事件 → ProcessFlow 字段正确填充
   - 多 flow 聚合：同 pid 多个连接，每个独立 ProcessFlow
   - R15 JA4 黑名单触发：mock ja4 在黑名单 → 评分扣分

**验收标准**：
- 端口面板 Flow 子视图显示 SNI / JA4 / bytes 列
- `proc flows` JSON 输出含 ja4 / bytes_out / bytes_in
- R15 黑名单触发（手动：加测试 ja4 到 ~/.config/proc/ja4_blocklist.txt → 触发后扣分）
- 全量回归 ≥ 950 passed

**容量预估**：~600 行（aggregator 200 + UI 200 + R15 100 + 测试 100），工具调用 30-50 次。
