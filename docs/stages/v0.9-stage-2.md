### 阶段 2：切片 A — uprobe on `SSL_write` 抓 ClientHello SNI

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.9-stage-2.md，完成所有任务后确认完成`

**目标**：在 OpenSSL `SSL_write` 入口（uprobe）抓 ClientHello 明文，解析出 SNI 字段，通过 ring_buf 推到 userspace。

**前置依赖**：v0.9 阶段 1 已完成（uprobe 框架跑通 + symbol offset 已知）。

**任务清单**（预测）：

1. **内核态 uprobe 程序**（`src/ebpf/ebpf-ebpf/src/main.rs`）
   - 加 `#[uprobe]` 函数 attach 到 `/lib/x86_64-linux-gnu/libssl.so.3:SSL_write`
   - 入参：`SSL *ssl`（参数 1，BPF 用 PT_REGS_PARM1）+ `const void *buf`（参数 2）+ `int num`（参数 3）
   - 读 buf 前 N 字节（ClientHello 最大 ~16KB，但首 1024 字节足够 SNI）
   - 用 `bpf_probe_read_user` 把 buf 内容读到栈

2. **ClientHello 解析**（`src/ebpf/sni_parser.rs` 新文件）
   - TLS record header（5 字节）：ContentType=22（Handshake）+ Version + Length
   - Handshake header（4 字节）：HandshakeType=1（ClientHello）+ Length
   - ClientHello body：Version(2) + Random(32) + SessionID(varlen) + CipherSuites(varlen) + Compression(varlen) + Extensions(varlen)
   - 遍历 Extensions 找 `extension_type = 0`（SNI）→ 解析 server_name list → 取第一个 entry
   - 验证：用 `openssl s_client -connect example.com:443 -servername example.com` 抓真实 ClientHello，比对解析结果

3. **ring_buf event 结构**
   ```rust
   // src/ebpf/flow.rs 扩
   #[repr(C)]
   pub struct SniEvent {
       pub pid: u32,
       pub ts: u64,
       pub fd: u32,
       pub ssl_ptr: u64,  // SSL* 地址，关联同一连接
       pub sni_len: u8,
       pub sni: [u8; 256],  // SNI 最大 253 字节
   }
   ```
   - 通过 RingBuf 推到 userspace

4. **userspace 处理**（`src/ebpf/worker.rs` 扩）
   - 收 SniEvent → 转 `SniRecord { pid, ts, sni: String, ssl_ptr }`
   - 推到 FlowAggregator

5. **测试**（`tests/test_ebpf_sni.rs` 新文件）
   - SNI parser 单元测试：用预录的 ClientHello bytes 解析（curl example.com 的真实抓包）
   - 集成测试：`sudo cargo test --features ebpf --test test_ebpf_sni -- --ignored`
     - 启动 proc flows → 触发 `curl https://example.com` → 验证 SNI event 出现 + sni = "example.com"

**验收标准**：
- uprobe attach 到 SSL_write 成功
- ClientHello 解析正确（手动 curl + 看 proc flows 输出）
- ring_buf 推 SniEvent 到 userspace
- ignored 集成测试通过

**容量预估**：~800 行（内核态 200 + parser 300 + 测试 300），工具调用 50-70 次。**关键风险**：aya uprobe API 可能与 v0.7 阶段 8 的 tracepoint API 差异大，开工时需读 aya 文档。
