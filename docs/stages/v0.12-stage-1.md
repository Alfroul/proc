### 阶段 1：Spike — ADR-0022 + Cargo.toml 清理 + 范围审计

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.12-stage-1.md，完成所有任务后确认完成`

**目标**：锁定 Windows-only 平台决策（ADR-0022），清理 Cargo.toml 中已明确不再需要的 Linux 依赖项，产出 stage 2 用的「Linux 代码移除范围审计」报告。本阶段**不删任何业务代码**（Spike 原则）。

**前置依赖**：v0.11.0 已 tag（`96416b5`），commit `d1beb6d`（A 类小修）+ `3d9a4b4`（brainstorm）已在 master。

**依赖测试**（开工时跑这些测试的详情）：
- `cargo test --release -q`（summary，应 ≥ 1146 passed）
- `cargo fmt --all -- --check`
- `cargo clippy --release --all-targets -- -D warnings`

**任务清单**：

1. **写 ADR-0022 Windows-only 平台决策**（`docs/adr/0022-windows-only-platform.md`）
   - Status: Accepted
   - Context: 用户主力 Windows 开发，Linux 路径（eBPF / PSI / nvtop / nethogs）一直未在真机环境充分验证（TD-19 主动推迟过两次）；维护双平台代码库成本高，v0.11 cycle 多次出现 Linux 路径相关 P2（cfg-gate 误判 / lifetime 问题等）；用户决策 proc 转为 Windows-only 应用聚焦核心用户场景
   - Decision: v0.12 起 proc 仅支持 Windows 10 1809+ / Windows 11。Linux/macOS 不再编译（Cargo.toml 移除 `target.'cfg(not(target_os="windows"))'` deps + `target.'cfg(target_os="linux")'` deps + ebpf feature + workspace member src/ebpf/ebpf-ebpf）；移除 src/ebpf/ / src/psi.rs 等模块；移除 ~30 文件 cfg gate；release CI 仅保留 Windows target
   - Alternatives: (a) 继续双平台，接受维护成本；(b) 仅移除 ebpf（最不成熟部分），保留 sysinfo Linux 路径；(c) fork 给社区维护 Linux 版本
   - Consequences: 旧 Linux/macOS 用户需 fork 或停留在 v0.11.0；ADR-0016（eBPF flow graph）Status 改 Superseded by ADR-0022；ADR-0013（PSI）/ ADR-0014（EcoQoS，仍保留）需重新评估；ADR-0011（FilterExpr）中关于 FlowSource.Ebpf 的描述要修订
   - Migration path: 用户 `git checkout v0.11.0` + `cargo build` 仍可用 Linux 路径，但不接受新功能

2. **更新历史 ADR Status**（不删文件，只改 Status 字段）
   - `docs/adr/0016-ebpf-flow-graph.md`：Status 从 Accepted 改 `Superseded by ADR-0022`，加注「v0.12 移除 ebpf 路径，ProcessFlow.source 仅保留 Schannel 变体」
   - `docs/adr/0013-psi-monitoring.md`：Status 从 Accepted 改 `Deprecated (v0.12 移除)`，加注「PSI 是 Linux 4.20+ 特性，v0.12 Windows-only 后不再适用」
   - 其他 ADR（0009 MCP / 0011 FilterExpr / 0019 worker restart / 0020 DNS ETW / 0021 signature）保持 Accepted

3. **Cargo.toml 清理**（保守，不删业务代码）
   - 删 `[target.'cfg(not(target_os = "windows"))'.dependencies]` 段（libc 等仅 Linux 用）
   - 删 `[target.'cfg(target_os = "linux")'.dependencies]` 段（aya / aya-log）
   - 删 `[features] ebpf = ["dep:aya", "dep:aya-log"]` 行
   - 删 `[workspace] members = ["src/ebpf/ebpf-ebpf"]` 段
   - 删 `default = ["nvidia", "nvtop", "nethogs"]` 中 `nvtop` / `nethogs`（Linux only feature）
   - 删 `[features] nvtop = []` / `nethogs = []` 行
   - 保留 `nvml-wrapper` optional + `nvidia` feature（Windows NVIDIA GPU 用）
   - `cargo build --release` 确保仍编译通过（不删业务代码只是 feature flag 调整，应无影响）

4. **写「Linux 代码移除范围审计」报告**（`docs/stages/v0.12-stage-2-audit.md`，供 stage 2 用）
   - 用 `rg -l 'cfg\(target_os\s*=\s*"linux"\)|cfg\(not\(target_os\s*=\s*"windows"\)\)|cfg\(target_os\s*=\s*"macos"\)' --type rust` 列全部 cfg gate 文件
   - 分类：
     - **整模块删除**：`src/ebpf/`（6 files）/ `src/psi.rs`
     - **整文件删除**：`tests/test_linux_stubs.rs` / `tests/test_psi.rs`（如保留为 stub skip，注明）
     - **cfg gate 清理**：~25-30 文件含 `#[cfg(not(target_os="windows"))]` / `#[cfg(target_os="linux")]` 块，stage 2 删除非 Windows 分支保留 Windows 分支
     - **跨平台保留**：`src/smart/mod.rs`（smartctl 跨平台）/ `src/collect.rs` 部分（sysinfo 跨平台）
   - 每个 cfg gate 文件给出 stage 2 修改策略（删哪个分支、保留哪个）
   - 估算 stage 2 工作量（行数 / 文件数 / 触发 Checkpoint 概率）

5. **CONTEXT.md 加 v0.12.0 段**
   - 顶部「⚠ 已知限制」段更新：移除 Linux ebpf / TD-19 相关条目，加「v0.12 起 Windows-only」
   - 「术语演进历史」加 v0.12.0 阶段 1 行（ADR-0022 决策记录，业务术语不变）

6. **tech-debt.md 更新**
   - TD-17 / TD-19 标 ✅ Fixed in v0.12.0 阶段 1（决策：不再追这个方向 = 自动清零）
   - TD-18 已 Fixed（v0.10.0）保持
