## 任务清单

### 1. R1 flaky 竞态修复（~15 业务行 + ~15 测试行）

**机制回顾**（brainstorm R1 段）：`test_real_llama_server_end_to_end` 与 `test_real_llama_server_grammar_constrains_output` 默认并行执行；前者的清理断言用**全局** `tasklist /FI "IMAGENAME eq llama-server.exe"` 检查——grammar 测试自己的 server 仍存活时误报「provider drop 后 llama-server 应已退出」。功能断言本身全过。

**改动点**：

- `src/agent/llama_server_handle.rs`：`LlamaServerHandle` 加 `pub fn pid(&self) -> Option<u32>`（透传 `self.child.id()`）——不改 spawn 生命周期管理（KillOnDrop / Job 对象属大改，风险 7 边界不动）
- `src/agent/llama_cpp_provider.rs`：`LlamaCppProvider` 加 `pub async fn server_pid(&self) -> Option<u32>`（锁 `ProviderInner.server` 取 handle PID；未 spawn 返 None）
- `tests/test_llama_cpp_provider.rs:521-530`：清理断言改为——drop 前 `provider.server_pid().await` 抓自身子进程 PID → drop + 1.5s 等待后 `tasklist /FI "PID eq {pid}"` 查该 PID 的 llama-server 进程不存在（PID 复用窗口在 1.5s 内且镜像名同为 llama-server 的概率可忽略；Windows 上 PID 空间大）

**验收**：`cargo test --release --test test_llama_cpp_provider -q` 连跑 ≥ 3 轮全绿（真实 server 在场时两测试真并行，旧断言会被随机打红的场景被根治）。

### 4. proptest dev-dep + `tests/test_filter_proptest.rs`（~230 测试行）

- `Cargo.toml` `[dev-dependencies]` 加 `proptest = "1.5"`（ADR-0036 D3 预登记；**runtime deps +0 纪律延续**）
- 两条属性（cases 256 = proptest 默认值，显式 `ProptestConfig::with_cases(256)` 注明 ADR 定值；parser 纯函数无 IO，16GB 机器秒级——风险 4 预期，超时降 cases 不加 feature gate）：

**属性 1：roundtrip 语义等价**——策略生成随机 AST（Process `FieldCmp`/`Regex` + Network `FieldCmp`/`Regex`/`In` 叶子 + `And`/`Or`/`Not` 复合，`prop_recursive` 限深）→ 测试侧 renderer 渲染回 filter 语法 → `parse()` → 原表达式与重解析表达式在**样本求值电池**（~8 个合成 `ProcessInfo` × `apply` + ~6 个合成 `ProcessFlow` × `apply_network`）上结果逐一相同。`FilterExpr` 无 `PartialEq`（含 `Regex`），语义等价用行为等价判定（比结构等价更强且可实现）。
- 数值字面量生成限简单十进制（裸数字 / `N%`），文本一律双引号包裹（生成字母表排除 `"` `\`）——保证渲染串必可重解析；regex pattern 字母表限 `[A-Za-z0-9._-]`（无 `/`、无元字符——渲染零转义需求），`case_insensitive` 经 `/i` 后缀往返（renderer 从 `re.as_str()` 剥 `(?i)` 前缀还原裸 pattern）
- `NetworkIn` 的 `HashSet` 渲染序经排序确定化

**属性 2：乱输入不 panic**——`proptest` `".*"` 生成任意字符串 → `parse()` / `parse_frame()` 返 Ok/Err 均可但绝不 panic；parse 成功的表达式再对样本电池 `apply` / `apply_network` 也不 panic（容错契约：类型不匹配返 false 不炸）。

## required checks 设置说明（任务 3 doc 手动项）

GitHub 仓库（`Alfroul/proc`）→ **Settings → Branches → Add branch protection rule**（branch name pattern: `master`）：

1. 勾选 **Require a pull request before merging**（可选，团队协作时；个人仓库可直接 push master 则只做第 2 步）
2. 勾选 **Require status checks to pass before merging** → 搜索并添加 ci.yml 的 4 个 job：
   - `check`（windows-latest：fmt + clippy + build ×2 + test 全量）
   - `check-macos`（macOS：fmt + clippy + check no-default-features）
   - `msrv`（ubuntu + Rust 1.85：check no-default-features——dev-deps 含 proptest 后此 job 是 MSRV 兼容的机器验证）
   - `audit`（cargo-audit 漏洞扫描）
   - （可选）`miri`（`.github/workflows/miri.yml`，job 名 `miri`——unsafe 代码 UB 检测，如加入 required 则合并不再被 miri 红挡住）
3. 保存后 required checks 生效——这是 ADR-0036 D2 的主防线；pre-push hook 是本地 opt-in 加速反馈层

**注意**：required checks 是仓库手动设置项（需要仓库 admin 权限 + 至少一次 push 后 job 名才出现在搜索框），Claude 无法代办——本文件留档步骤，用户按需设置。
