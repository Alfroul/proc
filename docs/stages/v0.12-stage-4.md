**目标**：修两个 v0.11 stage 3 / stage 4 落地后的 silent bug——(1) TD-30 `mem > 5%` 语义错误（当前按字节比较，几乎全部命中）；(2) TD-28 regex `\/` escape 不支持（CIDR / URL pattern 写不出来）。

**前置依赖**：阶段 3 已完成（signature 9 状态机）。

**任务清单**：

1. **TD-30：`mem > 5%` 语义修复**（`src/filter/{mod.rs, parser.rs}` + `src/collect.rs`）
   - 现状：`mem > 5%` 解析为 `Value::Percent(5)`，apply 时 `op.apply_num(p.memory as f64, 5.0)` —— 字节比较，几乎所有进程命中
   - 修复方案 A（推荐）：EvalCtx 加 `total_memory: u64` 字段，apply_num 在 `FieldValue::Num(mem) vs Value::Percent(p)` 时换算 `mem / total_memory * 100.0` 与 p 比较
   - 修复方案 B（更严格）：parser 阶段拒绝 `mem%` / `disk_read%` 等字节字段配 `%` 单位（破坏向后兼容，不推荐）
   - 选方案 A：surgical，不破坏现有表达式语义
   - EvalCtx 构造点（src/app.rs / src/view_models/process_panel.rs）传入 `sysinfo::System::new_all().total_memory()`
   - cpu 字段本身就是 %，与 mem% 不同：`cpu > 5%` 与 `cpu > 5` 等价（不变）；只修字节字段（mem / disk_read / disk_write / net_sent / net_recv）配 % 时的语义

2. **TD-28：regex `\/` escape 支持**（`src/filter/parser.rs`）
   - 现状：`parse_regex_lit` 用 `take_till1(|c| c == '/')`，第一个 `/` 就停止
   - 修复：改用状态机扫描——遇 `\` 转义下一个字符（包括 `/`），遇非转义 `/` 停止
   - 例子：`remote_addr =~ /192\.168\.1\.0\/24/` → pattern `192\.168\.1\.0/24`
   - 兼容性：旧表达式（无 `\/`）行为不变

3. **测试**（扩 `tests/test_filter_expr.rs` + `tests/test_filter_expr_v2.rs`）
   - TD-30 测试：
     - `mem > 50%` 在 16GB 系统上等价于 `mem > 8GB`（mock total_memory）
     - `mem > 5%` 不再命中 1KB 进程
     - `cpu > 5%` 与 `cpu > 5` 仍等价（cpu 字段本身就是 %）
     - `disk_read > 1mb` 仍按字节（不带 % 不换算）
   - TD-28 测试：
     - `remote_addr =~ /192\.168\.1\.0\/24/` 正确解析为 pattern `192\.168\.1\.0/24`
     - 旧表达式 `name =~ /chrome/` 不受影响
     - `sni =~ /example\.com\/path/` 正确解析
