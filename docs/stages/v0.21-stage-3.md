## 目标

v0.21 cycle 的**UI 消费层实装**（brainstorm 项 4，消费 stage 2 的 `SessionHandle` 三方法）：

## 已知风险（stage 3 实施时关注）

### 风险 1：switch_mode 内 build_session 阻塞（模型扫描）

`resolve_model_path` 扫盘（默认路径 + search_paths 递归）在进入面板时同步执行——本机实测 <1s 一次性成本可接受；CI/无 llama-server 环境构造失败降级 Error entry 不阻塞进入。**不缓存扫描结果**（agent.toml 可能被用户改，surgical 不预实现）。

### 风险 2：llama-server 孤儿进程（退出 proc 时 mid-run）

session 线程 mid-run 时进程退出，线程被杀不执行 `LlamaServerHandle::Drop` → llama-server 残留。mitigate：`teardown_agent_session` 有界等待（≤3s）线程退出再 Drop App；cancel 检查点密集（每 delta），正常远快于上限。**手动验收必须验证任务管理器无残留**（验收标准 6）。

### 风险 3：stage 1 既有测试兼容

stage 1 测试直接 `app.mode = AppMode::Agent`（不经 switch_mode，无 session）+ Esc/Ctrl+D——新路径 ExitPanel → switch_mode → teardown(None) 必须幂等 None 安全；`test_palette_agent_entry_switches_mode` 现在会真建 session（本机 llama-cpp 配置生效，spawn 线程但不 spawn llama-server）——App drop 后线程随 Sender 断开退出，无泄漏。

### 风险 4：TestBackend 渲染断言脆弱

断言用 buffer 关键子串（不用坐标/整行匹配）；中文 wrap 宽度按 char 计数（CJK 双宽显示 vs char 计数有偏差——断言选短 ASCII/固定前缀子串规避）。
