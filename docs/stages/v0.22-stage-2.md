## 任务清单

### 1. `src/agent/eval/runner.rs` — 执行循环 + 结果组装（~250 行业务）

**结果 JSON 顶层类型**（serde schema 本 stage 锁定，roundtrip 测试锚）：

```rust
/// 结果 JSON 顶层：meta + per-query 结果 + 聚合报告。
pub struct EvalRunFile {
    pub meta: EvalRunMeta,
    pub results: Vec<QueryResult>,
    pub report: EvalReport,
}

/// run 元信息（brainstorm 项 2「JSON 输出」行：时间戳 / provider / model /
/// attempts / max_steps / git describe）。
pub struct EvalRunMeta {
    pub timestamp: String,       // ISO UTC（不引 chrono——record.rs 同款 epoch→civil 算法）
    pub provider: String,        // ProviderSpec.name
    pub provider_detail: String, // ProviderSpec.detail（含 model 路径/名）
    pub attempts: u8,
    pub max_steps: u32,
    pub git_describe: String,    // `git describe --tags --always --dirty`，失败 fallback CARGO_PKG_VERSION
    pub quick: bool,
    pub query_count: usize,
}
```

**query 选择（纯函数，可测）**：

- `parse_levels(&str) -> Result<Vec<u8>, String>`——`"0,2"` → `[0,2]`；非法值（非 0/1/2、非数字）报错并列合法值
- `select_queries(queries, levels: &[u8], scenarios: &[String], quick: bool) -> Result<Vec<QuerySpec>, String>`——level / scenario 过滤 + QUICK 每 (scenario, level) 抽第 1 条（stage_3b `selected_queries` 同款 HashSet 去重模式）；scenario 名不在 FIXTURE_SCENARIOS 报错；选完为空报错

**执行循环**：

```rust
/// 逐 query 执行（complete 路径）+ attempts 重试 + 失败分类。
/// progress 回调每个 query 完成时触发（CLI 用于 eprintln 进度 + JSON 实时落盘）。
pub async fn run_eval(
    runner: &AgentRunner,
    queries: &[QuerySpec],
    attempts: u8,
    progress: &mut (dyn FnMut(&QueryResult, usize, usize) + Send + Sync),
) -> Vec<QueryResult>
```

- 单 query `run_one`：attempts 循环内 `runner.run(&q.text)`——`Ok(outcome)` 组装 `OutcomeSummary { final_text, actual_tools(steps tool_name 序列), stop_cause: stop.label(), llm_error: false, nudge_fallback: stop == EmptyAfterRetry }` → `classify_failure` → Pass 即 break；`Err(e)` 记 LlmError 半结果（`final_text_head = "LLM error: {e}"` 截断）继续下一 attempt。**记录最后状态**（末次 attempt 的结果即最终记录，attempts_used = 实际尝试次数）
- 单 query LlmError 用尽 attempts **不中断后续 query**（brainstorm 风险 1 mitigate 2）
- per-query 计时跨 attempts 累计（`Instant::now()` 包整个 run_one）
- `QueryResult.final_text_head` 截断 ~200 chars（char 级，防 JSON 膨胀）
- `passed = failure_mode == Pass`；`chain_steps_hit = tools_subsequence_hit(actual, expected).1`

**聚合（纯函数）**：`build_report(results) -> EvalReport`——per_level（L0/L1 passed/total；L2 加 full_chain + chain_steps_hit/chain_steps_total）/ failure_histogram（仅失败模式，按次数降序）/ total_duration_ms。**compare 消费同款口径，单一实现**（brainstorm 风险 5 mitigate 2）。

**时间戳 / git describe helper**：`utc_timestamp_iso()`（`YYYY-MM-DDTHH:MM:SSZ`）+ `utc_timestamp_compact()`（`yyyyMMdd-HHmmss`，输出文件名用）——epoch 秒 → civil 算法复制自 `src/cli/record.rs::epoch_days_to_ymd` 思路（该函数私有，eval 内自持一份 ~15 行）；`git_describe()` 子进程调用失败 fallback `concat!("v", env!("CARGO_PKG_VERSION"))`。

### 2. `src/agent/eval/report.rs` — markdown 报告 + compare（~200 行业务）

**按 ADR-0032 附录样式草案实施，不重新设计**（brainstorm 风险 4 mitigate 1）。一处小偏差：run 时间戳用 UTC（`Z` 后缀）非本地时区——不引 chrono，record.rs 同款决策。

- `render_markdown(run: &EvalRunFile) -> String`——单 run 报告：
  - 头部 meta 列表（run / provider / 参数 attempts+max_steps+git describe / 总时长）
  - `## 通过率（per level）`表：L0/L1 passed/total + 10 格 █ 条形 + 百分比；L2 full-chain 行 + L2 chain-step 行（`链步命中 n / 总链步 m`）

  - `## 失败 query 明细`表：`# / Level / Scenario / Query（~50 chars 截断）/ 失败模式 / 链命中 / stop / final_text（截断 ~200，QueryResult.final_text_head）`——仅失败行
- `render_compare_markdown(runs: &[EvalRunFile]) -> String`——对比报告：
  - run × 指标并列表（run 标签取 meta.provider + 文件无路径信息则序号；L0 / L1 / L2 full-chain / L2 chain-step / OutputDegraded 次数列）
  - `## 失败模式迁移`：首 run → 末 run 的逐模式 a/b/Δ 表（≥3 run 时同款取首末，附 run 标签）

## 已知风险（stage 2 实施时关注）

### 风险 1：报告格式打磨吸收超预期时间（brainstorm 风险 4）

**mitigate**：ADR-0032 附录样式草案是唯一锚——本 stage doc 任务 2 已把条形刻度（通过率 10 格 / 直方图 20 格 = 5%/格）等细节定死；实施时任何「想再改一版样式」的冲动直接拒绝（要改先改 ADR 附录）。

### 风险 2：JSON 实时落盘的写放大

每 query 全量重写 JSON：70 query × 末态 ~几百 KB = 总写量 ~20MB 级，机械盘也可忽略。**不优化**（简单正确优先；真成问题 v0.23+ 换 append-only 设计）。

### 风险 3：MockProvider seed 回放的多轮语义（实施时已实测确认）

complete() 按 query hash 每轮返回同一 assembled 响应；录制 fixture 的 `response_deltas` 只覆盖首轮流（实测 = Text + 单 ToolCall + EndTurn）——runner required+proc_finish 循环下回放重复执行同一 tool 至 max_steps → 分类 MaxSteps。**MockProvider 在 eval 中的用途 = 管线确定性验证（CI 结构断言）**，通过率数据必须来自真实 provider。

### 风险 4：`--output` 路径与 md 派生

`--output` 用户给 `.json` 路径 → md 同 stem 换 `.md`；给无扩展名路径 → md 加 `.md` 后缀。Windows 路径分隔符不敏感处理（`Path::set_extension` 直接用）。

### 风险 5：clippy 对长参数 / too_many_arguments

run_eval 保持 4 参（runner / queries / attempts / progress）不触发；Eval CLI 分支解构 9 字段是 clap 变体惯用（既有 ask 分支同款无 lint）。

### 风险 6：E2B 冒烟的 llama-server 依赖

冒烟需要本机 llama-server + gemma-4-E2B 模型（agent.toml 配置）。会话内小范围跑（3 query attempts=1）验证链路；如环境不可用（server 未装）则降级为 MockProvider 管线验证 + 用户后续自跑，并在完成报告中明确标注。
