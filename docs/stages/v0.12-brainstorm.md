## 候选方向（5 个 theme）

### Theme A：UX polish + signature completeness（推荐）

**Scope**：8-10 个 small TD 一波清，1 个 medium feature（trusted_signers.toml）

**内容**：
- TD-23 DNS ETW diag JSON 字段
- TD-26 HRESULT 映射扩
- TD-27 TRUSTED_SIGNERS 扩 + trusted_signers.toml（核心，解决最大误报源）
- TD-28 regex `\/` escape
- TD-30 `mem > 5%` 语义修复（核心，当前是 silent bug）
- TD-32 R17 ScriptInterpreter 系统白名单
- TD-33 R18 + path_check Downloads 去重
- TD-35 property_at_index lifetime
- TD-36 MCP DNS tool state 化

**工作量预估**：~600 行 + 测试
**周期预估**：3-4 stage，1-2 周完成
**收益**：v0.11 cycle 落地后的所有 user-visible 误报一次性收敛
**风险**：低（每项独立，互不依赖）

### Theme B：FilterExpr v3（功能扩展）

**Scope**：FilterExpr 大版本演进

**内容**：
- TD-28 regex `\/` escape
- TD-29 NetworkIn HashSet
- TD-30 `%` 单位语义修复
- TD-31 跨 ctx 表达式（`cpu > 5 AND sni =~ /evil/`）— 大改动

**工作量预估**：~400 行 + 测试
**周期预估**：3 stage，1 周
**收益**：Flow view 表达力大提升（跨 ctx 是用户最常问的功能）
**风险**：TD-31 破坏 ADR-0011 v0.11 阶段 3「类型系统保证字段不跨 ctx 误用」原则，需重新设计 ctx 抽象

### Theme C：Linux eBPF 真机验证（环境依赖）

**Scope**：TD-17 + TD-19 Linux 真机环境验证 + per-process bytes 实装

**内容**：
- TD-19 WSL2 / Linux 真机跑 `cargo +nightly build -p proc-ebpf --target bpfel-unknown-none`
- TD-17 uprobe on SSL_write 抓 SNI + tcp_sendmsg/recvmsg 累计 bytes
- ProcessFlow.bytes_out / bytes_in 实装

**工作量预估**：~800 行 + Linux 环境
**周期预估**：5-7 stage，2-3 周（含环境搭建）
**收益**：Linux 用户首次能用全功能 flow graph
**风险**：用户主用 Windows，Linux 环境成本高（之前两次主动推迟）

### Theme D：新功能（用户面向）

候选新方向（按价值排序）：
- **per-process 网络流量 bytes_out/bytes_in**（Windows 走 IP Helper EStats，已部分有；Linux 走 nethogs）
- **进程关系图可视化**（parent_chain 字段已有，TUI 内画 ASCII 树 / GraphViz 导出）
- **跨会话进程追踪**（重启后存活分析，需要持久化存储）
- **Windows Service 模式**（proc 作为服务后台跑，web UI 远程访问）
- **导出报告 PDF / HTML**（资产清点 / 安全审计场景）

### Theme E：代码质量 / 重构

**Scope**：清 TD-22 / TD-35 lifetime + 重构 FilterExpr ctx + 拆 App.rs

**内容**：
- TD-22 + TD-35 property_at_index lifetime 修正
- App.rs 进一步拆 controller（v0.7 阶段 5 留下的）
- 评估 FilterExpr ctx 抽象是否合并 EvalCtx + NetworkEvalCtx

**工作量预估**：~300 行
**周期预估**：2 stage
**收益**：长期维护性，无 user-visible 变化
**风险**：低

## 推荐方案

**首选：Theme A（UX polish + signature completeness）**

**理由**：
1. **承接 v0.11 用户反馈**：v0.11 cycle 加了 R16/R17/R18 三档评分，必然带来误报。Theme A 把 TD-27（trusted_signers 用户配置）+ TD-26（HRESULT 完整性）+ TD-32（R17 系统脚本白名单）+ TD-33（R18 Downloads 去重）一次性收敛，让 v0.11 的安全评分真正可用。
2. **修复 silent bug**：TD-30（`mem > 5%` 语义错误）当前是用户写后几乎全部命中，必须修。
3. **工作量可控**：~600 行，3-4 stage，比 v0.11 cycle（~3000 行）轻很多，符合 v0.8 类「小修一波清」节奏。
4. **每项独立**：8-9 个 TD 互不依赖，单个 stage 失败不影响其他，回退成本低。

**备选：Theme A 缩水版（仅核心 3 项）**

如果时间紧，只做：
- TD-27 TRUSTED_SIGNERS + trusted_signers.toml
- TD-30 `mem > 5%` 语义修复
- TD-26 HRESULT 映射扩

工作量 ~250 行，2 stage，一周搞定。然后剩余 TD 留 v0.13+。

**不推荐 Theme C（Linux eBPF）**：

用户主用 Windows，之前两次主动推迟。Linux 环境搭建成本高（WSL2 + nightly + bpf-linker），且 v0.12 不依赖 ebpf 路径。继续推迟到 v0.13+ cycle 启动前再评估（与 v0.8/v0.10 同款处理）。
