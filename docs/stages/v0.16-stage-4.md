## 已知风险

### 风险 1：REVIEW-v0.16 P1 / P2 数量不确定性

stage 4 撰写时点预计 P1 集中在文档完整性（stage 1 doc 头部 ✅ 缺 / brainstorm 表 ⬜ 未改），P2 可能集中在 brainstorm FAQ + stage 2/3 doc 已知风险段（MonitorManager 持久化 v0.15 TD-51 复活 / 长录屏 search offset 分页 / cache_status 字段 / VT100 replay search 支持 等候选）。**已 mitigate**：任务 2 §1.6 段在 Review 时按实际发现填，P1 数 N（预计 1-2）/ P2 数 M（预计 0-2）。

### 风险 2：Cargo.lock 同步失败

`cargo build --release` 自动同步 `Cargo.lock`，但如 Cargo.lock 含本地依赖（无）或 platform-specific 依赖可能不一致。**已 mitigate**：stage 4 任务 5 跑 `cargo build --release --no-default-features` 验证；如失败，手动 `cargo update -p proc --precise 0.16.0` 修正。

### 风险 3：git tag v0.16.0 时机

按 v0.14.0 / v0.13.0 / v0.15.0 同款规则，**stage 4 commit 完成后等用户确认再 push tag**（不在 stage 4 自动 push）。stage 4 commit 含本地 tag 创建（`git tag -a v0.16.0 -m "..."`），但 tag 不在 commit 内（git tag 是仓库级 ref，独立于 commit）。**已 mitigate**：stage 4 完工 commit 后单独跑 `git tag -a v0.16.0`，与 v0.14.0 / v0.15.0 同款「等用户确认 push」原则。

### 风险 4：CONTEXT.md 本地状态升级可能遗漏

CONTEXT.md 术语段（line 212）+ 演进历史段（line 225）「开发中，2026-07-07 启动」需改为「已落地，2026-07-07 发布」，stage 4 收尾时容易忘（与 v0.14 stage 5 / v0.15 stage 4 收尾同款规则）。**已 mitigate**：任务 9 显式列两段状态升级 + 演进历史加 stage 4 行，stage 4 完工时按验收标准 `grep "v0.16 阶段 4" CONTEXT.md` 验证。
