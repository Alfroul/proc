### 阶段 2：Schannel session + event 196 解析 + SNI 提取

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.10-stage-2.md，完成所有任务后确认完成`

**目标**：完整实现 Schannel ETW provider，解析 event 196 提取 SNI + PID + ts，推到 FlowAggregator。

**前置依赖**：v0.10 阶段 1 已完成（schema 已知）。

**任务清单**（预测）：

1. **Schannel session worker**（`src/schannel_etw/{mod.rs,provider.rs}` 完整实现）
   - 复用 `disk_io_etw/provider.rs` 模式：
     - `StartTraceW` 开 Schannel session（固定 name + GUID）
     - `EnableTraceEx2` 启用 `Microsoft-Windows-Schannel` provider + event 196 filter
     - `OpenTraceW` 注册 callback
     - 独立线程跑 `ProcessTrace`
   - worker 复用 `SnapshotWorker<Vec<SniRecord>>` 模板，1s tick → 主线程 drain

2. **event 196 解析**（`src/schannel_etw/parser.rs`）
   - 按 v0.10 阶段 1 调研的 schema 硬编码偏移：
     - ProcessId@0 (u32)
     - ServerName@8 (UTF-16 LE, len 在 @4)
     - CertificateHash@N (32 bytes)
   - 解析返回 `SchannelEvent { pid, sni: String, ts: SystemTime }`

3. **PID 关联**（thread_map 复用）
   - event 196 自带 ProcessId（不需要 thread_map）
   - 但 ProcessId 是发起 TLS handshake 的进程的 PID（如 svchost 转发场景需查 socket→pid）

4. **降级路径**
   - Win10 < 1809：无 event 196，try_spawn 返回 None
   - 非管理员：OpenTraceW 失败，None
   - Schannel provider 被其他工具占用：None

5. **测试**（`tests/test_schannel_etw.rs`）
   - 单元：mock event 196 bytes → parser 返回正确 SNI
   - 集成（管理员 only）：启动 worker → curl https://example.com → SniRecord 出现 + sni = "example.com"
   - 非 Windows / 非管理员：SKIP

**验收标准**：
- worker 在 Windows admin 跑通
- curl 触发后 1s 内 SniRecord 出现
- TD-18 标 Fixed

**容量预估**：~600 行（worker 300 + parser 100 + 测试 200），工具调用 30-50 次。**关键风险**：event 196 schema 不同 Win10/11 版本可能不同（1809 vs 22H2），开工时需多版本验证。
