### 4. record_start/stop 语义设计稿（ADR-0033 D5 展开，stage 2 实装输入）

**语义边界定稿**（三路径 + 一拦截）：

| 维度 | 设计 |
|---|---|
| **录制范围** | agent 调 proc_record_start 经 TUI confirm（y）后开始录制**整个终端屏幕**（与手动 R 键同款 VT100 recording v2 / `.prec`），录制期间 AgentPanel 会话继续（用户可见后续对话被录进回放） |
| **句柄持有** | record handle 由 **AgentSession 层**持有（跨 tool 调用保活——query 之间不丢）；复用 MCP 层 `proc mcp` 既有 record 子进程管理（ADR-0029 record_handle pattern，不重写） |
| **停止路径 ①** | 模型调 proc_record_stop（confirm y）显式停——返回落盘路径与文件信息，模型可在 answer 里告诉用户 |
| **停止路径 ②③** | Ctrl+D teardown / 会话异常 shutdown → 自动 stop 落盘（防孤儿录制进程——复用 App::shutdown 防孤儿模式），面板 Notice 提示「录屏已自动保存至 <path>」 |
| **CLI ask 拦截** | 单轮进程退出录制即死——继续拦截，文案改「录屏 tool 仅 TUI AgentPanel 会话支持（CLI 单轮进程无法保持录制）」 |
| **eval 口径** | 不受影响（eval complete 路径无 confirm 通道，两 tool 永远 blocked——D6 论证） |

**stage 2 实装清单预览**（设计稿的下游，供 stage 2 doc 编写参考）：`src/agent/session.rs`（AgentSession 持 handle + teardown 钩子）+ `src/agent/tools/dispatch.rs`（`execute_confirmed_tool` 两分支改真实执行 + CLI 拦截文案）+ confirm_summary 已就位不动 + 测试（TUI session 端到端 / 孤儿清理 / CLI 拦截不变锚）。

## 已知风险（stage 1 实施时关注）

### 风险 1：GBNF 冒烟结果模糊（部分兼容）

**问题**：冒烟可能出「不报错但 tool_calls 解析异常率升高」的中间态——4 项判定不够二值。
**mitigate**：判定表按证据归档（不强行二值化）；中间态时补跑一轮 `--quick`（26 条 ~19m）再定；ADR 注记精确数据（PASS/FAIL 分布 + 失败模式），stage 3 矩阵是否含 GBNF 列按此数据定。

### 风险 2：冒烟期间 llama-server 版本行为差异

**问题**：冒烟结论绑定当前 llama-server b8685——未来升级 llama.cpp 行为可能变。
**mitigate**：ADR 附录 B 注记 server 版本（git describe / `--version` 输出）；结论标注版本语境。

### 风险 3：agent.toml 还原遗漏

**问题**：冒烟后忘删 grammar_file 行 → stage 2/3 的「GBNF off」列被污染（变量混淆）。
**mitigate**：验收标准 2 显式检查（diff 备份）；冒烟步骤 4 是流程强制步；stage 3 挂机清单开头再核对一次配置。

### 风险 4：prompt v2 措辞稿与 stage 2 record 落地的措辞漂移

**问题**：修订 2 已把「录屏」写进写操作枚举，但 record 实装在 stage 2——若 stage 2 语义设计变更（如 record 需要不同引导），附录 A 文本要同步。
**mitigate**：stage 2 完成后核对附录 A 与实装一致性（stage 2 doc 的完工检查项）；不一致以 stage 2 实装为准更新附录 A（doc 小修范畴）。
