### 3. `src/agent/eval/mod.rs` 类型骨架 + 加载校验（~200 行）

```rust
//! v0.22 eval harness（ADR-0032）：70 query 基准表 + 结果类型 + 失败模式分类。
//! runner 实装在 stage 2（proc agent eval）；session 观测在 stage 3。

/// 单条基准 query（queries.toml 的 [[query]] 条目）
#[derive(Debug, Clone, serde::Deserialize)]
pub struct QuerySpec {
    pub scenario: String,
    pub level: u8,
    pub text: String,
    pub expected_tools: Vec<String>,
}

/// 失败模式分类（确定性，从 RunnerOutcome 判定——ADR-0032 D3）
#[derive(Debug, Clone, Copy, PartialEq, Eq, serde Serialize/Deserialize)]
pub enum FailureMode {
    Pass,
    NoToolCall,      // 无任何 tool 调用直接文字回答
    WrongTool,       // 有 tool 但 expected 未命中（L0/L1）
    ChainIncomplete, // L2 链部分命中（full-chain 失败但 chain-step > 0）
    EmptyAnswer,     // final_text 空 / nudge 兜底文案
    MaxSteps,        // stop = MaxSteps 且未通过
    LlmError,        // LLM 调用失败（attempts 用尽）
    OutputDegraded,  // 文本退化：特殊 token 字面量泄漏 / 高重复（2026-08-20 实测，优先归类——brainstorm 风险 6）
}

/// per-query 结果（结果 JSON 的原子单元）
#[derive(Debug, Clone, serde::Serialize/Deserialize)]
pub struct QueryResult {
    pub scenario: String,
    pub level: u8,
    pub query: String,
    pub expected_tools: Vec<String>,
    pub passed: bool,
    pub failure_mode: FailureMode,
    pub chain_steps_hit: usize,   // L2 口径：expected 中命中的 tool 数
    pub actual_tools: Vec<String>,// steps trace 的 tool 名序列
    pub stop_cause: String,
    pub final_text_head: String,  // 截断 ~200 chars（防 JSON 膨胀）
    pub duration_ms: u64,
    pub attempts_used: u8,
}

/// 聚合报告（结果 JSON 的 summary 段）
#[derive(Debug, Clone, serde::Serialize/Deserialize)]
pub struct EvalReport {
    pub per_level: Vec<LevelSummary>,      // L0/L1: pass/total；L2: full_chain + chain_step 双口径
    pub failure_histogram: Vec<(String, usize)>,
    pub total_duration_ms: u64,
}

/// queries.toml 加载（include_str! 编译进 binary）+ 全量校验
pub fn load_eval_queries() -> Result<Vec<QuerySpec>, String>;
```

**校验规则**（加载时断言，违反返 Err）：
- 总数 = 70；level 分布 L0=23 / L1=27 / L2=20
- query 文本无重复；scenario 名 ∈ fixtures 9 场景集合
- L2 条目 `expected_tools.len() >= 2`；全部条目 `!expected_tools.is_empty()`
- expected_tools 中的 tool 名 ∈ agent catalog 47 tool 名单（防拼写错）——对照 `src/agent/tools/catalog.rs` 注册名单

**`src/agent/mod.rs` 接线**：加 `pub mod eval;` + re-export `pub use eval::{QuerySpec, FailureMode, QueryResult, EvalReport, load_eval_queries};`。

**注意**：FailureMode / QueryResult / EvalReport 的字段形状本 stage 锁定（serde schema 即结果 JSON contract）；判定逻辑（`classify_failure` 等纯函数）**本 stage 直接实装**——纯函数无副作用，属 v0.20 stage 1「trivial 纯函数直接实装」原则；执行循环 / IO / 报告生成留 stage 2。**三个纯函数落地 + 单测**：
- `classify_failure(outcome 摘要, expected) -> FailureMode`——判定顺序：**OutputDegraded 优先**（final_text 退化即整体 fail，即使 tool 命中），然后 NoToolCall / WrongTool / ChainIncomplete / EmptyAnswer / MaxSteps / LlmError
- `tools_subsequence_hit(actual, expected) -> (bool, usize)`——保序子序列双指针（允许中间插其他 tool），返回（全中？, 命中数）
- `is_degraded_output(text) -> bool`——退化检测（brainstorm 风险 6）：特殊 token 字面量名单 `DEGRADED_TOKEN_MARKERS = ["<eos>", "<end_of_turn>", "<tool_call", "<turn|>"]` 任一子串命中，或同一片段连续重复 ≥ `DEGRADED_REPEAT_LIMIT`（常量，建议 8——`<eos><eos>...` 数百次级实测远超此线；正常中文长文本不误伤，单测锁定）

## 已知风险（stage 1 实施时关注）

### 风险 1：L2 expected 链标注主观性（brainstorm 风险 3 的 stage 1 面）

链定得过严 full-chain 会虚低。**mitigate**：保序子序列口径（允许中间插 tool）+ 逐条对照 seed fixture 的 tool call 序列反推（不自创）+ queries.toml 人类可读——**stage 1 交付时请用户过目 L2 20 条链**（验收标准 7），异议当场调（数据文件改动，无逻辑耦合）。

### 风险 2：L0/L1 迁移的逐字一致性

50 条从测试常量手迁 TOML，错一字锚测试红——**锚测试本身就是 mitigate**（`test_query_table_matches_eval_toml`）。迁移时用脚本化对比（读 QUERY_TABLE 段 + 读 TOML + diff）而非纯手抄更稳（实施会话自行选择，验收以锚测试为准）。

### 风险 3：AgentSub 加变体的 match 穷尽连锁

`Eval` / `SessionInfo` 变体加入后 agent_cmd dispatch 的 match 报 non-exhaustive——逐处补分支（友好拦截）。**别用 `_ =>` 通配兜底**（未来第 5 个变体静默漏分支）；如既有代码已用通配符则保持既有风格（surgical 原则）。

### 风险 4：toml crate 对集成测试的可见性

锚测试需在 `tests/` 里解析 TOML——toml 在 `[dependencies]`（AgentConfig 使用中），Cargo 语义下集成测试可用 dependencies + dev-dependencies。如实施时遇到可见性问题，fallback = 经 `proc::agent::eval::load_eval_queries()` 公开 API 取数比对（逻辑等价，小修范畴）。

### 风险 5：serde schema 字段名漂移

QueryResult / EvalReport 是结果 JSON contract，字段名一旦被 stage 2 报告生成 / stage 3 compare 消费就成事实 API——本 stage 用 `#[serde(deny_unknown_fields)]`？**不用**（过度约束，前向兼容差）；用 roundtrip 测试锁字段名（任务 6 的两个 roundtrip 测试即此目的）。
