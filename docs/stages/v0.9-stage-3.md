### 阶段 3：切片 B — JA4 指纹算法（RFC 9503）

> **独立会话指令**：`阅读 CONTEXT.md 和 docs/stages/v0.9-stage-3.md，完成所有任务后确认完成`

**目标**：从 ClientHello 抓 cipher suites + extensions + ALPN，按 [RFC 9503 JA4 algorithm](https://www.ietf.org/archive/id/draft-ietf-tls-wg-tls-essentials-01.html) 计算 hash，给每个 flow 打指纹标签。

**前置依赖**：v0.9 阶段 2 已完成（ClientHello 已能解析）。

**任务清单**（预测）：

1. **JA4 算法实现**（`src/ebpf/ja4.rs` 新文件）
   - 输入：解析后的 ClientHello struct（cipher suites / extensions / ALPN）
   - 输出：36 字符 hash（12 字段 prefix + 32 字节 SHA-256 truncate）

   JA4 字段构成（12 字符 prefix）：
   ```
   q (quic=“q” / tcp=“t”)
   d (DTLS=“d” / TLS=“t”)
   SNI (d=有 / i=无)
   N (number of ALPN)
   first 4 chars of first ALPN (or “00”)
   ||
   cipher suites count
   cipher version (97=TLS1.3, 98=TLS1.2)
   ||
   extension count
   ||
   signature algorithm count
   ```
   
   - 然后 cipher suites 排序去重 → SHA-256 → 取前 24 hex
   - 然后 extension 排序（去掉 SNI 和 ALPN）→ SHA-256 → 取前 24 hex

2. **集成到 sni_parser**
   - `sni_parser::parse_client_hello(bytes) -> ParsedClientHello`
   - `ParsedClientHello { sni: Option<String>, ja4: String, cipher_suites: Vec<u16>, extensions: Vec<u16>, alpn: Vec<String> }`

3. **SniEvent 扩展**
   ```rust
   pub struct SniEvent {
       // ... 原字段
       pub ja4: [u8; 36],  // JA4 hash hex
   }
   ```

4. **测试**（`tests/test_ja4.rs` 新文件）
   - 用预录的 ClientHello bytes 测试 JA4 输出（Firefox / Chrome / curl / OpenSSL s_client 各一个，验证不同指纹）
   - 已知指纹（来自 RFC 9503 附录）：
     - curl 7.81 = `t13d1516h2_8daaf6152771_b0da82dd1658`
     - Firefox 96 = `t13d1716h2_5b57614c22b0_0771c93bca59`
     - Chrome 97 = `t13d1715h2_5b57614c22b0_185d0b9277c2`
   - 解析后 hash 应匹配

5. **集成测试**
   - 启动 proc → 触发 `curl https://example.com` → proc flows 显示该 flow 的 ja4 hash
   - 验证 hash 是 `t13d1516h2_8daaf6152771_b0da82dd1658`（curl 真实指纹）

**验收标准**：
- JA4 算法实现完整（12 字段 prefix + 32 hex hash）
- 4 个已知 ClientHello bytes 测试通过
- 端到端 curl 触发 flow 显示正确 JA4

**容量预估**：~600 行（算法 300 + 测试 300），工具调用 40-60 次。**关键风险**：JA4 算法细节多（排序去重规则 / signature algorithm 区分），实现易出错，需对 RFC 仔细。
