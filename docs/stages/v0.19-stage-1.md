### 1. 基础设施 3 项

#### 1.1 ADR-0027 §6 SSE transport lifecycle 扩段（~100 行 doc）

**落地范围**（4 子段，含 stage 1 Spike 3 项调研结论）：

- **§6.1 runtime 分支选择**（项 1 落地）：stdio `current_thread`（v0.7~v0.18 既有路径零回归）/ SSE `multi_thread worker_threads(4)`。**调研结论**（context7 tokio docs 验证 2026-07-13）：`Handle::runtime_flavor() -> RuntimeFlavor`（CurrentThread / MultiThread 两个变体）完美适配 stage 2 测试 `test_stdio_transport_uses_current_thread_runtime` / `test_sse_transport_uses_multi_thread_runtime`。DockerMonitor runtime 独立（不抢 MCP runtime 线程），真实风险是 multi_thread worker thread 被 docker 同步 `block_on` 阻塞，mitigate worker_threads(4) ≥ 一般 client 数
- **§6.2 axum 路由 + StreamableHttpService**（项 3 落地）：**调研关键发现**——Cargo feature flag 实测修正（cargo build error 实测 + context7 rmcp 0.11 docs 验证）：brainstorm §决策 4 假设的 `transport-streamable-http-server` 单数正确，需补 `-session` 后缀启用 session submodule（含 `StreamableHttpService` struct），**不存在 `-tower` 后缀变体**（context7 docs 描述的「tower submodule」是 module 可见性需 `-session` + `-streamable-http-server` + `server` 三 feature 组合）。**按 brainstorm 步 15 小修规则（< 5 处）stage 1 内直接修正**。`StreamableHttpService::new` API 签名验证（service_factory closure + session_manager Arc<M> + StreamableHttpServerConfig builder）。axum 0.7.9 + tower 0.5.3 + tower-http 0.6.11 与 rmcp 内部对齐无 duplicate（cargo tree -d 实测）
- **§6.3 multi-client 注册表**（项 2 落地）：`HashMap<String, Peer<RoleServer>>` 升级 `HashMap<String, Vec<Peer<RoleServer>>>`。**调研结论**：rmcp 0.11 `Peer<RoleServer>` 文档未明确 Eq/Hash impl，stage 2 用 `Arc::ptr_eq` 做 vec 去重（Peer 内部 Arc 包装 cheap clone 后 pointer 一致），fallback 到 `Peer::id()` 或 `mcp-session-id` HTTP header。push task 改造（项 4 落地）：1s tick 遍历 `Vec<Peer>` 用 `tokio::task::JoinSet` 并发调 `peer.notify_resource_updated`

### 4. stage 1 Spike 3 项调研子任务

#### 4.1 rmcp 0.11 Peer identity API 调研（风险 5 mitigate）

**调研方法**：context7 query rmcp 0.11 docs `Peer<RoleServer>` struct impl Eq/Hash/PartialEq/Clone。

**调研结论**：
- `RoleServer` 实现 PartialEq + Eq（但 RoleServer 是 PhantomData marker，比较无意义）
- `Peer<RoleServer>` 实现了 `FromContextPart` trait，从 `RequestContext` 创建
- `LocalSessionHandle::id()` 返 `&SessionId`（SSE 路径专用，stdio 无 session）
- HTTP header `mcp-session-id`（SSE 路径，stdio 无）
- **文档未明确显示 `Peer<RoleServer>` derive Eq/Hash**

**stage 2 实装策略**（写入 ADR-0027 §6.3）：
1. stdio 路径（current_thread）：vec 长度 ≤ 1，identity 检测降级为「vec 是否空」
2. SSE 路径（multi_thread）：用 `Arc::ptr_eq(p1, p2)` 做 vec 去重（Peer 内部 Arc 包装，cheap clone 后 pointer 一致）
3. fallback：`Peer::id()` / `mcp-session-id` HTTP header（stage 2 调研具体 API）

#### 4.2 axum 版本对齐 + cargo tree -d 调研（风险 2 mitigate）

**调研方法**：cargo build error 实测 + cargo tree -d 实测 + context7 rmcp 0.11 docs 验证。

**调研关键发现**（与 brainstorm §决策 4 假设差异，按 brainstorm 步 15 小修规则 stage 1 内修正）：

| brainstorm §决策 4 假设 | rmcp 0.11 实际 features 清单（cargo error 输出） | 验证结论 |
|---|---|---|
| `transport-streamable-http-server`（单数） | `transport-streamable-http-server` ✅ + `transport-streamable-http-server-session` ✅ + `transport-streamable-http-client` + `transport-streamable-http-client-reqwest` + `tower`（独立 feature） | brainstorm 假设正确，需补 `-session` 后缀启用 session submodule（含 `StreamableHttpService` struct）。**不存在 `-tower` 后缀变体** |

**最终 Cargo.toml 配置**（cargo build --release 实测通过，2026-07-13）：
```toml
rmcp = { version = "0.11", features = ["server", "transport-io", "transport-streamable-http-server", "transport-streamable-http-server-session"] }
```

**cargo tree -d 实测**（2026-07-13）：axum 0.7.9 / tower 0.5.3 / tower-http 0.6.11 各一份，无 duplicate deps。

#### 4.3 tokio runtime 类型检测 API 调研（风险 3 mitigate）

**调研方法**：mcp__exa-search__web_search_exa 查 tokio runtime detect current_thread vs multi_thread。

**调研结论**：`tokio::runtime::Handle::runtime_flavor() -> RuntimeFlavor`：
- `RuntimeFlavor::CurrentThread`：current_thread runtime 标识
- `RuntimeFlavor::MultiThread`：multi_thread runtime 标识
- `RuntimeFlavor` derive `#[derive(Debug, PartialEq, Eq)] #[non_exhaustive]`（可直接 == 比较；match 要 `_` arm）

**stage 2 测试设计**（写入 ADR-0027 §6.1）：
```rust
let runtime = build_runtime(&TransportKind::Stdio).unwrap();
assert_eq!(runtime.handle().runtime_flavor(), RuntimeFlavor::CurrentThread);
```

stage 1 Spike 已落地 3 个 build_runtime stub 测试用此 API。

## stage 1 Spike 关键设计决策

### 决策 1：Cargo feature flag 修正（按 brainstorm 步 15 小修规则）

**brainstorm §决策 4 假设** vs **rmcp 0.11 实际 features**（cargo build error 实测）：

| brainstorm §决策 4 假设 | rmcp 0.11 实际 |
|---|---|
| `transport-streamable-http-server`（单数） | `transport-streamable-http-server` + `transport-streamable-http-server-session`（后者启用 session submodule 含 StreamableHttpService struct） |

**不存在 `-tower` 后缀变体**——context7 docs 描述的「tower submodule」是 module 可见性，需三 feature 组合启用。

**修正范围**（< 5 处属小修，按 brainstorm 步 15 stage 1 内直接修正）：
- Cargo.toml（rmcp features 加 `-session`）—— 1 处
- ADR-0027 §6.2（描述 Cargo feature flag 验证）—— 1 处
- brainstorm §决策 4 描述（stage 1 内不修正 brainstorm 文档，仅在 stage doc + ADR 注明实测结论）—— 0 处

**不触发回溯修复**（< 5 处阈值），stage 1 完成报告中说明。

### 决策 2：stage 1 Spike 简化策略（注册表 Vec<Peer> 业务最小适配）

stage 1 Spike 不动业务代码逻辑（仅类型升级 + 业务最小适配让编译通过）：
- subscribe：vec push 无 identity 检测（同 client 多次 subscribe 同 URI 会 push 重复 vec 项）
- unsubscribe：清空整个 vec（不精确，stage 1 Spike 简化）
- spawn_push_task：双层 for 循环（顺序遍历，不并发）+ fail peer 清空整个 vec（不精确）

**stage 2 改造**（v0.19 cycle）：
- subscribe：`Arc::ptr_eq` identity 检测 vec 去重
- unsubscribe：`vec.retain(|p| !Arc::ptr_eq(p, &target))` 精确移除
- spawn_push_task：`JoinSet::spawn` 并发调 `peer.notify_resource_updated` + `join_next().await` 逐个判断 fail peer + 一次性从 vec `Arc::ptr_eq` retain 精确清理

stdio 单 client 场景下 vec 长度 ≤ 1，stage 1 Spike 简化策略等价精确清理。SSE multi-client 场景下 stage 2 改造。

### 决策 3：CLI flag dispatch 适配不动业务路径

`McpSub::Serve` 改 struct variant 加 3 字段后，dispatch 路径适配：
- `src/cli/mod.rs`：`None => McpSub::Serve { transport: "stdio".to_string(), bind_addr: "127.0.0.1".to_string(), port: 8080 }`
- `src/cli/mcp_cmd.rs`：`McpSub::Serve { transport: _, bind_addr: _, port: _ } =>` 仍调 `run_mcp_serve()` 无参（stage 1 Spike 不接 TransportKind 分支）

**stage 2 重构**：`run_mcp_serve(kind: TransportKind)` 接 kind 参数，dispatch 用 `TransportKind::from_cli_str(&transport)` 把 CLI String 转 TransportKind。
