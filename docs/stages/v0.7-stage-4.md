**目标**：把进程列表的搜索从纯子串匹配（`name.to_lowercase().contains(&query_lower)`）升级为过滤表达式（`cpu > 5 AND name =~ /chrome/`），同时保留原 substring fallback。

**前置依赖**：阶段 3 已完成（搜索框已经成为 AppLayer::Search 一层，本阶段在此基础上扩展）。

**依赖测试**（开工时跑详情）：

- `cargo test --release --test test_search -- --nocapture`（v0.6 搜索基线）
- `cargo test --release --test test_command_palette -- --nocapture`（阶段 3 命令面板基线）

**技术决策（详见 ADR-0011）**：

- **parser 库**：用 `nom 7-8`（不用 pest）。理由：nom 更轻量，no_std 友好，对小型表达式 parser 更合适；pest 适合完整语法（如 SQL 子集）
- **不引入 SQL/javascript 引擎**：FilterExpr 是表达式不是脚本，没有副作用、没有变量绑定、没有循环
- **语法设计**（参考 bottom）：
  - 字段比较：`<field> <op> <value>`，op ∈ `=` `!=` `>` `<` `>=` `<=` `=~`
  - 布尔组合：`AND` / `OR` / `NOT`（大写敏感）+ 括号 `( )`
  - 字段：`cpu` `mem` `pid` `name` `user` `cmd` `disk_read` `disk_write` `net_sent` `net_recv` `security_score`
  - 值：数字（`5` / `5.5` / `5mb` / `5gb`）/ 字符串（`chrome`）/ 正则（`/chrome/i`）
  - 单位：`b` / `kb` / `mb` / `gb` / `tb`（1024 进制）/ `%`（百分比）
- **切换方式**：搜索框第一字符为 `:` 切到 FilterExpr 模式，否则走原 substring。例：`:cpu > 5 AND name =~ /chrome/` 触发 FilterExpr；`chrome` 走原 SearchState

**任务清单**：

1. **依赖添加（5 min）**

2. **FilterExpr AST（1 h）**
   - 新建 `src/filter/mod.rs`：
     ```rust
     #[derive(Debug, Clone)]
     pub enum FilterExpr {
         FieldCmp { field: Field, op: CmpOp, value: Value },
         Regex { field: Field, re: regex::Regex, case_insensitive: bool },
         And(Box<FilterExpr>, Box<FilterExpr>),
         Or(Box<FilterExpr>, Box<FilterExpr>),
         Not(Box<FilterExpr>),
     }

     #[derive(Debug, Clone, Copy)]
     pub enum Field { Cpu, Mem, Pid, Name, User, Cmd, DiskRead, DiskWrite, NetSent, NetRecv, SecurityScore }

     #[derive(Debug, Clone, Copy)]
     pub enum CmpOp { Eq, Ne, Gt, Lt, Ge, Le }

     #[derive(Debug, Clone)]
     pub enum Value {
         Number(f64),         // 已转换单位
         Percent(f64),
         Text(String),
     }

     impl FilterExpr {
         pub fn apply(&self, p: &ProcessInfo) -> bool { /* ... */ }
     }
     ```
   - `apply` 实现：match 字段 → 从 ProcessInfo 取值 → match op → 比较
   - 字段映射表用 `match field` 而非反射，编译期保证字段名正确
   - 验证：单元测试覆盖每个 Field × CmpOp 组合

3. **nom parser（2 h）**
   - 新建 `src/filter/parser.rs`：
     - `pub fn parse(input: &str) -> Result<FilterExpr, ParseError>`
     - nom 组合子：`alt` / `delimited` / `tag` / `map_res` / `named!`
     - 递归下降：expr = or_expr ; or_expr = and_expr ("OR" and_expr)* ; and_expr = not_expr ("AND" not_expr)* ; not_expr = "NOT"? primary ; primary = "(" expr ")" | leaf
     - leaf = field cmp_op value | field "=~" regex_lit
     - 错误信息友好：`ParseError { msg: String, position: usize }`（不是 nom 默认的 verbose error）
   - 验证：单元测试 20+ case（合法语法、非法语法、边界条件）

4. **ProcessInfo 字段抽取（30 min）**
   - `src/filter/mod.rs` 加 `fn extract_field(p: &ProcessInfo, f: Field) -> FieldValue`
   - `FieldValue` enum：`Num(f64)` / `Text(String)`
   - 字段映射：
     - `Cpu` → `p.cpu_usage as f64`
     - `Mem` → `p.memory_bytes as f64`（byte 单位）
     - `Pid` → `p.pid as f64`
     - `Name` → `p.name.to_string()`
     - `User` → `p.user_id.as_ref().map(...).unwrap_or_default()`
     - `Cmd` → `p.cmd.join(" ")`
     - `DiskRead` / `DiskWrite` / `NetSent` / `NetRecv` → 对应字段 as f64（byte/s）
     - `SecurityScore` → `p.security_score.unwrap_or(100) as f64`
   - 验证：单元测试覆盖每个字段

5. **SearchState 接入 FilterExpr（1 h）**

     ```rust

         Substring,  // v0.6 已有

     }

     pub struct SearchState {
     ```

   - `handle_input` 修改：
     - 第一字符是 `:` → 切到 FilterExpr 模式，去除 `:` 后的字串喂给 parser

   - 验证：原 substring 路径行为完全不变
