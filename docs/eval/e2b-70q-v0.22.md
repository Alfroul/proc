## 关键观察

### 1. OutputDegraded 是 E2B 最大瓶颈（风险 6 量化闭环）

21/70 query（**30%**）输出退化，占失败的 55%——2026-08-20 手动实测的三层退化（brainstorm 风险 6）在 70 query 规模下得到量化。典型形态（明细表 #1/#5/#8 等）：

- **proc_finish 语法泄漏成正文**：`proc_finish{answer:<|" "|>...}` 整段作为文本吐出（模型想发结构化 tool call 但走了文本通道），随后 `<tool_call|>` + `<eos>` 字面量连发
- **`<eos>` 重复循环**：#8/#10 连续数十个 `<eos>` 后接正常文字——停止 token 被当文本
- **退化文本非空且常含正确答案**：#8「Docker 未运行」的解释本身是对的，但外壳是泄漏语法 → 按 D3 口径仍记失败（正确决策）

**无 LlmError（0 次）**——llama-server 全程稳定（70 query + 重试零连接故障，惰性 spawn 一次到底）；无 MaxSteps / EmptyAnswer。E2B 的问题不在「不会调工具」（tool 通道大部分 query 正常），在「收尾时把 finish 调用写成文本」。

**现成零代码开关**（v0.22 不动，数据留给 v0.23+ 决策）：`agent.toml [llama-cpp] grammar_file = "tool_call"`（GBNF 强制 JSON tool call 输出，v0.20 决策 C 逃生舱）——预期直接消灭 proc_finish 语法泄漏型退化。更强模型（v0.23+ 下载后 `--compare`）是另一条路。

### 2. 与 v0.20 验收数字的口径差（17/23 vs 23/23 不是回归）

v0.20 stage_3b 验收：L0 23/23、L1 21/27。本轮 eval：L0 17/23、L1 14/27。差值主要来自三处，**均非 agent 能力退化**：

1. **text_ok 加了退化检测**（D3 新口径）——v0.20 判定只查 final_text 非空，proc_finish 语法泄漏文本当时会判过；本轮 21 条 output_degraded 里多数在 v0.20 口径下是 Pass
2. **环境因素：Docker daemon 未运行**——docker 场景 10 条（L0 3 / L1 3 / L2 4）全部失败，模型正确识别「Docker 未运行」并解释，但部分外壳退化、部分 expected tool（proc_docker_inspect 等）无对象可调。v0.20 验收时已知同样问题（REVIEW-v0.20 验收口径拍板段）
3. **E2B 非确定性**——同 query 两次 attempt 行为可不同（attempts=2 取末次）

排除 docker 10 条后的近似口径：L0 17/20（85%）、L1 14/24（58%）。

### 3. L2 双口径（首跑数据，v0.23+ 模型对比的基线列）

- **full-chain 1/20**：唯一全链命中 = process-diagnose「列出所有签名验证失败的进程并解释原因」（实际链 proc_ls→proc_inspect→proc_inspect，链步命中 2/2 保序子序列通过）
- **chain-step 12/43（28%）**：E2B 能走对链的前 1-2 步（如 proc_help 发现 → 首 tool 执行），第三步起发散（改用错误 tool / 转文字解释 / 反问用户）
- 典型模式：**反问缺参**（#19/#25/#26/#29——「请提供盘符/PID/路径」）是 L2 的合理行为但 eval 口径记失败（expected 链未走）——多步规划能力是 E2B 的能力边界，与 brainstorm 决策 2 预判一致

### 4. 写操作发现链量化（REVIEW-v0.21 观察 3 闭环）

eval 走 complete 路径（无 confirm 通道），写 tool 一律 blocked JSON。实测：usb L1「帮我安全释放 E 盘」——模型经 proc_help 发现链找到 proc_eject_status 并调用成功，随后正确解释「安全策略限制无法直接执行」+ 给建议。**发现链工作正常**，blocked 回复的应对（转向解释）也符合 system prompt 契约；v0.21 观察 3 的「不引导时倾向文字解释」在 L2 usb「eject_status → kill 反馈循环」query 复现（#21：模型直接声明「我不能执行系统操作」并模拟演示——写 tool 发现链未触发）。

## 结论

1. **eval harness 全链路验证通过**：70 query 实跑 + 实时落盘 + 分类 + 双口径报告 + 归档，零 LlmError 零中断（风险 1 未触发）
2. **E2B 画像清晰化**：单步 tool 调用基本可靠（L0 排除退化/环境后 ~85%），多步规划弱（full-chain 5%），收尾语法泄漏是最大可修复项（GBNF 逃生舱待 v0.23+ 数据决策）
3. **数据资产落位**：本 JSON 是未来 `--compare` 的 E2B 基线列（更强模型 / GBNF 开关 / prompt 调整，任一变量变化后一条命令出对比）
